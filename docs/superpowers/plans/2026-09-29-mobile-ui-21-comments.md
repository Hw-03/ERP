모바일 360·390·430·768×822 및 360×420에서 내역 목록/묶음, 품목 상세, 생산 상세, BOM, 공유 선택기를 캡처하고 DOM을 확인했다. 파일명은 `{화면}-{폭}x{높이}.png` 형식이다.

- 내역 행 높이 모든 규격 98px, 가로 넘침 없음. 551px에서 부모 배지와 재고 변화 및 하위 코드와 재고 변화가 같은 줄이다.
- 생산 숫자 열은 360px에서 각각86px, 390px에서96px, 430px에서약109.33px, 768px에서222px로 대표·AF·PF 동일하다. 스크롤 후에도 열 제목 고정. 모바일 기준은 1024px 미만으로 맞췄다.
- BOM 가로 넘침 없음. 360×420 헤더97px, 구성품 영역약270.6px. 실제 깊은 구성 전개 및 포커스 복귀 확인.
- 선택기 목록→버튼8px, 탭바 padding-top8px. 목록 높이822 화면에서471px, 420 화면에서85px. 작은 화면에서 낱개 선택·해제 가능. 최소320px 부모 제한과 검색 중복 패딩을 제거하고 낮은 화면 헤더 패딩을 줄였다.
- 색상 실측: 파랑 rgb(47,116,231), 청록 rgb(7,141,176), 노랑 rgb(185,134,25). 주간보고 하위 탭 stroke도 같은 노랑이다.
- PC1280에서 생산의 기존 설명·표, BOM 소요량/창고/부서/총재고 열, 선택기의 코드·재고 열을 확인했다.

## 자동 검증

- 내역/재고 관련 7파일 129개 테스트 통과.
- 생산 모바일·PC 14개, BOM 모바일 헤더 1개 통과. 재고 상세 44개는 위129개와 중복이다.
- IoTargetPicker.responsive 9개, MobileIoComposeWizard.header 11개, MobileMoreScreen 4개 통과.
- `npm run typecheck:app`, `npm run lint:strict`, `npm run build`, `git diff --check` 통과. 최종 생산 후속 수정은 해당 ESLint 및 프로덕션 빌드 TypeScript로 재확인.
- 별도 에이전트 읽기 리뷰에서 P1/P2 발견 없음. 기존 styled-jsx 테스트 경고는 남아 있으며 테스트 실패는 없다.

검증 한계: 실제 기기 가상 키보드·안전 영역은 에뮬레이션하지 않았다. 모든 업무 상태 조합을 생성하지 않았고, 브라우저 검증은 기존 데이터의 읽기 및 화면 내 선택만 사용했다. 이전 12개 주석의 전체 탭 검증은 기존 기록을 유지한다.

API·DB·계산 규칙 및 주간보고 내부 변경 없음. 커밋·푸시·배포 없음.
