# 모바일 UI 피드백 반영 — 2026-09-29

기존 v2 이후 사용자가 지정한 화면 구성 수정 기록이다. 앞선 문서의 “선택 행을 늘리지 않음”, “재고 2열”, “업무함 드롭다운” 기준은 이번 요청으로 대체한다. 기존 430px / 720px / PC 규격은 유지한다.

- 추가 주석 구현 완료 후 `typecheck:app`, `lint:strict`, `build` 통과. 1024px에서 PC 대시보드와 기존 품목코드 열 유지 확인.

### 앞선 수정 검증

- 승인함 메뉴를 열어도 기존 작성 컴포넌트를 언마운트하지 않는다. 요청 작성으로 복귀 시 동일 DOM 유지, 실제 승인함 선택 시 기존 이탈 확인·취소·폐기 전환 테스트 통과.
- 기존 모바일 테스트와 재고 행/KPI/승인 탭, 공급업체 관리, 품목 선택, 수량 조정, 최종 확인 관련 검사를 수행했다. 변경된 여백·열 수·문구에 대한 기존 기대값을 갱신했다.
- `npm run typecheck:app`, `npm run lint:strict`, `npm run build` 통과.
- `git diff --check` 통과. 전역 CSS·폰트 로더·MobileViewportFrame·PC 전용 파일·주간보고 내부 변경 없음. MobileShell의 NavButton/nav/pill 변경 없음.
- 360 / 390 / 430 / 550 / 592 / 767px에서 본문·탭바는 최대 430px, 768 / 1023px에서 720px이며 중앙축 일치. 대시보드 가로 넘침 없음. 1024px PC 전환 및 모바일 스타일 scope가 없는 것 확인.
- 실브라우저: KPI/재고 표, 승인함 메뉴→부서 승인 화면→요청 작성, 원자재 입고→공급업체→품목→수량→최종 확인창, 더보기, 불량 허브→바로 처리→폐기→출처→품목/사유 입력 확인.
- 360×420에서 최종 확인 메모·확인창과 불량 사유 입력 접근 확인. 실제 휴대폰 키보드 검증을 대신하는 결과는 아니다.
- 검증은 3016 미리보기와 기존 복제 DB에서 수행했다. 실제 재고 반영/폐기/승인 실행은 하지 않았다. 입력 흐름의 기존 자동 초안 저장은 복제 환경에서만 발생할 수 있다.
- PC의 기존 v2 비교 기록은 이전 문서에 보존했다. 이번 후속 수정에서 PC 전체 화면의 픽셀 비교를 다시 수행한 것은 아니다. 하위 흐름 모든 데이터·권한·오류 조합을 실브라우저로 전수 검사한 것으로 주장하지 않는다.
