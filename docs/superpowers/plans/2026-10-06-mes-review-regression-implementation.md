# DEXCOWIN MES 검토 결과 수정 및 반복 검증 실행 계획

**GOAL:** 사용자 기대값과 충돌하지 않는 수정 후보를 해결하고, 자동 회귀 테스트와 재사용 가능한 브라우저 검증 스킬로 재발 방지 근거를 남긴다.

사용자가 2026-10-06 이 계획의 실행을 승인했다. 시작 기준 HEAD는 `e11a0c874a6029e59dd25d9d560dc277bbb14acf`이고 작업 트리는 깨끗했다. 구현 단계는 main에서 브랜치·워크트리 생성, 커밋·푸시 없이 진행했다. 이후 사용자 요청으로 이번 변경만 기능별 5개 커밋으로 나누고 현재 main의 origin에 푸시하는 후속 작업을 승인받았다.

## 승인된 범위

- 이번 수정 관련 흐름부터 자동 테스트와 브라우저 스킬을 구축한다. 전수 검수와 지도는 보류한다.
- 모델 기호의 현재 1~5자 지원을 유지한다. 모호한 연결을 임의로 추론하지 않는다.
- 원본 직원·개발 서버/DB, 사용자 기대값 판정, 동결 파일은 보존한다.
- 이전 검수 원장의 관찰을 최신 main에서 재현한 뒤 수정한다. 과거 파일 검증을 다시 미실행으로 기록하지 않는다.

## 작업과 검증

- [x] **백엔드 모델 연결 계약:** 현재 기호 스냅샷을 정렬된 기호 단위로 전체 소비하는 유일 분해를 구현한다. 기존 정상 한 글자·공용·빈 코드 호환을 유지한다. 모호한 읽기는 명시적 오류, 모호하거나 미등록·중복 슬롯의 품목 저장은 422, 기존 품목의 해석을 바꾸는 모델 기호 생성·변경은 409로 막는다. 연결 품목 삭제 보호도 같은 슬롯 판정을 사용한다. QF1 단일·공용 모델, API 목록/상세/플래그 편집, 모호성 및 기존 연결 보존을 pytest RED→GREEN으로 증명한다.
- [x] **출하 취소 정합성:** 최신 준비 취소 뒤의 정상 요청 취소는 시각과 CANCELLED 이벤트가 증명될 때만 후속 전이로 인정한다. 정합성 검사와 복구 판단은 같은 기준을 사용한다. 준비·픽업·역순 취소·요청 취소, 재고·예약 복구, 취소 증거 누락/이전 시각/후속 작업의 불일치를 검사한다.
- [x] **초기 재고 원장:** 양수 초기 재고에 공통 initial_stock 작업과 양수 목적 위치별 RECEIVE 거래를 남긴다. 각 거래 수량은 그 위치 효과와 같고 합계는 초기 수량과 같다. 0에는 작업·거래를 만들지 않는다. 초기 재고 출처를 표시하고 F704 창고 수량, 주간 입고/검산, 생산량 0, F705 불변, 공통 작업 취소 후 복구를 검사한다. 새 거래 enum과 과거 자료 자동 백필은 추가하지 않는다.
- [x] **관리자 모델·품목 화면:** 실제 렌더 경로에서 API 모델 슬롯으로 연결 품목/BOM과 편집 모델을 복원한다. 플래그만 바꾼 저장 payload와 재열기 동작을 Vitest로 고정한다. 모델 삭제 성공 뒤 직원 목록을 재조회하고 기존 폼 동기화 경로를 사용한다. 삭제 실패와 직원 재조회 실패도 검증한다.
- [x] **브라우저 환경 도우미:** 임시 코드 사본과 전용 DB·CSV·로그·프론트 산출물을 사용한다. HEAD와 명시적 작업 파일 overlay 해시를 기록하고 다른 dirty 변경을 자동 포함하지 않는다. 원본 포트, 경로 이탈, 점유 포트와 프로세스 소유권 불일치를 거부한다. 시작 실패 때 소유 프로세스를 정리하고 종료 뒤 증거를 보존한다.
- [x] **mes-browser-regression 스킬:** 작성 전 baseline 사용 시나리오를 평가한다. 승인된 기대값과 감사 ID의 부분 검증 범위를 연결하고, 실제 UI 조작·기대/실제·코드 식별값·URL·KST·증거·복구 결과를 실행별 폴더에 남긴다. 자동 테스트와 브라우저 결과를 구분하고 PASS/DIFFERENCE/BLOCKED/SKIP을 사용한다. 작성 후 독립 에이전트의 실제 사용을 검증한다.
