# 작업 예약 UI 개선 실행 계획

> 추천 모델: GPT-6.1 Sol / 추론: High / 대시보드·관리자 구현 병렬 분담

**GOAL:** 예약과 입고 예정을 작업자가 쉽게 이해하도록 대시보드를 정리하고, 관리자 작업 예약 상세를 기존 MES 디자인에 맞춰 재구성한다.

## 작업 경계

- work-reservations-ui 격리 워크트리와 3120 미리보기에서만 구현한다.
- 메인·직원 서버, DB 구조·예약 계산·승인·취소 API는 변경하지 않는다.
- 커밋·푸시·병합은 수행하지 않는다.

## 표시 계약

- 부서별 실재고에 해당 위치의 예약 수량을 한 번 표시한다. 구현 중 사용자 추가 피드백에 따라 예약도 옅은 알약으로 바꾸고, 부서·예약·불량 알약을 동일한 높이와 기준선으로 정렬한다. 부서와 예약은 같은 그룹으로 묶어 함께 줄바꿈한다.
- 재고 분포 막대는 부서별 실재고 길이와 색을 유지하고 해당 위치의 예약 비율만 사선으로 표시한다(2026-10-21 사용자 후속 요청). 상단 범례와 품목명 아래 중복 예약·입고 예정 문구는 제거한다. 실사와 불량·구형 패턴은 유지한다.
- 상세는 사용 가능 재고를 우선하고 예약된 재고와 들어올 예정을 분리한다.
- 실재고 214, 생산 예약 60, 입고 승인 대기 10 사례는 가용 154 / 예약 60 / 들어올 예정 10이다.
- 승인 대기 여부는 작업 상태로 표시하며 입고는 기존 자재의 예약으로 간주하지 않는다.
- 이동은 출발·도착으로 표시하고 전체 증가로 합산하지 않는다. 누락·조회 실패·불완전 예정을 0으로 표시하지 않는다.
- 직원 화면에서 내부 SR 번호와 예약 대상 없음 등 무의미한 문구를 제거한다.
- 관리자 상세는 작업 목적·담당자, 예약 자재 표, 완료 후 결과, 접는 처리 기록 순서로 재구성한다.
- 이 메뉴의 외부 스크롤 프레임·마스크를 제거하고 패널 테두리와 구분선으로 정돈한다.
- 관리자 취소의 필수 사유·중복 방지·revision 충돌 재확인은 유지한다.

## 체크포인트

- UI-1: 표시 계약 확정, 154 / 60 / 10 및 예약 없는 입고 승인 대기의 실패하는 회귀 테스트 확보.
- UI-2: 대시보드와 관리자 두 에이전트 구현, 부모 통합 및 실제 화면 점검.
- UI-3: 관련 테스트·타입·린트, 1912 / 1366 / 390 화면과 라이트·다크, 독립 검토 및 디자인 보정.

각 체크포인트를 별도 GOAL로 추적한다. 완료 증거는 아래에 기록한다.

## 진행 기록

- UI-1 완료: 직원용 표시 계약 확정. InventoryReservationPresentation.test.tsx의 두 회귀 테스트가 이전 UI에서 예상한 이유로 실패함을 확인했다(예약된 재고 표시 부재, 예약할 자재 없는 입고의 승인 대기 상태 가림).
- UI-2 완료: 대시보드와 관리자 구현을 GPT-6.1 Sol / High 두 에이전트에 독립 파일 범위로 배정했다. 실제 화면 점검으로 상세 요약을 축소하고 관리자 목적·결과를 나란히 배치해 첫 화면에 예약 자재 표가 보이도록 보정했다.
- UI-2 추가 요청 반영: 사용자가 실제 화면의 알약 없는 예약과 세 항목의 정렬을 지적했다. 최신 요청을 우선해 예약 알약을 도입하고, 두 대상 화면에서 언급 외의 간격·정렬·줄바꿈도 브라우저로 점검한다.

- 재고·예약 계산, API·DB 구조, 동결 영역, 공용 관리자 primitive는 변경하지 않았다. 커밋·푸시·메인 반영은 하지 않았다.
