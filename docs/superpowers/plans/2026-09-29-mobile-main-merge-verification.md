# 모바일 개발 내용 메인 통합 전 검증 기록

## 승인 범위와 보존

- 사용자가 3016 미리보기 워크트리의 개발 내용을 기능별로 세분화하여 메인에 병합하고 커밋·푸시하도록 승인했다.
- 서버 워크트리: `C:/Users/user/.codex/worktrees/mobile-ui/ERP`. 기존 detached HEAD `ac92db97`에 파일 교체 없이 `codex/mobile-ui`를 연결했다.
- 최신 메인 기준은 `4ee96514`이다. 모바일 개발 기준 이후 메인의 네 개 커밋은 통합 후보에 모두 포함했다.
- 사용자 승인으로 동결 하단 탭의 아이콘 색상 변경을 포함한다. 앞선 개발 문서의 탭 변경 없음 설명은 각 문서 작성 당시의 기록이다.
- 개발 변경은 기능 41개와 기존 개발·검증 문서 9개로 나눠 기록한다. 해당 구현의 변경된 테스트를 함께 포함한다.
- 워크트리와 브랜치를 유지한다. 3016 서버의 중단·재시작, 서버 워크트리의 checkout·reset·stash·rebase·clean은 수행하지 않는다.
- 메인과 서버 워크트리의 개발용 `frontend/next-env.d.ts` 변경은 포함하지 않는다. 다른 워크트리의 미커밋 작업도 포함하지 않는다.
- 작업 전 변경 파일 ZIP, binary diff, HEAD·파일 SHA256·서버 응답을 `_attic/runtime/mobile-merge-20260929/`에 보존했다. 개발 소스 바이트는 유지했고, 문서 하나의 끝 빈 줄만 Git 공백 검사를 위해 정리했다.

## 검증 환경과 결과

- 메인 기준과 모바일 변경을 3-way 적용한 후보를 별도 검증 디렉터리에 복사했다. 적용 충돌은 없었다.
- 서버의 소스·개발 산출물 대신 검증 복사본에서 Node 20으로 타입 생성, TypeScript, strict lint, production build, 번들 검사를 수행했다. 모두 통과했다.
- 최초 production build는 외부 node_modules junction을 Turbopack이 허용하지 않아 실패했다. 검증 복사본에만 동일한 의존성을 복사한 후 기본 Turbopack 빌드가 통과했다. 애플리케이션 설정은 변경하지 않았다.
- 변경 영역의 모바일·공용·PC 회귀 테스트를 실행했다. 최초 실행의 모듈 import 오류 두 파일은 의존성 복사가 완료된 환경에서 다시 실행해 통과했다.
- 관련 테스트 총계는 2,214개 통과와 기존 실패 3개이다. 전체 테스트가 모두 통과했다고 주장하지 않는다.
- 기존 실패는 `frontend/app/mes/_components/_history_sections/__tests__/historyTableHelpers.test.tsx`의 내역 표 제목·접근성 문구 기대값이다. 테스트는 '재고 변동'을 기대하지만 현재 메인 구현은 '수량 변동'을 사용한다. 변경하지 않은 최신 메인에서도 같은 세 개 실패를 재현했다. 해당 표 구현과 테스트 파일은 이번 통합에서 수정하지 않았다.
- 각 기능 커밋에서 명시적 경로 stage, staged 파일 확인, `git diff --cached --check`, smart staged 검증 계획 확인을 수행한다. 검증 계획은 범위를 확인하는 용도로 사용하고, 실제 근거는 병합 후보의 관련 테스트·타입·lint·빌드·브라우저 결과를 재사용한다.
- React act 및 styled-jsx 테스트 환경 경고는 실패와 구분해 원본 로그에 보존한다.

## PC 비교

최신 메인과 병합 후보를 같은 복제 DB·관리자 계정·라이트 테마에 연결했다. 실제 거래 제출은 하지 않았다. 브라우저에서 표시 요소의 글자·좌표·크기·글꼴·색상·배경·padding·border·radius·shadow·display를 비교했다.

| 크기 | 비교 상태 | 결과 |
|---|---|---|
| 1440 × 1000 | 대시보드 | 비교 요소 일치 |
| 1440 × 1000 | 재고 상세 및 입고 선택 메뉴 | 비교 요소 일치 |
| 1440 × 1000 | 생산 가능수량 요약·모델 펼침·제품 BOM 상세 | 비교 요소 일치 |
| 1440 × 1000 | 입출고·불량·내역·일일 작업 일보 | 비교 요소 일치 |
| 1024 × 900 | PC 대시보드 및 일일 작업 일보 | 비교 요소 일치 |

- 1024px 첫 비교는 탭별 크기·자동 사이드바 호버·날짜 팝업 상태가 달랐다. 같은 크기와 상태로 맞춘 결과를 최종 근거로 사용한다. 일보는 숨겨진 팝업과 그 조상을 제외한 실제 표시 요소로 비교했다.
- 모바일 개발 브랜치의 변경 대상에 PC 전용 컴포넌트, 동결 주간보고 내부, 전역 CSS, 백엔드는 없다. 공유 컴포넌트는 수정됐으므로 PC 관련 코드를 전혀 수정하지 않았다고 표현하지 않는다.
- 공용 로딩의 `motion-safe` 클래스는 동작 감소 설정을 존중하는 변경이다. 새 조회 props와 공통 helper 변경도 포함돼 있으므로 모든 PC 코드·모든 환경의 동작이 완전히 동일하다는 결론은 내리지 않는다.
- 비교한 대표 상태에서 PC 표시 차이를 발견하지 않았다. 모든 화면·데이터·권한·오류·테마 조합 또는 원시 픽셀 전수 비교는 수행하지 않았다.

## 운영 확인

- 작업 시작과 기능 커밋 중 3016 페이지의 HTTP 200 응답을 확인했다. 서버 listener PID는 `40768`, 부모는 `23784`로 유지됐다.
- DB 마이그레이션·운영 DB 수정·배포는 수행하지 않았다. 로그인 및 화면 검증은 기존 복제 DB 환경에서만 수행했다.
- 로컬 비교용 서버는 별도 포트를 사용한다. 작업 종료 시 이번 검증에서 만든 비교 서버만 정리하고 원래 3016/3017/8016 및 모바일 프록시를 유지한다.
- 메인 병합 결과가 검증 후보와 같은 소스인지 확인한 후 일반 push를 수행한다. 강제 push와 워크트리 삭제는 하지 않는다. GitHub CI는 시작 상태와 링크만 보고하며 완료를 기다리지 않는다.
