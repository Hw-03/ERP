# 작업 예약 메인 통합과 워크트리 정리

> **추천 모델: GPT-6.1 Sol** — 예약 계약과 최신 메인 개선을 함께 보존한다.
> **추천 추론 수준: High** — 기능 되돌림 이력과 실제 DB 전환을 검증한다.
> **실행 방식: 하위 에이전트 병렬 작업** — 프론트·백엔드 검토를 분담하고 부모가 최종 반영한다.

**GOAL:** 작업 예약과 이번 화면 개선을 최신 메인에 통합·검증·푸시하고, 메인 실행 환경 반영 후 현재 워크트리를 안전하게 정리한다.

## 승인 범위

- 최신 main의 격리 detached 후보에서 예약 기능 되돌림을 역으로 복원하고, work-reservations-ui의 후속 변경을 결합한다.
- 최신 요청자 취소 권한, 내역 복사, 검색창·스켈레톤 개선과 메인의 별도 미커밋 작업을 보존한다. 별도 미커밋 작업은 이번 커밋에서 제외한다.
- 복사 DB에서 마이그레이션·기존 작업 전환을 시험한다. 실제 전환 시 대상 목록을 고정하고 전환 불가인 기존 임시저장만 사유 취소한다. 부분 완료·완료 작업과 실제 재고·거래 내역은 보존한다.
- 전체 프론트·백엔드 게이트, 계약·빌드·번들 및 실제 화면을 검증한 후 메인 코드·DB·실행 환경에 반영하고 일반 푸시한다.
- 0048의 downgrade를 시도하지 않는다. 실패 시 검증된 이전 코드·DB 쌍으로 복구하고, 반영 후 새 업무가 있으면 변경분을 먼저 보존한다.
- 메인 정상 동작·푸시 확인 후 미리보기 서버를 소유 경로로 식별하여 종료하고, 필요한 ignored 자료를 보존한 뒤 UI 워크트리와 통합 후보를 보관·정리한다. 별도 원본 예약 워크트리와 직원 실행 환경은 변경하지 않는다.
