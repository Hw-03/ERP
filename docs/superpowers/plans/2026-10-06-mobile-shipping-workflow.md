# 모바일 출하 업무 확장

**추천 모델: GPT-6 Sol** — 기존 출하 계약을 모바일에 연결한다.
**추천 추론 수준: High** — BOM 재매칭과 비동기 응답, 이탈·상태 전환 회귀를 검증한다.
**실행 방식: 하위 에이전트 병렬 작업** — 공통 계약 확정 후 작성과 상세·이력을 분담하고 화면 연결·검증을 통합한다.

## 승인 범위

DEXCOWIN MES 모바일에서 PC와 같은 출하 요청 작성·수정, 준비·픽업 완료와 취소,
이력 조회를 수행한다. 백엔드 API·DB 스키마를 재사용한다.

- 진입: 출하 관리·출하 이력 카드, 실제 건수.
- 관리: 새 요청, 준비 중·준비 완료 목록, 실제 최종 PF 중심 카드.
- 작성: 기준 PF → BOM 구성 → BOM 매칭 → 요청 정보 → 최종 확인.
- 상세: 인보이스·SN, PA/PF·동반품, 준비 체크, 메모·수정 이력·연결 로그.
- 완료 처리: 품목·수량·예약·재고 영향 확인 후 실행. 부족 재고는 창고 이동으로 연결.
- 이력: 완료·요청 취소 구분, 인보이스/PF 검색, 연·월별 펼침과 서버 커서 더 보기.
- 이동: PC URL 계약, 단계 입력 유지, 초안·인보이스 이탈 확인, 화면 전환 취소 구분.
- 스타일: 기존 색상 토큰, 20px 카드, 본문 14px·입력 16px·터치 44px 이상.
- 동결된 모바일 탭바와 PC 최종 카드 높이·열·스크롤은 보존한다.

## 작업과 검증

1. 공용 순수 함수 추출 — helper 및 기존 PC 출하 회귀 테스트.
2. 모바일 작성 위저드 — 기본 BOM, 후보·신규 이름, 수정·동반품, 실패·늦은 응답.
3. 상세·이력 — 상태별 실행·취소, 체크·인보이스, 수정 내역, 검색·페이지.
4. Shell·URL·전환 — 직접 URL, 탭·뒤로/앞으로, 1024px 경계, 취소 시 입력 유지.
5. 통합 — 관련 Vitest, 타입·정적 검사, 별도 복제 DB 브라우저 업무 검증.

실제 등록·완료·취소는 복제 DB에서 수행한다. 브라우저에서는 360·390·768px와 PC,
긴 이름, 입력·스크롤, 라이트·다크를 확인한다. 커밋·푸시는 별도 요청 전 실행하지 않는다.

## 구현 완료 및 검증 — 2026-10-06

- 공용 요청 초안·전송·매칭 검증 함수와 모바일 작성, 상세, 이력 화면 구현 완료.
- PC URL 계약과 모바일 이력 이동 연결 완료. Next 내부 history 표식을 재사용해
  검색 매개변수 갱신이 생략되던 문제를 수정하고 PC 전환에서 같은 요청을 확인했다.
- 관련 Vitest 12개 파일의 86개 테스트 통과. 기존 PC 출하 161개와 Desktop Shell
  51개 회귀 테스트 통과 결과도 확인했다. TypeScript 및 변경 production 파일 ESLint 통과.
- 복제 DB의 브라우저에서 신규 등록 → 준비 완료 → 픽업 완료 → 픽업 취소 →
  준비 취소 → 메모 수정 → 요청 취소를 실행했다. 픽업 재고 차감, 취소 역거래,
  예약 생성·해제, 수정 이력과 취소 이력 검색을 읽기 전용 DB 조회로 대조했다.
- 부족 재고의 창고 입출고 연결과 뒤로 복귀, 연·월별 이력 조회, 직접 URL,
  작성 중 탭 이탈, 1024px 전환 취소 시 초안 유지도 브라우저에서 확인했다.
- 360·390·768px와 PC의 레이아웃 및 라이트·다크 화면을 확인했다.
  키보드 공간은 360×480의 짧은 뷰포트로 확인했으며 실제 휴대전화 OS 키보드는 미검증이다.
- 원본 DB에는 검증용 송장번호가 없음을 확인했다. 백엔드 API·스키마와 동결된
  하단 탭바 및 PC 최종 카드 스타일은 이번 변경에 포함하지 않았다.
