# 출하 재진행 동기화 검증 개선

**GOAL:** 정상적으로 다시 준비 완료된 출하를 동기화 검증이 차단하지 않도록 수정하고, 사전 검증 실패 시 직원 서버를 정지하지 않는다.

## 변경 계약

- 출하 WORKFLOW는 커밋된 최신 created_at 기준으로 비교한다. 동시각은 명시적 역전 연결로만 정렬하며 상충 상태는 복구 불가 오류다.
- 정상 재진행을 과거 취소로 되돌리지 않는다. 다른 취소·배정·재고 검사는 유지한다.
- 실제 배포는 스키마 변화가 없어도 격리 DB의 migration, SQLite/FK, 재고, 업무 진단과 데이터 보존 검증을 정지 전에 수행한다.
- 정지 전 실패는 PRE_STOP, 사후 실패는 POST_STOP으로 보고한다. dry-run/NO_CHANGES는 유지한다.
- 직원 원본 DB 변경·실제 배포·기동·커밋·푸시는 이번 구현 범위가 아니다.

## 검증 기록

- RED: 정상 재진행·최신 상태 불일치·오래된 복구 ID 등 7개 테스트 실패 확인.
- RED: 사전 검증 실패를 설정해도 기존 배포가 성공하는 문제와 stderr가 exit 8을 1로 덮는 문제 재현.
- GREEN: 재진행 및 격리 검증 관련 44개 테스트 통과.
- 직원 DB 읽기 전용 진단: 기존 WORKFLOW_STATE_RESIDUE 2건 해소, 전체 issue_count=0. 상태·원장 수정 없음.
- 출하 취소·재시도·동시성·복구·관리자 진단·격리 사전검증 77개 테스트 통과. 운영 안전 전체 묶음의 테스트 삽입 위치 오류 2건을 수정 후 해당 파일 전체 재검증 통과; 변경한 래퍼 exit 보존·정지 전 차단·성공 배포 3개도 통과.
- 예약 제목·본문 갱신 중 한글 출력 인코딩 오류를 발견해 Unicode 문자열로 재저장하고, UTF-8 읽기로 제목·본문 및 replacement character 0개 확인. 매일 04:00 KST 유지.

## 운영 지침 시나리오

단독 작업 요청에 따라 별도 에이전트 없이 계약 및 다음 압박 시나리오를 검토했다(에이전트 행동 실험은 아님).

1. 출근 임박 + 활동 승인 + PRE_STOP 실패: 재실행이나 데이터 반영 없이 차단 증적만 보고한다.
2. 코드 복사 완료 + POST_STOP 실패 + 빨리 기동 요구: 완료로 보고하지 않고 실제 헬스와 백업을 보고한다. 기동은 별도 판단한다.
3. 과거 CANCELLED + 최신 PREPARED 원장: 과거 복구 ID를 적용하지 않고 현재 회차 진단을 따른다.

기존 스킬에는 PRE_STOP/POST_STOP과 재진행 계약이 없었음을 확인한 뒤 추가했다. 시간·호출 순서·검증 실패 금지는 유지한다.
