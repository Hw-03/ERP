# 모바일 12개 주석 구현·검증

**GOAL:** 행 높이·줄바꿈·아이콘·정렬·여백을 일관되게 수정하고, 접근 가능한 모든 모바일 탭과 하위 화면을 브라우저에서 검증한다.

## 승인된 구현 기준

- 내역/재고 행 98px, 품명 공백 우선 2줄 말줄임, 전체 이름 상세 제공. 단건 내역 수량 요약은 상세에서만 표시.
- 생산 가능 수량 3열 가운데 정렬, 탭 아이콘 PC 고유색. 탭바 색 외 디자인 유지.
- 실행 버튼 아래 중복 패딩 제거, 탭바 위 8px만 유지. 불량 검색 라벨 숨김·빈 장바구니 최소 56px·표 외곽 클립/내부 스크롤 분리.
- 체크리스트 선택 행 가용 높이 배분/최소 88px, 공통 아이콘 배경과 문구 비율 적용.
- BOM 헤더 압축, 551px 기준 지정 품목 144px 이하. 기존 조회·펼침·포커스·터치 보존.
- 모바일만 수정. API/DB/계산 및 동결 주간보고 내부 변경 없음. 커밋·푸시·배포 없음.

## 크기·회귀 검증

- 변경 화면 360/390/430/768px, 낮은 화면 360×420, PC 1024px 이상.
- 행 실측, 2줄 말줄임, 중앙 정렬, 외곽 마감, CTA/탭바 8px, BOM 헤더 높이를 확인한다.
- 관련 테스트, 타입 검사, 린트, 빌드 결과를 완료 시 기록한다.
- 실제 승인·폐기·출하 확정은 하지 않는다. 데이터가 없어 진행할 수 없는 경로는 명시한다.

## 2026-09-29 검증 결과

- 기존 격리 작업 폴더의 3016 미리보기에서 관리자 계정으로 확인했다. 기존 작업 변경을 보존했다.
- 551×822 및 변경 화면의 360/390/430/768×822, 360×420에서 가로 페이지 넘침 없음.
- 재고와 내역 행은 각 크기에서 98px. 품명 영역은 공백 우선 줄바꿈/2줄 말줄임이며 상세에 전체 이름을 유지한다.
- 생산 가능 현황은 모델 왼쪽, 나머지 헤더/수량 center. 탭 SVG stroke는 파랑/초록/빨강/보라/중립색으로 확인했다.
- 불량 표는 외곽 overflow hidden과 내부 스크롤을 분리하고 캡처로 모서리를 확인했다. 빈 장바구니 56px. 보이는 검색 라벨은 숨겨지고 접근성 이름은 유지된다.
- 불량 실행 버튼~탭바 8px. 입출고 공유 품목/수량/최종 확인 버튼의 잔여 pb-1을 제거한 뒤 최종 확인 화면에서 모든 지정 크기 8px를 재확인했다.
- 360×420에서 불량 사유 입력·관리 분류와 실행 버튼을 동시에 접근할 수 있었다. 바깥 본문과 안쪽 결과표의 스크롤은 분리되어 있다.
- 체크리스트 선택 행은 높이 822에서 105px, 높이 420에서 최소 88px. 마지막 모델까지 스크롤해 진입했다.
- DX3000 지정 품목 BOM 헤더는 551px에서 97px, 펼침/접기/닫기는 44×44px, 목록 영역은 약 600px. 360×420에서도 목록 영역 약 247px를 확보했다. 닫은 뒤 `하위 구성 보기`로 포커스 복귀 확인.
- 1280×900 PC에서 대시보드 상세/BOM 표, 기존 불량 검색 라벨과 품목 코드·부서 가용 열, 가로 넘침 없음을 확인했다. 모바일 전용 옵션의 기본값 false와 PC 분기는 별도 코드 검토 통과.
- 사양 검토 및 코드 품질 검토 통과. frozen 주간보고 내부와 backend 변경 없음. 탭바의 nav/pill 디자인 변경 없음.

### 검증 한계

- 작성 중·내 요청·창고/AS 승인 대기·출하 이력·알림은 데이터가 없어 빈 상태만 확인했다. 해당 데이터 상세는 미검증이다.
- 주간보고에서 선택한 튜브 BOM은 하위 품목이 없어 더 깊은 전개는 미검증이다.
- 부서 생산에서 선택한 BOM은 부품 재고 부족으로 최종 확인이 비활성이다. 검증을 위해 재고를 가져오거나 변경하지 않았다.
- 모든 메뉴 진입을 확인했으며, 방향별 모든 품목/입력 조합을 전수 검사한 것은 아니다. 위 표에 실제 도달한 단계를 기재했다.
- 실제 승인·반려·폐기·재작업·입출고 반영·출하 확정·체크리스트 편집 저장은 실행하지 않았다.
