**실행 방식: 하위 에이전트 병렬 준비 + 부모 순차 검증** — AS 제어, 패킷 수집, BOM 기록기를 분담하고 부모가 실제 환경 검사를 통합한다.

## 목표와 범위

AS의 수신 지연·관측 손실을 실행 중 감지해 후속 발행을 중단하고, BOM은 원래 입력 흐름을 바꾸지 않은 자연 발생 실패 보존을 준비한다. 이 도구 목표는 과거 AS·BOM 원인 확정과 별개다.

- 후보 `codex/mes-main-candidate-comparison-20261016`, 시작 HEAD `63d4ed59acf223e6cad62b3a360d905825d92021`과 기존 미커밋 변경을 보존한다.
- 검토용 3038/8038, 사용자 초안·연구 요청, main·직원 DB/서비스·예약은 변경하지 않는다.
- 도구 검사는 별도 Linux 환경, 업무 DB 없는 고정 응답 서버와 React 입력으로 한정한다. AS 기존 업무 구간, 원 BOM 선택자, 전체 검사는 실행하지 않는다.
- 공개 업무 API·스키마·재고 계산식, 커밋·푸시·CI 실행은 범위 밖이다.

## CP0 — 기준 고정

HEAD·파일/lockfile 해시·미커밋 원본·보호 DB/session 해시·프로세스를 기록한다. 새 실행 폴더에서 기존 런타임을 사용한다. 시작 파일 사본과 과거 원문은 수정하지 않는다.

## CP1 — AS 실시간 수신과 중단

기존 파일 기록과 함께 Next worker 수신 이벤트를 Unix 소켓으로 즉시 비동기 전달한다. 실행 ID·PID·순번·요청 ID를 검사하고 발생 시각과 실행기 전달 시각을 구분한다. Next 처리 시각을 TCP 도착 시각으로 부르지 않는다.

시계 오차 10ms·발행/수신 오차 20ms는 유지한다. 만료 타이머와 발행 직전 공통 가드에서 검사하며 수신 확인을 기다려 일정을 미루지 않는다. 기록 미도착, 실제 Next 처리 시각 초과, IPC 단절·잘못된 ID·순번 누락·대기열 초과를 구분해 최초 중단을 고정한다. 늦은 정상 기록으로 재개하지 않는다.

보장 범위는 **감지 후 새 발행 없음**이다. 이미 발행한 요청은 강제로 끊지 않고 결과를 보존한다. 최초 위반·감지·중단, 발행/미발행 목록을 남긴다.

## CP2 — 패킷 수집과 손실 구간

loopback IPv4/TCP 진단 포트를 커널 소켓 필터로 제한하고 헤더 메타데이터만 저장한다. 수신 버퍼 요청/실제값을 기록하고 제한된 배치로 먼저 수신한다. 시스템 설정과 무제한 큐는 사용하지 않는다.

100ms와 준비·시작·중단·보존·정리 경계에 통계를 읽는다. 통계 초기화를 고려한 구간값·누계·조회 전후 시각을 기록한다. 커널 패킷 손실·사용자 공간 기록 오류·BPF 손실을 구분하고 실시간 중단에 연결한다. 손실 구간이 실패 소켓 관측과 겹치면 완전한 원인 근거로 사용하지 않는다. 과거 손실 2건의 발생 시점은 계속 미확인이다.

## CP3 — BOM 자연 발생 기록 준비

기존 native/명령/실패 전 보존기를 재사용한다. 원 테스트의 입력·즉시 다음·단언·기한을 유지하고 정상 경로의 조건부 중단점과 상태 setter 계측을 사용하지 않는 선택적 기록 경로를 마련한다. 대상 숫자 입력 명령·포커스·이벤트·DOM·React 추적값·매칭 요청을 제한된 버퍼에 저장한다. 최초 값 손실과 쓰기 호출 스택을 고정하되 제품 상태를 변경하지 않는다.

준비·기록 손실은 관측 불충분이다. 명령 성공·대상 식별·무손실인데 이벤트/값 변화가 없다면 확보한 입력 실패 증거로 보존하며 원인 계층은 단정하지 않는다. 입력 뒤 시작한 같은 대상 매칭 요청과 선행 기본값 응답을 구분한다. 원 단언 실패 자료는 테스트별 정리·context 종료 전에 저장한다.

이번에는 기록기 자체 검사만 한다. 이후 실제로 필요한 정상 BOM 검증에 선택적으로 연결하며 새 반복·예약·CI는 만들지 않는다.

## CP4 — 검증·기록

- AS: 정상, 전달 지연, 처리 시각 초과, 미도착, 실행기 지연, IPC/순번 오류, 중단 후 미발행과 진행 요청 결과 보존.
- 패킷: 필터·양방향·통계 초기화/누계·구간 경계·손실/기록 오류·마지막 배치.
- 실제 도구: 업무 DB 없는 실제 Next worker와 고정 응답 서버, 실제 React 기록 on/off의 입력 결과·추가 포커스/요청 부재.
- 변경 파일과 직접 소비자만 검사한다. 고의 지연·손실은 도구 검사이며 원 제품 실패 재현이 아니다.
- 묶음마다 상세 결과·첫 비교표·활성 TODO·인계를 갱신한다. 기존 유효 근거를 재사용하고 새 검사·미실행을 구분한다.

완료는 도구 신뢰성과 다음 실패 보존 준비에 한정한다. 과거 원인·직원 영향·병합 판단은 새 인과 근거가 없으면 계속 미확정/보류다.
