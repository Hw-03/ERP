- 첫 일반 E2E는 297건 통과·1건 실패·1건 재시도 통과였다. 불량 보관은 로딩 중 즉시 `isVisible()`이 false를 반환해 필터 펼치기를 건너뛰었다. 두 실패 trace 모두 이 순서를 확인했다. 새 보관 화면의 기본 접힘 계약에 맞춰 버튼 출현을 기다리는 클릭과 `aria-expanded=true` 단언으로 바꾸고, 해당 파일 3건을 재시도 0으로 통과했다 (`e2e-ci-storage-green.log`). 부분/전량 복귀·위치 수량·다른 원건 불변 단언은 유지한다.
- 출하 `SHIP-VARIANT`의 첫 시도는 BOM 매칭 요청에 의도한 2가 아닌 1이 전송돼 후보가 없었다. 서버는 38ms/200으로 해당 입력에 맞게 응답했고 fixture 품목/BOM 생성은 정상이었다. 화면 수량 2와 실제 매칭 payload 2를 직접 검사하도록 보강한 뒤 빠른 입력 흐름을 그대로 3회, 재시도 0으로 확인했다 (`e2e-ci-variant.log`). URL 대기·고정 sleep·재시도 증가·제품 추측 패치는 넣지 않았다. 최초 입력 누락의 정확한 경합 원인은 미확정이며 반복 통과를 원인 해결로 주장하지 않는다. 최초 trace와 새 trace를 보존한다.
- 위 두 E2E의 현재 소스 해시·선언 위치만 원장 바인딩에 갱신하며 과거 완료/단언/보고서는 보존한다. 프론트 제품 코드·빌드 입력이 바뀌지 않아 최종 production 빌드와 실제 자료 브라우저 근거를 재사용한다. 후속 정합성 조회 수정은 67건 국소 검사로 구분하며 과거 전체 검사를 새 코드 전체 PASS로 확대하지 않는다.
