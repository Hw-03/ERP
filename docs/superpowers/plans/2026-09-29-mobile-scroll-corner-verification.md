# 모바일 스크롤 모서리 수정 검증 기록

완료: 2026-09-29. 기존 mobile-ui 격리 작업 폴더에서 구현했으며 커밋·푸시·배포는 수행하지 않았다.

## 참고한 PC 커밋과 적용 원리

- `0369395b`, `3eda140b`: 스크롤 콘텐츠와 화면 높이에 고정되는 프레임을 분리한다. 자연 높이 콘텐츠의 마지막에만 둥근 모서리가 붙으면 중간 스크롤의 하단이 직각이 된다.
- `16b532a9`, `ab7f88c6`: sticky 요소 사이에 불필요한 스크롤 컨테이너를 만들지 않고, 모서리 마스크 배경을 실제 주변 `--c-bg`에 맞춘다.
- `603a5993`, `913ab33a`: 헤더 곡률과 외곽 곡률을 맞추며 sticky 경계의 모서리·테두리를 별도로 유지한다.
- 원문: `_attic/docs/EXTERNAL_SCROLLBAR_RAIL_GUIDE.md`. PC 코드는 변경하지 않았다.

## 적용

- `MobileScrollFrame.tsx:6`: 대시보드·내역의 실제 scroller 밖에 클릭을 막지 않는 고정 모서리 마스크를 둔다. 내역은 상·하단, 대시보드는 하단에 적용한다.
- `InventoryItemsTable.tsx:123`: 모바일 표는 `overflow-clip`으로 외곽을 유지한다. 모바일 헤더의 독립 24px 곡률을 제거하고 20px 상단 마스크와 불투명 헤더 배경을 사용한다.
- `MobileDashboardScreen.tsx:175`: 검색·초기화 도구줄의 실제 높이를 측정해 표 헤더와 상단 모서리의 sticky 위치를 맞춘다.
- `useChunkedRender.ts:26`: 로딩 중 감지 요소가 없는 모바일 조회에서 로딩 해제 후 추가 행 감지를 연결한다. 기본값과 PC 호출 동작은 유지한다.

- 수정 전 캡처에서 화면 하단 모서리 픽셀이 주변 배경과 달라 실패함을 확인했다. 수정 후 동일 위치가 주변 배경과 일치했다.
- 551×822의 처음·중간·끝 스크롤 캡처로 재고 표 상단의 흰 조각, 내역 상·하단 직각 잘림이 사라짐을 확인했다.
- 360·390·430·768px와 360×420에서 가로 넘침 없음, 콘텐츠와 탭바 너비 일치, 하단 간격 8px를 실측했다.
- 필터 초기화 줄을 표시했을 때 헤더가 검색 영역 바로 아래에 유지됨을 확인했다.
- 최초 조회 후 재고 행 누적 렌더링과 목록 끝까지의 스크롤을 확인했다.
- PC 1280px에서 대시보드·내역의 기존 열, 24px 곡률, 모바일 마스크 미적용을 확인했다.
- 관련 Vitest 31개, 대상 ESLint, `npm run typecheck:app`, `npm run build`, `git diff --check` 통과.
- 개발 중 React 미마운트 상태 갱신 경고 기록을 확인했다. 새로고침·재진입 및 새 검증 탭의 화면 전환에서는 재발하지 않았다.
- 캡처와 실측 JSON: `_attic/runtime/mobile-ui/screenshots-v9/`.

## 후속: 상단 곡선 옆 세로선

- 추가 참고 커밋: `350d2aae`는 PC 목록의 긴 wrapper 테두리를 정리하고, `913ab33a`는 헤더에 필요한 윤곽을 복원했다. `603a5993`은 모서리 마스크가 외곽 경계까지 닿도록 1px 확장했다.
- 수정 전 551px 화면에서 표 외곽은 x=72.5~478.5, 마스크는 x=73.5~477.5였다. 양쪽 1px 테두리가 마스크 밖에 남았다.
- `InventoryItemsTable.tsx:122`: compact 마스크를 wrapper 앞 형제로 옮겨 외곽 전체를 덮는다. 높이와 음수 여백은 그대로여서 목록 위치와 스크롤 높이는 유지된다.
- 수정 후 마스크와 외곽의 양끝이 일치하며, 곡선 바깥의 좌우 픽셀이 주변 배경과 같음을 확인했다. 기존 외곽 테두리·헤더 및 행 구분선·PC 분기는 유지했다.
- 551px의 처음·중간·끝, 360·768px, 360×420 및 검색 결과 1개인 목록을 확인했다. 가로 넘침과 모서리 돌출이 없었다.
- 새로 진입한 화면에서 100행 누적 렌더링과 목록 끝을 확인했다. 브라우저 오류·경고는 없었다.
- 관련 Vitest 11개, 대상 ESLint, `git diff --check` 통과. DOM 배치와 스타일 변경은 관련 테스트·린트·브라우저 실측으로 검증했다. 읽기 전용 코드 리뷰에서도 구체적인 회귀 문제는 발견되지 않았다.
- 캡처: `_attic/runtime/mobile-ui/screenshots-v10/`.

## 후속: 곡선 선 제거·간격 유지·필터 정렬

- 모바일 상단 마스크에서 테두리 띠를 주변 배경으로 덮었다. PC의 곡선 테두리 분기는 그대로 유지했다.
- 도구줄 실제 높이에 기존 8px 간격을 더해 헤더·모서리 고정 위치를 계산한다. 도구줄 아래의 절대 위치 배경이 간격 사이로 스크롤 행이 보이지 않게 한다.
- 필터 버튼과 AND/OR를 묶고 AND/OR를 버튼 왼쪽에 배치했다. 닫힌 영역의 여백을 제거하고, 펼침·닫힘 모두 버튼 오른쪽을 목록 외곽에 맞췄다.
- 수정 전 595px에서 스크롤 중 간격은 0px, 필터 버튼은 목록 오른쪽보다 8px 안쪽이었다.
- 수정 후 595px의 처음·중간에서 모서리와 도구줄 간격은 8px, 버튼과 목록의 오른쪽은 모두 x=500.5였다. 360px에서는 필터 열림·닫힘 모두 x=348로 일치했다.
- 초기화 줄이 표시되어 도구줄 높이가 98px일 때도 헤더·모서리는 y=106에 유지되어 간격이 8px였다. 가로 넘침은 없었다.
- 관련 Vitest 17개, 대상 ESLint, `git diff --check` 통과. 브라우저 오류·경고와 읽기 전용 리뷰의 구체적인 회귀 지적은 없었다. 좁은 모바일 배치·스타일 변경이므로 전체 게이트는 반복하지 않았다.
- 캡처: `_attic/runtime/mobile-ui/screenshots-v11/`.

## 후속: 하단 다섯 탭의 상단 여백 통일

- 더보기의 기존 12px를 기준으로 `MobileShell.tsx:512`의 공통 main에 `pt-3`을 적용했다. 여백은 실제 scroller 밖에 있어 스크롤 중에도 유지된다.
- 대시보드·입출고·불량·내역·더보기의 개별 상단 padding을 제거했다. 내역의 기존 16px도 공통 12px로 통일했다. 주간보고는 외부 스크롤 wrapper의 중복 `pt-3`만 제거했고 내부 보고서는 변경하지 않았다.
- 595×822에서 다섯 탭의 콘텐츠 시작은 모두 y=12였다. 대시보드 sticky 검색창과 내역 scroller도 스크롤 중 y=12를 유지했다.
- 360×420의 내역·더보기에서 상단 12px, 하단 탭바 앞 8px, 가로 넘침 없음이 유지됐다. 하단 nav·버튼·pill 디자인은 변경하지 않았다.
- 관련 Vitest 65개, 대상 ESLint, `git diff --check` 통과. 읽기 전용 리뷰에서도 main padding과 `h-full` 소비자의 높이에 구체적인 회귀 문제는 발견되지 않았다.
- 캡처와 실측: `_attic/runtime/mobile-ui/screenshots-v12/`.

## 후속: 입출고 상단 버튼·진행 안내·빈 작업 영역

- 모바일 입출고의 네 탭을 44px 둥근 버튼으로 변경했다. 선택된 버튼은 파란 바탕과 흰 글자, 비선택 버튼은 옅은 바탕과 테두리로 구분한다. 기존 클릭·건수·이탈 확인 동작은 유지했다.
- 진행 안내를 둥근 패널로 정리하고, 헤더가 없을 때 섹션 탭의 중복 8px margin을 제거해 상단 12px 기준을 유지했다. 승인함 목록도 공통 12px 좌우 여백에 맞췄다.
- 모바일 AS·연구 승인함의 플라스크를 Wrench 아이콘으로 교체했다. 데스크톱 분기는 변경하지 않았다.
- 모바일 작성 중 패널에 남은 높이를 전달하고, 빈 상태의 260px 최소 높이를 모바일에서만 해제했다. 긴 작업 목록의 외부 스크롤은 유지한다.
- 실제 서버에 관리자 작성 중 요청이 있어 빈 상태를 만들려고 요청을 삭제하지 않았다. 실제 화면 DOM·CSS를 복사한 임시 정적 레이아웃에서 빈 영역을 검증했고 임시 파일은 삭제했다. 595×822에서 빈 영역과 main 하단은 y=732, nav는 y=740으로 일치했고, 360×420에서도 빈 영역과 main 하단은 y=330으로 일치했다.
- 실제 화면 360×420에서 탭 높이 44px, 상단 12px, 가로 넘침 없음과 작성 목록 표시를 확인했다. 595×822에서 작성 화면과 승인함 공구 아이콘을 확인했다.
- 관련 Vitest 35개 통과. 후속 최소 높이·정렬 수정 후 직접 관련 18개를 재실행해 통과했다. 대상 ESLint와 `git diff --check`도 통과했다. 읽기 전용 리뷰에서 구체적인 회귀 결함은 발견되지 않았다.
- 캡처: `_attic/runtime/mobile-ui/screenshots-v13/`. `empty-layout-fixture-595.png`는 정적 레이아웃 검증 캡처다.

- 실제 내 요청 빈 화면에서 595×822의 패널 하단과 main 하단은 모두 y=732, nav 시작은 y=740이었다. 360×420에서도 패널과 main 하단이 y=330으로 일치하고 가로 넘침이 없었다.
