# DEXCOWIN MES 배포 기준판·통합판 직접 확인

이 안내는 직원 서버와 분리된 로컬 검토 환경용이다. main이나 직원 서버를 바꾸지 않는다. 두 판은 같은 날 동기화된 직원 원형 자료에서 준비했으며, 업무 검증 중 만든 기록은 별도 QA DB에 보관했다.

## 실행 방법

PowerShell에서 기존 워크트리로 이동한다.

**전환·초기화·종료 명령 전에 `127.0.0.1:3035`의 브라우저 탭을 모두 닫는다.** 열어 둔 화면이 새 DB로 자동 재접속하면 이전 요청의 조회/취소 미리보기를 다시 보내 감사 로그가 생길 수 있다. 시작 전후 DB 불변 검사는 이 경우에도 기동을 중단한다. 원본 직원 서버의 브라우저나 서비스는 건드리지 않는다.

```powershell
Set-Location C:\Users\user\.codex\worktrees\mes-expectation-closure\ERP
```

배포 기준판을 연다.

```powershell
python scripts/dev/mes_integration_review.py baseline --manifest-sha256 d7fd68539720ff4ce47d64d56a527ed5ba214308f02005cade36011734d65f4e
```

통합판을 연다.

```powershell
python scripts/dev/mes_integration_review.py integrated --manifest-sha256 d7fd68539720ff4ce47d64d56a527ed5ba214308f02005cade36011734d65f4e
```

명령이 기동 완료를 알리면 새 탭으로 `http://127.0.0.1:3035/mes`를 연다. 원하는 역할의 직원으로 로그인한다. PIN은 이 대화에서 준비한 격리용 값을 사용한다. 실제 직원 계정의 PIN은 바꾸지 않았다. 실행 묶음의 모든 소스·의존성·빌드 해시를 읽으므로 전환 시작에 수 분 걸릴 수 있다.

종료 명령:

```powershell
python scripts/dev/mes_integration_review.py stop --manifest-sha256 d7fd68539720ff4ce47d64d56a527ed5ba214308f02005cade36011734d65f4e
```

처음 자료 상태에서 다시 확인하려면 버전 선택 명령 끝에 `--reset`을 추가한다. 기존 검토 DB는 `review-before-reset-*.db`로 먼저 보존된다. 단순 버전 전환에서는 각 버전에서 입력한 검토 내용을 유지한다.

미커밋 변경, 다른 소유자의 프로세스, 바뀐 manifest/코드/빌드/Node/설정/초기 DB, 서로 다른 스키마 조합, 정지 중 외부에서 바꾼 DB/WAL을 발견하면 중단한다. 거부 메시지가 나왔다고 가드를 끄거나 원래 서버를 종료하지 않는다. 전환 도중 강제 종료되어 lock이 남은 경우에도 상태 확인 후 복구해야 한다.

## 두 판의 의미

- 배포 기준판: 실제 배포 파일과 대조한 `1fbfca85`, DB revision `20261014_0045`.
- 통합판: 전체 작업을 합친 `4d89375c`에 불량 사유 메모 검색 누락을 바로잡은 `863d8183`의 제품 소스, DB revision `20261015_0046`.
- 이후 QA 체크포인트 커밋은 검증 기록과 전환 도우미를 남긴다. 커밋만 되돌려 현재 DB에 연결하는 방식은 사용하지 않는다.
- 기존 작업 브랜치와 원래 커밋은 보존돼 있다. 원격 푸시는 하지 않았다.

## 직접 확인할 흐름

| 흐름 | 선택/입력 | 확인할 결과 |
|---|---|---|
| 창고 원자재 입고→이동 | 창고 담당, `3-HR-0033`, 기존 공급업체, 소량 입고 후 창고→고압 | 입고는 창고만 증가, 이동은 창고 감소/고압 증가, 전체 수량 유지 |
| AS 사용·승인 | 위 고압 재고로 AS 새 요청, 기존 승인 담당자로 승인 | 승인 전 예약만 증가, 승인 후 해당 부서 정상 수량 감소 |
| 생산·분해 | 조립 담당, `7-AA-0060`, 실제 BOM으로 생산 1/분해 1 | 부모와 자식이 조립에서 반대로 증감, 부품 창고 수량 불변 |
| 수량 보정·전환 | 창고 소량 보정, `7-AA-0061`→`7-AA-0060` 전환 1 | 실제 출발/도착과 사용·회수 부품을 미리보기대로 반영 |
| 격리·복귀 | 창고 또는 부서의 새 불량/B급/구형 원건, 부분/전량/일괄 복귀 | 원건 잔량 감소, 원래 정상 위치 복원, 분류 변경/복귀 뒤에도 최초 발생 통계 유지 |
| 재작업·폐기 | 새 격리 원건의 일부로 실행 | 부모/자식의 정상·격리·폐기 수량 구분, 취소 시 같은 위치로 복원 |
| 튜브 입고·반품 | 튜브 담당, `8-TR-0001`, 허용된 기존 공급업체 | 튜브 위치만 변경, 새 격리 원건 반품과 취소가 서로 반대 증감 |
| 출하 | 새 QA 요청, `6-PF-0050`와 동반 `6-PR-0119` 각 1 | 준비 때 예약, 픽업 때 출하 위치 감소, 픽업/준비 역순 취소 시 수량·예약 복원 |
| 내역·보고 | 새 요청에 구분 가능한 QA 메모, 처리 뒤 내역/일보/주간 | 묶음별 실제 위치·담당자·시간·취소 연결, 취소와 완료 수량 구분 |

기존 운영 요청은 완료하지 말고 새 QA 요청을 만든다. 재고 부족 안내가 나오면 품목/BOM/기초 수량을 직접 바꿔 통과시키지 않는다. 모바일 크기에서는 입출고·불량 복귀·출하·내역 취소의 별도 화면도 확인할 수 있다.

실행 결과·변화 수량·성능·한계는 [통합 검증 기록](2026-10-15-mes-integration-results.md), 남은 상태는 [활성 TODO](../../../_attic/handoff/active/2026-10-15-mes-deployed-integration-todo.md)에 있다. 실제 직원 자료가 들어 있는 DB·화면·원문 로그는 ignored runtime에만 있다.

## 현재 한계

- 계획의 3.00MiB 번들은 기준판/통합판 모두 초과했다. 배포판이 사용 중인 3.20MiB 검사는 통과하지만 별개의 결과다.
- 부서 간 직접 이동 메뉴는 두 화면의 허용 작업 목록에 없어 브라우저로 실행하지 않았다.
- PostgreSQL 전용 2조건은 이번 SQLite 검증에서 실행하지 않았다. 실제 전환·업무 검증은 복제 SQLite 기준이다.
- 일부 일보 취소 작업명이 내부 식별자로 표시된다. 수량/위치/취소 연결의 오류와 구분해 기록했다.
- 이전 전체 기대값 완료를 새 통합판 전체 PASS로 바꾸지 않았다. 이번 자료는 실제 실행한 경로와 국소 검사 범위만 증명한다.
