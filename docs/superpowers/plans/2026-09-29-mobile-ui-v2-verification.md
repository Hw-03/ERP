## 기능 보존 확인

- 부모가 구현하고 독립 검수자가 diff와 소비 경로를 읽었다. 업무함 선택 포커스 복원, 일보 좁은 폭 줄바꿈, 작은 터치 영역을 지적받아 반영했다.
- API·업무 계산·권한·기본 선택값·조회 정책·저장 시점 변경을 발견하지 못했다. backend, Desktop 컴포넌트, globals.css, 동결 weekly 내부 diff 없음.
- MobileShell diff는 main 크기/모바일 scope와 외부 모달 scope뿐이다. NavButton/nav/pill 구현은 변경하지 않았다. MobileViewportFrame은 기준 커밋과 동일하다.
- 최종 통합: **32개 파일, 323개 테스트 통과**. 모바일 디렉터리, Inventory 상세/목록/KPI, WarehouseSectionTabs, DailyWorkReport, Capacity 모바일/PC, HistoryDetailPanels/FilterBar 포함.
- 메뉴 열기 무전환·권한·건수·선택 포커스, 깊은 BOM 0~8 펼침/접힘, 초안·이탈 확인·알림 이동·필수 사유·출하 체크·일보 저장/오류 회귀 포함.
- 최종 `npm run build` 성공(내장 TypeScript 포함). `npm run typecheck:app`, `npm run lint:strict` 성공 후 마지막 국소 변경은 해당 파일 eslint와 관련 테스트 재확인.
- styled-jsx의 jsdom `jsx` 속성 경고는 기존 테스트 환경 경고로 남는다.

## 검증 범위와 한계

- 모든 화면 × 모든 폭 × 모든 업무 상태를 실브라우저에서 전수 조합한 것은 아니다. 폭 경계는 공통 shell/대시보드를 모두 측정하고 각 대표 화면은 390px 및 관련 낮은 높이로 확인했다. 변경하지 않은 v1 계정/알림/지도/주간 검증은 이전 기록을 재사용했다.
- 실제 iOS/Android 키보드·회전 센서는 사용하지 않았다. 낮은 viewport는 키보드의 완전한 대체 검증이 아니다.
- 깊이 0~8 BOM은 테스트 fixture 검증이며 실데이터 브라우저는 실제 존재하는 트리 단계에서 확인했다.
- 최종 승인·반려·폐기·취소 등 실거래의 모든 조합을 제출하지 않았다. 요청·검증·저장 보존은 기존 회귀 테스트와 diff 검수를 함께 사용했다.
- 같은 폭의 모바일 전후 비교에서 일보 날짜는 기존 캡처와 하루 차이가 있으며, 다른 상태 차이가 있는 캡처는 화면 재배치 참고용이다.
- 사용자 만족도를 보장하거나 테스트 통과만으로 디자인이 완벽하다고 선언하지 않는다. 미리보기와 전후 비교가 최종 디자인 판단 자료다.
