# BOM 저장·완료 해제 성능 개선

**GOAL:** BOM 추가·수량 변경·삭제·완료·완료 해제의 기존 업무 결과를 보존하면서, 저장 후 쓰기 잠금과 중복 재조회를 제거하고 서버 성공 응답을 화면에 즉시 반영한다.

사용자 승인: 2026-10-28. 서버 성공 응답 전에는 화면 값을 변경하지 않는다.
직원 서버·DB에는 쓰기·부하 시험을 하지 않으며 커밋·푸시·배포는 포함하지 않는다.
현재 checkout을 유지하고, 검증용 소스·DB·서버는 별도로 격리한다.

## 구현 계약

- BOM 생성·수정, 완료·해제는 검증·감사 뒤 flush → 기존 응답 DTO 복사 → 기존 헬퍼로 commit 1회 → DTO 반환.
- 커밋 뒤 ORM refresh·만료 속성 접근을 제거하고 이벤트 문자열도 미리 복사한다. 삭제의 기존 커밋 경계는 유지한다.
- API·스키마·정렬·관리자 권한·감사·revision·주간 스냅샷·전수조사 가드는 유지한다.
- BOM 행은 서버 응답으로 기존 detail·전체 캐시에 반영한다. 미로딩 목록을 가짜 생성하지 않는다.
- 완료 응답은 기존 품목에 bom_completed_at·updated_at만 병합한다. 재고·예약·모델·has_bom을 대체하지 않는다.
- 서버 성공 뒤 완료 표시·busy를 즉시 해제한다. 동일 부모의 중복 요청을 막으며 다른 부모 선택은 허용한다.
- 삭제·완료 확인창은 성공 때만 닫는다. 후속 GET 실패는 저장 실패·롤백으로 바꾸지 않는다. 쓰기는 자동 재전송하지 않는다.

## 공용 갱신 계약

- QueryClient별 BOM·items 조정 모듈은 저장 수·세대·진행 요청·dirty 상태를 보관한다.
- 변경 전 GET과 저장 중 새로 시작한 GET을 취소한 뒤 확정 응답을 적용한다.
- 저장 중 갱신을 모아 마지막 저장 종료 후 활성 조회를 실행한다. 같은 cycle은 Promise를 공유한다.
- 조회 중 다른 revision은 후속 cycle로 반영한다. DB 복원의 낮은 revision도 갱신한다.
- realtime에서 items 취소를 조정 모듈로 이관하고 workStatus 취소·메타데이터 선조회·다른 모든 root는 유지한다.
- 작업예약 명령의 취소 기본 동작은 그대로 유지한다. 파생 BOM·부모 여부·생산 능력은 기존 정규 조회로 확인한다.
