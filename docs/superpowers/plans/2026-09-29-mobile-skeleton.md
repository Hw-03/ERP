# 모바일 전체 스켈레톤 적용

**GOAL:** 3016 격리 워크트리의 모바일 전체에 완성 화면 구조를 유지하는 스켈레톤을 적용하고, 최초 조회·재조회·실패·빈 결과를 정확히 구분한다.

## 승인된 기준

- 대상은 `mobile-ui/ERP`의 기존 미커밋 디자인을 포함한 현재 작업 트리다.
- 참고 커밋은 `80ae143d`, `54ada6c6`, `d8e2e440`이다. 마지막 커밋의 180ms 투명도 전환과 중복 페이드 제거를 따른다.
- 최종 헤더·필터·외곽·행 구조를 유지하고 데이터만 스켈레톤으로 교체한다.
- 같은 대상 재조회에서는 기존 내용을 유지하고, 새 날짜·주·품목·요청에서는 이전 대상 값을 표시하지 않는다.
- 성공한 빈 결과, 최초 실패, 갱신 실패를 구분한다. 인위적인 대기 시간을 추가하지 않는다.
- 부모는 공통 조회 컴포넌트·모션·셸·상세 공통 훅·알림을 맡는다. 화면별 작업은 재고·내역·상세, 입출고·불량, 출하·더보기 하위로 나눈다.
- 기존 KpiCard.loading/AsyncState.skeleton을 재사용하고 ReadLoading의 선택적 skeleton을 추가한다. picker와 상세의 선택적 로딩·오류·재시도 상태를 전달한다.
- 관련 Vitest 회귀 테스트, 타입·변경 파일 lint·diff 검사, 열린 인앱 브라우저의 모바일·태블릿·PC 확인을 수행한다.
- 동결된 주간보고 내부·모바일 탭바·PC 출하 카드·전역 CSS·백엔드·DB를 보존한다. 커밋·푸시·브랜치 변경은 하지 않는다.

## 실행 기록

**완료: 2026-09-29**

- 대시보드·내역은 기존 KPI·필터·표·98px 행을 유지한다. 필터의 강제 200ms 로딩을 제거했고, 조회 조건 변경 첫 렌더부터 이전 조건의 목록·집계를 숨긴다.
- 입출고·불량은 요청·승인·초안·인수인계·품목·공급업체·보관·통계·분해 영역의 실제 구조에 맞는 골격을 표시한다. 미조회 건수, 미확보 오류, 성공한 0을 구분한다.
- 출하·주간보고 wrapper·지도·체크리스트·일보에 최초 조회와 캐시 재조회 상태를 적용했다. 일보 작성자 placeholder 판정은 모바일에서만 보완했다.

- 추가 요청에 따라 **내역 스켈레톤은 6개**로 변경했다. 98px 행 크기는 유지하며 여섯 번째 행은 viewport 아래 경계에서 자연스럽게 잘린다.
