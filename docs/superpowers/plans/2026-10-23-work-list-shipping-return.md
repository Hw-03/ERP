# 출하 상세에서 작업 목록 복귀

**GOAL:** 전체 작업 목록에서 ‘출하에서 열기’로 이동했다가 브라우저 뒤로 가기를 하면, 이전 검색·필터·펼친 항목·스크롤 위치를 복원한다.

## 적용 내용 — 2026-10-23 구현

- 출하 이동 전에 현재 이력을 `section=cart`로 교체하고 Next.js 이력 필드를 보존한다. 작성 화면의 `step`, `draftId`, `stockRequestId`는 복귀 주소에서 제거한다.
- 이력에는 고유 키만 저장한다. 조회 범위·검색·필터·정렬·페이지·선택·탭 접힘·안쪽 및 바깥쪽 스크롤은 같은 로그인 내 메모리에서 이력별로 복원한다.
- 목록과 상세 렌더 이후 ResizeObserver로 위치를 복원한다. 재조회와 레이아웃 변화 중에도 보정하며, 사용자의 직접 스크롤 입력에는 즉시 자동 복원을 중단한다.
- 대상이 사라지거나 404이면 선택을 해제한다. 새 메뉴 진입에는 복귀 키를 전달하지 않으며, 직원·로그인·권한 변경과 인증 오류에는 기록을 폐기한다.
- 출하의 ‘계속 작성’은 원본 목록 이력을 덮는 replace 대신 원래 출하 이력으로 forward하여, 다음 Back도 목록으로 복귀하게 한다. 해당 복귀 기록이 없는 일반 이동은 기존 이탈 정책을 유지한다.
- 데스크톱에만 복원 동작을 추가한다. 기존 모바일 화면·220ms 전환·데이터 재조회 정책을 유지한다.

## 검증

- URL 누락과 이탈 취소의 실패 회귀를 먼저 확인한 뒤 수정했다.
- 이력 분리·반복 복원·Next 상태 보존·인증 경계·지연 상세·사용자 스크롤·짧아진 목록·안쪽 및 바깥쪽 스크롤을 검사한다.
- 실제 개발 브라우저에서 출하 상세 왕복 시 펼친 출하 항목과 스크롤 683px 복원, 앞으로 재진입, 미저장 입력 보호와 이탈 취소 후 재복귀를 확인했다. 테스트 입력은 저장하지 않고 지웠다.
- 관련 프론트 테스트 218건 통과: 8개 파일 216건을 검증한 뒤 추가한 목록 예외 테스트 2건과 영향받는 스크롤·목록 58건을 재검증했다. TypeScript·변경 파일 ESLint·diff 검사도 통과했다.
- 개발 서버에만 적용했다. DB 변경, 서버 재시작, 직원 서버 반영, 커밋·푸시는 수행하지 않았다.
