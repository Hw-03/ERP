# 튜브 원자재 입출고 구현 계획

**GOAL:** 튜브 직원이 전용 업체 목록과 튜브 원자재 품목을 사용해 승인 없이 튜브 재고의 입고·출고를 처리하고, 격리 불량품도 전용 업체로 반품할 수 있게 한다.

사용자 승인: 2026-10-08, 이 대화의 “계획대로 진행해줘”. 커밋·푸시·브랜치 변경은 별도 요청이 없으므로 수행하지 않는다.

## 확정한 동작

- PC·모바일 입출고 탭에 `튜브 원자재 입출고`를 추가한다. 튜브 소속 직원만 사용하며 기존 입출고 사용 제한을 유지한다.
- 기존 원자재 입출고 화면을 재사용한다. 입고·출고 → 업체 → 품목·수량 → 확인 순서다. 부서 선택 없이 튜브 재고로 고정한다.
- 삭제되지 않은 `process_type_code == TR` 품목만 직접 선택한다. BOM을 전개하지 않는다.
- 정상 재고의 반품은 새 메뉴 출고로 처리한다. 격리된 불량품은 기존 불량 화면에서 반품한다.
- 튜브 직원 모두 튜브 전용 업체를 추가·이름 수정·숨김·복구한다. 창고 업체와 과거 거래를 보존하며 튜브 업체는 빈 목록에서 시작한다.

## API 계약과 처리

- IO `work_type=tube_material`, `sub_type=tube_receive_supplier|tube_outbound_supplier`를 추가한다.
- 입고는 `none → production/튜브`, 출고는 `production/튜브 → none`으로 처리한다. 승인 없이 즉시 실행한다.
- 거래는 입고 `RECEIVE`, 출고 `MATERIAL_OUT`이다. 외부 입고를 생산 실적으로 기록하지 않는다.
- 활성 튜브 직원, 기존 입출고 제한, TR 품목, 직접 선택 구성, 튜브 재고 경로, 업체 scope를 미리보기·초안·제출·실행에서 검증한다.
- 출고는 예약분을 제외한 가용 정상 재고만 사용한다. 부족·위조 요청은 일부 반영 없이 거부한다. 중복 제출 방지는 기존 구조를 따른다.
- 공급업체 `scope=warehouse|tube`, 기본값 warehouse를 추가한다. 이름 중복 제약은 `(scope, normalized_name)`이다. 기존 ID·참조·이력은 그대로 유지한다.
- 업체 GET query와 POST body에 scope를 추가한다. PATCH 관리 권한은 실제 업체 scope로 판단한다. 기존 호출은 warehouse 기본값으로 호환한다.
- 공용 업체 선택 화면에 scope를 전달하고 목록 변경 때 이전 조회 응답을 무시한다. 숨김·잘못된 업체를 가진 초안은 재선택하도록 안내한다.
- 불량 반품은 실제 격리 원건의 부서가 튜브이고 현재 연결 품목 코드가 TR이면 tube 업체를 사용한다. 그 밖의 경우 및 원건 없는 레거시는 warehouse를 유지한다. 혼합 scope는 분리 반품 안내로 거부한다.
- 입출고 이력·작업 기록·일일 작업보고의 새 유형 라벨과 필터를 연결한다. 동결된 주간보고는 수정하지 않는다.
