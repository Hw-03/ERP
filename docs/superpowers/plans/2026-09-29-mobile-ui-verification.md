## 자동 검증

- 최종 통합: 모바일 디렉터리, CapacityDetailModal 모바일/PC, HistoryDetailPanels, DailyWorkReportScreen을 포함한 **27개 테스트 파일·262개 테스트 통과**.
- 별도 수행: 계정·알림·shell 관련 **14개 파일·100개 테스트**, PC/공용 ConfirmModal·Inventory·History 관련 **5개 파일·39개 테스트** 통과. 일부 shell 테스트는 최종 통합과 중복되므로 총합으로 집계하지 않는다.
- 화면군별 기존 입출고·승인·인수인계·불량, 일보·출하·체크리스트, 재고·내역 테스트도 분담 실행했다. 후속 변경은 직접 영향받는 테스트를 다시 실행했다.
- 최종 `npm run typecheck:app`, `npm run lint:strict`, `npm run build` 모두 종료 코드 0.
- BOM 관련 기존 테스트 9개도 별도 통과했다. 공통 데스크톱 트리는 깊이 0~8, 모바일 표시 옵션은 2단계에서 긴 이름·펼침/접힘을 확인했다. 모바일 9단계까지 실브라우저 검증한 결과는 아니다.
- `git diff --check` 통과. Desktop 컴포넌트, `backend/`, `globals.css`, `_weekly_sections/` diff 없음. MobileShell의 NavButton/nav/pill 내부는 그대로이며 본문과 nav 외곽 폭만 분리했다.
- 기존 styled-jsx가 jsdom 테스트에서 출력하는 non-boolean `jsx` 경고는 남아 있다. 테스트 실패나 빌드 오류는 없었다.
- 독립 리뷰에서 발견한 좁은 필터 toolbar 겹침·긴 무공백 이름·낮은 높이의 불량 카트 접근 문제는 수정 후 재검증했다.

## PC 비교

동일 복제 데이터·상태에서 1440×1000의 대시보드, 입출고, 불량, 내역, 일보, 생산 가능 현황을 기준 화면과 비교했다. 마지막 일보 변경도 재비교했다. 1024×844 대시보드에서도 비교했다.

표시된 주요 요소의 텍스트·좌표·폭·높이·글꼴·색·배경·padding·border·radius·display 비교가 일치했다. 캡처에서도 의도치 않은 차이를 발견하지 못했다. 이는 해당 상태의 기하/스타일 비교 결과이며 모든 PC 상태의 픽셀 완전 일치를 주장하는 것은 아니다. 비교 JSON과 PNG는 `screenshots/pc-*`에 보관했다.

## 모바일 비교와 검증 한계

- 주요 화면을 360·390·430·592·768·1023px에서 확인했다. 최종 내역 상세는 여섯 폭을 다시 측정했고, 일보 360px·주간보고 592px도 최종 재확인했다.
- 대시보드·입출고·불량·내역·더보기·일보·생산 현황 전후 캡처와 BOM·체크리스트·주간보고·출하·지도·알림·로그인 개선 캡처를 남겼다.
- 라이트/다크를 확인하고 복제 환경 테마를 라이트로 복원했다. 긴 품명·큰 수량은 실제 재고/내역 및 단위 테스트로 확인했다. 로딩·빈 결과·오류/재시도는 관련 테스트와 조회 화면으로 확인했다.
- 390×420의 일보/불량 입력 접근을 확인했다. 불량 메모는 font-size 16px이며 스크롤 가능한 본문 안에서 화면에 노출된다. 실제 iOS/Android 키보드는 사용하지 않았으므로 장치별 키보드 동작은 실기기 확인이 남는다.
- 복제 DB의 출하 목록은 비어 있어 구성품이 있는 출하 화면은 테스트 fixture로 검증했다. 실데이터에 샘플 출하를 섞지 않았다.
- 기존 지도 회전 정책과 공용 주간보고 표는 보존했다. 이들 기존 기능의 표시 방식 자체를 바꾸지 않았다.
- 실거래의 최종 승인·격리·취소를 전체 조합으로 제출하지 않았다. 해당 요청/검증 보존은 기존 기능 테스트와 변경 diff로 확인했다.
- 원본 작업 트리는 구현 중 다른 작업으로 진행되었으며 이 결과는 요청한 기준 커밋에 고정되어 있다. 최신 원본과 통합하는 작업은 수행하지 않았다.
