사용자 승인 계획의 실행 기록이다. main 반영·푸시, 직원 배포, 원본 DB 변경, 기존 동기화 예약 변경은 제외한다. 기존 사용자 검토판 `127.0.0.1:3035`는 그대로 유지한다.

- 새 후보는 `localhost:3036`, 백엔드 8036 및 별도 DB를 사용한다. 기존 3035 검토판과 구분한다.

## CP2 — DB 이력과 정보 보존

- 새 `20261015_0047` merge revision의 부모는 `20261014_0046`, `20261015_0046`이다. 기존 revision은 보존하고 새 merge는 업무 데이터를 변경하지 않으며 자동 배포 정책을 선언한다.
- 최신 head 기대값만 갱신한다. 역사적 버전·과거 검토 manifest는 바꾸지 않는다.
- 검증된 원형 직원 스냅샷 사본에서 0045, main 0046, 통합 0046 출발 경로를 각각 새 head까지 검사한다. 기존 행·재고·예약·역할, 신규 검색 테이블, 외래키·스키마를 대조한다.
- 서비스 정지 전 사전검사 함수를 복제본에만 실행한다. 실제 동기화 명령은 호출하지 않는다.

## CP3 — 실패와 화면 검증

- main CI `38673954647`의 HistoryFilterBar 단언, 잘못된 실사 cursor 응답, 불량 E2E 및 후속 시간초과를 기준선으로 분리한다.

## CP4 — 커밋과 CI

- 병합, DB 이력, 원인별 수정·검증 기록을 검토 가능한 커밋으로 나눈다. 실제 날짜·명시 stage·cached diff check·smart 계획 확인을 지킨다.
