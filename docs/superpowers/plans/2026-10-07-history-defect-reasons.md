# 제출 묶음과 불량 사유 관리

사용자 승인 계획을 이 워크트리에서 실행한다. 기준은 `34890d0fb1b214a58eee3a1adcc1a2524b1dcbc8`, detached HEAD다. 현재 main 변경은 가져오지 않는다. 커밋·푸시·원본 반영·배포는 별도 요청이 필요하다.

## 구현 계약

- 거래 로그·승인 요청의 `submission_id`는 표시만 담당한다. 한 제출 아래 기존 작업과 취소 단위를 유지한다. 제출 대표에는 전체 취소를 제공하지 않는다.
- 부분 취소 후 제출은 유지한다. 역거래는 독립 이력이다. 재작업의 부모·구성품 연결 복원은 기존 동작을 유지한다.
- 과거에는 배치 번호 또는 명시적 다건 요청 ID가 확인되는 내역만 묶는다. 시간·담당자·메모로 추측하지 않는다.
- 검색 일치 표시, 완결된 묶음 단위 페이지, 기존 날짜·부서·모델·통계·달력·일보 정책을 유지한다.
- 사유 마스터의 고유 번호로 격리·거래·승인·배치를 연결한다. 현재 이름으로 통계를 표시하고 당시 이름으로 개별 내역을 표시한다.
- 활성 직원은 검색·추가·이름 수정·사용 중지·복구할 수 있다. 변경을 감사 기록에 남긴다. 정규화 중복 차단, 신규 이름 1~32자, 기타 고정, 물리 삭제 없음.
- 제출 시 카테고리 필수, 기타 메모 필수. 임시저장 미선택 허용. 새 요청은 활성 사유만 선택, 기존 승인대기는 저장 당시 이름·ID로 실행한다.
- 기존 기본 사유 활성화, 과거 사용자 이름은 비활성 보존, 빈 사유는 미분류 유지. 긴 원문을 자르지 않는다.
- 서버 시작은 DB를 변경하지 않는다. 이관은 명시적 bootstrap으로 실행한다. 원본·직원 DB를 변경하지 않는다.
