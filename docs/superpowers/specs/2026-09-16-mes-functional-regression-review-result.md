| 6 | 관리자 설정의 업무 연쇄 | 변경 이후 작업만 새 기준을 사용하고 과거 요청·내역은 당시 스냅샷 유지 |
| 7 | 보류 조사 테스트 승격 | 코드·실측으로 기대값이 명확해진 항목만 병합 차단 회귀 테스트로 승격 |

각 단계는 서비스 단위 테스트 → API/DB 통합 테스트 → 핵심 브라우저 E2E 순서로 작성한다. 한 품목이라도 오류가 있으면 다음 단계나 제출로 넘어가지 않고, 모든 오류를 같은 화면에 표시하며, 재고·예약·내역은 전체 무변경이어야 한다.

## 5. 판정 데이터 보존 규칙

- JSON은 브라우저 `localStorage`에서 복구한 원본 판정이며 270개 ID를 모두 보존한다.
- 기대값 문장을 고쳐도 항목 ID는 바꾸지 않는다. 그래야 사용자 판정과 자동 테스트가 계속 연결된다.
- `기대값 맞음`은 당시 실제 동작을 승인했다는 뜻이 아니라, 제시한 기대 반응이 사용자 의도와 맞다는 뜻이다.
- 보류 항목은 테스트에서 삭제하지 않고 `조사/비차단`으로 유지한다. 기대값이 확정된 날부터 병합 차단 테스트로 승격한다.
