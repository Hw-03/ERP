# 관리자 내보내기 단일 카드 통합 설계

## 상태

- 사용자 승인: 2026-08-04
- 구현 상태: 완료 (2026-08-04)
- 대체 대상: `2026-08-03-admin-export-independent-cards-design.md`의 하단 독립 카드 배치

## 목적

관리자 내보내기 화면에서 실제 사용 빈도가 낮은 범용 데이터와 내부 원본 로그를 서로 다른 상위 카드로 계속 노출하지 않는다. 두 기능은 삭제하지 않고 하나의 `데이터 내보내기` 카드 안에서 모드로 전환해 필요할 때만 사용하도록 한다.

F704-02 연간 자재 입출고관리대장과 F705-02 연간 생산일지는 공식 서식이므로 현재 독립 카드와 다운로드 동작을 유지한다.

## 화면 구조

- 상단에는 현재와 같이 같은 크기의 공식 서식 카드 두 개를 둔다.
  - `F704-02 연간 자재 입출고관리대장`
  - `F705-02 연간 생산일지`
- 하단에는 전체 가용 너비를 사용하는 `데이터 내보내기` 카드 하나만 둔다.
- 화면의 최상위 작업 카드는 F704-02, F705-02, 데이터 내보내기 총 3개다.
- `내부 원본 로그 (월별)`은 별도 카드나 별도 제목 영역으로 표시하지 않는다.
- 기존 표면, 색상 토큰, 18px 제목, 44px 조작 높이를 유지하며 새로운 강조색이나 중첩 카드를 추가하지 않는다.

## 데이터 내보내기 카드

### 모드 전환

- 카드 상단 조작부에 `일반 데이터`와 `내부 원본 로그` 두 모드를 둔다.
- 두 모드는 기존 `FilterChip`을 사용하는 하나의 선택 그룹으로 표시한다.
- 최초 진입 기본값은 `일반 데이터`다.
- 모드 전환은 같은 카드의 본문만 교체하며 별도 페이지, 모달, 접기 영역을 만들지 않는다.
- 일반 데이터에서 고른 범위·형식·기간·비활성 데이터 포함 상태는 원본 로그 모드에 다녀와도 유지한다.

### 일반 데이터 모드

- 현재의 `전체`, `품목`, `입출고`, `직원`, `BOM` 범위를 유지한다.
- 품목·입출고는 CSV와 Excel을 제공하고 직원·BOM은 CSV만 제공한다.
- `전체`는 현재처럼 품목·입출고·직원·BOM CSV 4개만 내려받는다.
- 내부 원본 로그는 월별 파일이며 일반 데이터와 생성 방식이 다르므로 `전체`에 포함하지 않는다.
- 입출고 기간, 비활성 직원 포함 등 선택 결과에 영향을 주는 조건부 옵션과 카드 내부 성공·실패 피드백을 유지한다.

### 내부 원본 로그 모드

- 사용자가 이 모드를 처음 선택할 때 월별 원본 로그 목록을 조회한다. 일반 데이터 모드로만 사용하는 동안에는 목록 API를 호출하지 않는다.
- 월별 파일 표는 제거하고 `대상 월` 선택과 `파일 형식` 선택만 표시한다.
- 대상 월은 기존 `AppSelect`, 파일 형식은 기존 `FilterChip`으로 표시한다.
- 대상 월은 사용 가능한 월을 최신순으로 제공하며 최신 월을 기본 선택한다.
- 파일 형식은 `CSV`와 `Excel`을 제공한다.
- 다운로드 버튼은 선택한 월과 형식을 반영한 단일 실행 버튼으로 표시한다.
- 백필과 수동 새로고침은 사용자 화면에 추가하지 않는다.
- 원본 로그가 없으면 다운로드 버튼 대신 `아직 누적된 파일이 없습니다` 상태를 표시한다.
- 목록 조회 실패와 다운로드 실패는 같은 카드 안의 경고 영역에 표시한다.

## 컴포넌트 책임

- `AdminExportSection`이 공식 서식 카드, 통합 데이터 카드, 활성 모드와 일반 데이터 내보내기 상태를 소유한다.
- 원본 로그 모드의 목록 조회, 월·형식 선택, 파일 다운로드는 `AdminAuditCsvControls` 컴포넌트로 격리한다.
- 기존 `AdminAuditCsvSection.tsx`는 `AdminAuditCsvControls.tsx`로 이름을 바꾸고, 독립 카드 표면과 월별 표를 제거한다. 이전 파일명과 심볼의 코드·테스트 참조는 남기지 않는다.
- 새 공용 추상화는 만들지 않고 기존 버튼, 선택 컨트롤, 필터 칩과 색상 토큰을 재사용한다.

## 데이터 흐름

1. 사용자가 내보내기 화면에 진입하면 공식 서식 카드와 일반 데이터 모드만 렌더링한다.
2. 일반 데이터 다운로드는 현재 범위·형식별 API와 클라이언트 CSV 생성을 그대로 사용한다.
3. 사용자가 `내부 원본 로그`를 선택하면 그때 월별 파일 목록을 조회한다.
4. 목록 응답에서 가장 최신 월을 기본값으로 정한다.
5. 사용자가 월과 형식을 고른 뒤 다운로드하면 기존 관리자 원본 로그 다운로드 API를 호출한다.
6. 모드를 전환해도 서로의 선택 상태를 덮어쓰지 않는다.

## 백엔드와 데이터 보존

- DB 스키마와 저장 데이터는 변경하지 않는다.
- `TransactionLog`를 원본으로 사용하는 자동 월별 CSV 미러 생성을 유지한다.
- 기존 원본 로그 목록·CSV·XLSX·백필 API를 유지한다. 백필 API는 운영용으로만 남긴다.
- 기존 품목·입출고 CSV/Excel 관련 API도 유지한다.
- 이번 변경은 관리자 화면의 정보 구조와 프런트엔드 호출 시점만 바꾼다.

## 접근성과 오류 처리

- 두 모드는 이름이 있는 단일 선택 그룹으로 제공하고 현재 선택 상태를 보조기기가 인식할 수 있게 한다.
- 대상 월과 파일 형식에는 명시적인 라벨을 제공한다.
- 로딩 중에는 중복 다운로드를 막고 실행 버튼에 진행 상태를 표시한다.
- 성공 메시지는 `status`, 실패 메시지는 `alert`로 같은 카드 안에 표시한다.
- 모드 전환 자체는 네트워크 실패와 무관하게 항상 가능해야 한다.

## 검증 기준

- 내보내기 화면의 최상위 작업 카드가 F704-02, F705-02, 데이터 내보내기 3개뿐이다.
- `내부 원본 로그 (월별)` 독립 카드와 월별 파일 표가 보이지 않는다.
- 최초 화면에서 일반 데이터 조작부가 보이고 원본 로그 목록 API는 호출되지 않는다.
- 내부 원본 로그 모드를 선택하면 최신 월이 기본 선택되고 다른 월 및 CSV·Excel 형식을 선택할 수 있다.
- 선택한 월과 형식으로 기존 다운로드 API가 정확히 한 번 호출된다.
- 빈 목록, 목록 오류, 다운로드 오류가 통합 카드 안에서 처리된다.
- 원본 로그 모드에 다녀와도 일반 데이터의 기존 선택값이 유지된다.
- F704-02·F705-02 다운로드 동작과 오류 처리가 회귀하지 않는다.
- 좁은 화면에서도 모드·월·형식·다운로드 조작이 겹치거나 잘리지 않는다.
- 관련 Vitest와 변경 범위에 맞는 프런트엔드 검증이 통과한다.

## 범위 제외

- 백엔드 원본 로그 생성·복구 정책 변경
- 원본 로그를 일반 데이터의 `전체` 다운로드에 포함하는 기능
- 새로운 파일 형식이나 데이터 범위 추가
- 공식 서식 카드의 API, 필드, 배치 변경

## 역사 문서 처리

- 2026-08-04 이전의 날짜형 계획과 핸드오프에 남은 `AdminAuditCsvSection` 및 독립 카드 설명은 당시 구현을 기록하는 역사 문맥이므로 유지한다.
- 현재 기준 문서인 2026-08-03 독립 카드 설계·계획과 관리자 내보내기 후속 핸드오프에는 이 설계가 대체한다는 상태를 명시한다.
