# DEXCOWIN MES 축소 범위 종료 기록

현재 상태: 축소 범위의 코드 HEAD `6c7c348d` CI 성공. 종료 문서 커밋 후 최종 HEAD CI는 별도로 확인한다. main 미반영·직원 환경 미적용.

사용자의 2026-10-10 지시에 따라 성능 목표를 이번 변경의 일반 품목·상세 조회 회귀 확인으로 줄였다. 추가 최적화와 전체 로컬 검사 반복을 멈췄으며, 유효한 기존 검증을 해당 범위에만 재사용했다. 무거운 조회의 모든 부하 절대 상한 달성 및 현재 기대값 전체 재실행은 종료 범위 밖이다.

## 작업 브랜치와 검증

- 브랜치: `codex/mes-expectation-closure`
- 기준 main: `2d79cd2848900fb66f99443af411fcec347877cd`
- 코드 HEAD: `6c7c348dab2022cc6e0d4ad5c43f9a64ce716253`
- [코드 HEAD CI](https://github.com/Hw-03/ERP/actions/runs/38018425265): 실제 8개 작업 모두 SUCCESS. 프론트 3,799 PASS, PostgreSQL 필수 88 PASS·0 SKIP/FAIL/ERROR, OpenAPI 기준 일치 및 일반 E2E 289 PASS·1 flaky를 확인했다. 일반 E2E의 출하 초안 화면 검사 한 건은 첫 시도 실패 후 기존 재시도에서 통과했으며 재시도 없는 통과로 세지 않는다. 이전 HEAD `6d8ca629`의 OpenAPI 및 일반 E2E FAIL 원문도 보존한다.
- 번들: 로컬 Windows와 실제 Linux CI에서 각각 3,145,717바이트. 승인 한도 3,145,728바이트를 유지했다. 남은 여유는 11바이트이며 추가 최적화를 진행하지 않았다.
- CI 보정: 테스트의 날짜·격리 자료 의존 및 실제 리스너 확인을 국소 보완했다. PostgreSQL 전용 URL에는 설치된 `psycopg2`를 명시했다. 검사 대상·실제 PostgreSQL 실행·건너뜀 금지·커버리지·번들 기준은 유지한다.
- 의존성 보정: 앞선 CI에 설치된 SQLAlchemy 2.1.4의 기본 드라이버 변경으로 백업/복구 두 사례가 실패했다. 로컬 검증 runtime은 2.0.52이며 `>=2.0.31,<2.1` 한 줄로 기존 2.0 계열을 유지한다. 복구 구현과 DB는 변경하지 않았다.
- API 기준 보정: CI Pydantic 2.14.0이 삭제한 수량 문자열 패턴을 기존 기준에서 없애지 않고 `>=2.9.0,<2.14`로 실제 검증한 2.13.4 계열을 유지한다. DB 연결을 금지한 국소 검사에서 기존 OpenAPI 전체 문자열이 정확히 일치했다.
- E2E 보정: 새 격리 건의 고유 메모로 정확한 행을 찾고, 단말 등록의 성공 안내를 로딩 안내와 구분했다. 기존 기록 보존·새 기록 소멸·세션 보존 단언을 유지하며 실제 실패 재현 후 관련 3개 검사가 통과했다. 현재 전체 기대값은 NOT_RUN으로 유지한다.

## 실제 공동복구와 후속 프론트

C18에서 0038→0044→0038 실제 백엔드·production 프론트 기동/조회/종료와 이전 DB·코드·프론트·Node 복원을 확인했다. 설치 실패·복구 실패 주입 후 재개 및 정상 첫 복구는 native/outer 0이다. 실제 강제 종료 본체도 native 0이며, 원 수집기 FAIL125는 보존하고 null/빈 문자열 비교 오류의 별도 읽기 재검증 근거를 연결했다. 이전 실패를 성공으로 덮어쓰지 않았다. DB 동일성은 원형 SQLite snapshot digest·스키마/자료 비교 계약이다.

이후 CI의 번들 초과를 없애기 위해 두 데스크톱 화면의 동일 BOM 버튼만 공유했다. 클릭·비활성 조건·순서·스타일과 모바일 분기를 유지했고 관련 78개 검사, lint·타입·새 빌드 및 실제 격리 페이지 기동/종료를 확인했다. **새 빌드에 C18 P10/Q10의 정확한 산출물 복구 성공을 승격하지 않는다.** 변경되지 않은 백엔드·DB·설치/복구 구현의 근거는 유지하며 새 페이지 기동은 API·버튼 동작·새 빌드 공동복구 PASS를 뜻하지 않는다. [정제 복구 근거](2026-10-10-mes-recovery-scoped-results.json)에 양쪽 범위를 구분했다.
