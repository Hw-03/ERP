# 모바일 조립 체크리스트 편집·이동 설계

## 목표

모바일 조립 체크리스트에서 제품 선택 화면의 정보 계층을 단순화하고, 관리 화면에서 체크 항목 문구를 수정하거나 다른 박스로 이동해 영구 저장할 수 있게 한다.

## 범위

- 제품 선택 헤더의 `제품을 선택하세요.` 문구를 제거한다.
- 헤더의 `조립 체크리스트`를 기존 `text-xl`에서 모바일 표시 제목 단계인 `TYPO.display`로 키우고, 좌우 버튼·아이콘과 수직 중앙을 맞춘다.
- 모든 제품 카드에서 `조립 체크리스트` 보조문구를 제거하고 모델명을 `text-xl font-black`으로 키운다.
- 관리 상세 화면에서 항목 문구를 인라인으로 수정한다.
- 관리 상세 화면에서 드래그한 항목을 같은 박스 안에서 재정렬하거나 다른 박스의 원하는 위치로 이동한다.
- 박스 이름 편집, 박스 삭제, 체크리스트 실행 화면의 완료 표시 방식은 변경하지 않는다.

## 검토한 접근

1. **인라인 수정 + 박스 간 직접 드래그 + 원자적 이동 API (선택)**
   - 목록 맥락을 유지한 채 가장 적은 조작으로 수정·이동할 수 있다.
   - 서버가 출발·도착 박스 순서를 한 트랜잭션으로 저장해 중간 실패 상태를 만들지 않는다.
2. **수정 팝업 + 대상 박스 선택 드롭다운**
   - 구현은 단순하지만 반복 작업마다 팝업과 선택 단계를 거쳐야 하고 원하는 삽입 위치를 지정하기 어렵다.
3. **삭제 후 다른 박스에 재생성**
   - 기존 API를 재사용할 수 있지만 항목 ID가 바뀌고 두 요청 사이 실패 시 데이터가 유실될 수 있어 제외한다.

## 화면 동작

### 제품 선택 화면

- 상단 카드는 기존 블루 아이콘, 설정 버튼, 뒤로가기 버튼과 카드 스타일을 유지한다.
- 제목은 한 줄만 표시하고 `TYPO.display` 크기로 키운다. 제목 영역은 `min-w-0 flex-1`을 유지해 좁은 화면에서도 버튼을 밀어내지 않는다.
- 제품 카드는 기존 48px 아이콘과 터치 영역을 유지하고, 모델명 한 줄만 수직 중앙에 배치한다.

### 항목 문구 수정

- 관리 목록에서 항목 문구를 누르면 해당 행만 편집 상태가 된다.
- 문구 영역은 여러 줄을 보존할 수 있는 `textarea`로 바뀌고 `저장`, `취소` 버튼을 표시한다.
- 앞뒤 공백을 제거한 결과가 비어 있으면 저장할 수 없다.
- 저장 성공 시 서버가 반환한 최신 체크리스트로 화면을 갱신한다. 실패하면 기존 문구를 유지하고 현재 관리 화면에 오류를 표시한다.
- 드래그 핸들과 삭제 버튼은 편집 진입과 분리해 오조작을 막는다.

### 박스 간 이동

- 드래그 핸들을 잡아 같은 박스의 항목 위에 놓으면 기존처럼 그 위치로 재정렬한다.
- 다른 박스의 항목 위에 놓으면 그 항목 위치에 삽입한다.
- 다른 박스의 빈 영역 또는 빈 박스에 놓으면 해당 박스의 맨 아래에 삽입한다.
- 드래그 중인 행과 대상 행·박스는 기존 블루 강조 토큰으로 표시한다.
- 서버 저장이 실패하면 서버가 확정한 기존 목록을 유지하고 오류 문구를 표시한다.

## API와 데이터 일관성

- `PUT /api/assembly-checklists/items/{item_id}`에 `{ "content": string }`을 보내 문구를 수정한다.
- `PUT /api/assembly-checklists/items/{item_id}/move`에 `{ "target_section_id": UUID, "target_index": number }`를 보내 항목을 이동한다.
- `target_index`는 이동 항목을 제외한 대상 박스 목록의 0부터 시작하는 삽입 위치다.
- 이동 API는 같은 체크리스트 안의 박스만 허용한다.
- 서버는 항목 소속 변경과 출발·도착 박스의 `sort_order` 재번호화를 한 번의 커밋으로 처리한다.
- 기존 동일 박스 재정렬 API는 호환성을 위해 유지한다.
- 기존 컬럼 `section_id`, `content`, `sort_order`를 그대로 사용하므로 DB 마이그레이션은 없다.

## 오류와 접근성

- 없는 항목·박스는 404, 빈 문구·범위를 벗어난 위치·다른 체크리스트로의 이동은 422로 처리한다.
- 아이콘 전용 버튼은 구체적인 `aria-label`을 유지한다.
- 모든 조작 버튼은 최소 44px 터치 영역을 확보한다.
- 기존 `LEGACY_COLORS`와 `TYPO`만 사용하며 새 인라인 색상 값은 추가하지 않는다.

## 검증

- 백엔드: 문구 수정·공백 거부·없는 항목·박스 간 중간 위치 이동·빈 박스로 이동·양쪽 연속 순서·다른 체크리스트 거부를 API 테스트로 검증한다.
- 프런트엔드: 제거된 문구, 확대된 제목·모델명, 인라인 저장·취소, 같은 박스 재정렬 유지, 다른 박스 이동 요청을 컴포넌트 테스트로 검증한다.
- 관련 백엔드·프런트엔드 테스트와 변경 범위 검증 게이트를 실행한다.
