## 화면 계약

- 품목명·코드·출처와 수량 합계를 품목 카드 하나에 표시한다. 사유별 수량·카테고리·메모·관리 분류는 별도 입력 묶음으로 유지한다.
- `다른 사유 추가`는 PC에서 마지막 사유의 카테고리 오른쪽·삭제 왼쪽에, 모바일에서는 카드 아래에 표시한다. PC 카테고리와 메모의 오른쪽 끝을 맞추며 추가 버튼은 12px 글자와 작은 좌우 패딩, 44px 높이를 사용한다. 좁은 PC 입력 영역에서는 줄바꿈한다. 수량 1, 빈 사유·메모, 기본 불량 격리 분류의 새 줄을 같은 품목 마지막 줄 뒤에 삽입한다. 새 수량 입력에 포커스를 주고 값을 선택한다.
- 삭제는 해당 사유만 제거하며 마지막 사유 삭제 시 품목 선택도 해제한다. 다른 사유의 입력은 그대로 보존하고 인접 수량으로 포커스를 이동한다. 모바일 장바구니의 마지막 사유 삭제 시 기존 뒤로가기 경로로 품목 선택 단계에 자동 복귀하고 삭제한 품목의 선택 버튼으로 포커스를 이동한다.
- 담긴 품목 버튼은 사유 건수를 표시하고 입력 카드로 이동한다. 모바일에서는 수량·사유 입력 단계로 이동한다.
- 품목 수와 사유 건수를 구분한다. 확인창은 품목별 합계와 사유별 수량·카테고리·메모·관리 분류를 표시한다.
- 격리 등록의 사유 복사 버튼과 눈에 보이는 사유 번호 제목을 제거한다. 접근성 라벨은 사유 순서를 유지한다. 즉시 폐기·재작업의 기존 입력은 유지한다.
- PC는 수량·카테고리·삭제를 첫 줄에, 메모·관리 분류를 둘째 줄에 배치한다. 첫 줄 조작은 높이 44px·모서리 10px를 통일하고 둘째 줄 메모·관리 분류 버튼은 높이 58px를 맞춘다. 모바일 수량 조절기는 감소·숫자·증가를 가로로 배치해 높이 44px로 표시하며, 관리 분류·삭제와 아래쪽 기준선을 맞춘다. 화면 너비 400px 이하에서는 관리 분류를 다음 줄로 보내고, 카테고리·메모는 전체 너비로 표시한다. 모바일 입력은 컨테이너 쿼리와 중첩 flex 대신 내용 높이를 유지하는 블록 배치를 사용하며 재고·필수 입력 오류가 있어도 수정·삭제 컨트롤을 표시한다. 모바일 가능 재고·실행 후 정보는 코드·출처 줄의 오른쪽에 표시하며 공간이 부족하면 오른쪽 정렬로 줄바꿈한다.
- 품목 카드의 코드·출처 부서를 하나의 보조 정보 줄로 표시한다. 메모는 펼쳐진 두 줄 입력을 유지한다.
- 공용 사유 선택기의 숨김은 확인창에서 승인한 뒤 저장한다. 취소·Escape는 숨김 버튼으로, 성공은 검색 입력으로 포커스를 돌린다. 실패 시 확인창·선택·메모를 보존한다.
- PC 격리 최종 확인창은 최대 너비 960px로 표시하고 수량·카테고리·관리 분류·메모를 사유별 표로 비교한다. 품목명·코드·출처·합계는 품목당 한 번 표시하며, 화면 높이에 맞춘 내부 스크롤과 고정 제목·확인 버튼을 사용한다. 빈 메모는 `—`로 표시하고 접근성 설명은 유지한다.
- 격리 제출의 공통 서버 오류는 장바구니에 한 번 표시하고 입력 변경·재시도 시 지운다. 필수 입력·재고 검증은 유지한다.
- PC 입력의 미선택 안내는 선택창 안의 `사유 카테고리를 선택하세요.` 문구로 표시한다(2026-10-15 후속 변경). 카테고리 미선택의 제출 차단과 기타 메모 필수 검증은 유지한다. PC 목록의 `추가`·`담김`은 같은 너비와 기존 추가 버튼 높이 26px로 표시하며 사유 건수의 자릿수에 맞춰 너비를 함께 조정한다.
- 기존 테마 토큰·화면 분기·패널 스크롤과 PC 품목 선택 표의 행 높이를 유지한다. 장바구니의 신규 추가·삭제 조작과 모바일 터치 조작은 44px 이상 영역을 확보한다.

## 입력과 저장 계약

- 저장 줄 배열과 순서를 유지하고 표시용 그룹만 계산한다. 줄 키는 UUID이며 PC·모바일이 그룹 계산·합계 검증을 공유한다.
- 같은 품목·출처·부서의 합계가 예약을 제외한 가용 재고를 초과하면 입력 화면에서 제출을 막는다. 수량이 유효하지 않으면 합계 숫자 대신 확인 필요 상태를 표시한다.
- 카테고리 필수, 기타 카테고리의 메모 필수 규칙을 유지한다. 제출 중 편집을 잠그고 기존 일괄 API의 줄 수 상한을 적용한다.
- 기존 일괄 격리 API에서 같은 품목의 여러 줄을 허용한다. 사유별 원건·거래 기록을 만들고 공통 제출 ID로 연결한다. 순차 재고 차감과 전체 트랜잭션을 유지해 한 줄 실패 시 전체를 원복한다.
- 입력을 바꾸지 않은 재시도는 요청 ID와 줄 순서를 유지한다. 추가·수정·삭제는 일괄 요청 ID를 갱신하며, 기존 공통 제출 ID 생명주기는 유지한다.
- API 형식과 DB 스키마를 변경하지 않는다.

## 검증 항목

- 같은 품목의 3/A + 4/B + 3/C 일괄 제출, 사유·관리 분류·공통 제출 보존.
- 중간 삭제와 추가 후 나머지 입력 및 포커스 보존, 제출 잠금과 상한, 격리 복사·번호 제목 제거.
- 창고·부서 가용량과 예약을 고려한 합계 초과 차단, 서버 실패 시 재고·원건·원장 전체 원복.
- 동일 요청 재시도, 변경된 수량·사유·순서 충돌, 실패 후 보충 재시도.
- PC·모바일·좁은 모바일의 긴 품목명, 밝은·어두운 테마와 가로 넘침, 확인창 및 실제 저장.
- 기존 단일 품목·다른 품목 일괄 격리·즉시 폐기·재작업 회귀. 저장을 포함한 브라우저 검증은 전용 테스트 DB에서 수행한다.
- 공용 사유 숨김의 확인 전 요청 없음·취소·Escape·포커스 복원·저장 중 잠금·실패 후 재시도.
- PC 1915×884에서 두 사유와 추가 버튼이 패널 내부에 표시됨, 1280px PC·393px/320px 모바일의 배치·컨트롤 크기 유지.
