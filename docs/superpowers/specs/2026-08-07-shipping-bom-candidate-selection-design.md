# 출하 BOM 후보 선택 설계

## 목적

출하 요청에서 BOM을 수정한 사용자가 이미 등록된 동일 구성의 PA/PF를 중복 생성하지 않도록 돕는다. 단, 동일 BOM이라는 이유만으로 최초에 선택한 국가·판매처 PF를 다른 품목으로 자동 전환하지 않는다.

## 확정된 사용자 규칙

1. 1단계에서 고른 기준 PF는 국가·판매처를 포함한 출하 의도다.
2. BOM을 논리적으로 수정하지 않았다면 기준 PF를 최종 출하품으로 그대로 사용한다.
3. 기준 PF와 달라진 BOM이 기존 PF와 완전히 일치할 때, 시스템은 기존 PF를 모두 **후보**로 제시한다.
4. 후보 중 하나를 명시적으로 선택할 때만 해당 PF와 그 PF에 연결된 PA를 재사용한다.
5. 후보를 선택하지 않고 신규 생성을 선택하면, 처음 선택한 국가·판매처 맥락으로 새 PA/PF를 생성한다. 이때 PA/PF 이름은 기존 이름과 달라야 한다.
6. 동일 BOM 후보가 여러 개여도 서버는 임의의 첫 후보를 선택하지 않는다.

## 화면 흐름

### 기준 BOM과 같은 경우

3단계는 선택한 기준 PF/PA를 표시한다. 다른 동일 BOM 후보가 있어도 후보 선택을 요구하지 않으며, 5단계 출하 품목도 기준 PF를 표시한다.

### 기준 BOM과 다른 경우

3단계는 다음 두 영역을 표시한다.

- `동일 BOM 기존 품목 후보`: 완전히 일치하는 PF 후보 목록. 각 행은 PF 코드·품목명과 해당 PF에 직접 연결된 PA 코드·품목명을 함께 표시한다.
- `처리 방식`: `기존 품목 재사용`(후보 1개 선택 필요) 또는 `선택한 국가·판매처로 신규 생성`.

기본 선택은 신규 생성이다. 후보 행을 선택하면 재사용 처리로 전환한다. 신규 생성을 선택한 상태에서는 후보가 표시되더라도 최종 품목을 바꾸지 않는다.

후보가 없으면 신규 생성 처리와 PA/PF 이름 입력만 표시한다. 후보가 여러 개면 모두 표시하고, 행 선택 전에는 재사용으로 진행할 수 없다.

## 서버 계약과 영속 상태

현재 BOM 매칭 응답의 단일 `matched_pa_item_id`/`matched_pf_item_id`는 후보 배열로 대체한다. 후보는 다음 정보를 포함한다.

- `pf_item_id`, `pf_item_name`, `pf_mes_code`
- `pa_item_id`, `pa_item_name`, `pa_mes_code`

응답은 별도로 현재 기준 PF가 요청 BOM과 정확히 일치하는지 제공한다. 이 값이 참이면 UI는 기준 PF 유지 상태를 사용한다.

출하 요청에는 사용자가 확정한 최종화 방식을 보존한다.

- `KEEP_BASE`: 요청 BOM이 기준 PF와 같을 때 기준 PF를 사용
- `REUSE_CANDIDATE`: 선택한 후보 PF ID를 사용
- `CREATE_NEW`: 동일 후보가 있어도 새 PA/PF를 생성

후보 PF ID는 `REUSE_CANDIDATE`에서만 저장한다. 저장/준비 중 전환 시 서버는 이 PF가 요청 BOM과 여전히 일치하고 삭제되지 않았는지 다시 검증한다. PA는 후보 PF의 연결 PA를 사용하므로 별도 선택하거나 자동 치환하지 않는다.

`CREATE_NEW`에서는 기존 시그니처 검색 결과를 재사용하지 않는다. 이름 검증과 새 품목 생성은 현재 규칙을 유지한다.

## 매칭 알고리즘

1. 요청 PA 구성과 PF 구성으로 최종 BOM 시그니처를 계산한다.
2. 기준 PF 자체가 해당 시그니처와 일치하는지 먼저 판정한다.
3. 일치하지 않으면 활성 PF 전체에서 정확히 일치하는 PF를 모두 찾는다.
4. 각 PF 후보의 직접 PA 구성품을 함께 반환한다.
5. 후보 정렬은 코드와 품목명 기준으로 안정적으로 수행한다. 생성일이나 DB 반환 순서로 하나를 암묵 선택하지 않는다.

## 오류 처리

- 후보 재사용을 선택했으나 PF를 고르지 않으면 다음 단계 및 저장을 막고 선택을 안내한다.
- 저장 또는 준비 중 전환 때 후보 BOM이 달라졌거나 삭제되었으면 후보를 다시 선택하도록 안내한다.
- `KEEP_BASE`가 되었지만 기준 PF와 요청 BOM이 더 이상 같지 않으면 처리 방식을 다시 선택하도록 안내한다.
- 신규 생성 상태에서 PA/PF 이름이 없거나 기준 품목명과 같으면 현재의 이름 검증을 적용한다.

## 검증

1. 동일 BOM의 PF가 여러 개일 때, 모두 후보로 표시되고 자동 선택되지 않는다.
2. Vector 기준 PF와 Global PF가 동일 BOM이어도, 수정하지 않은 Vector 요청은 Vector를 최종 출하품으로 유지한다.
3. BOM 수정 후 Global 후보를 선택하면 Global PF와 연결 PA를 재사용한다.
4. BOM 수정 후 신규 생성을 선택하면 후보가 있어도 새 PA/PF를 생성한다.
5. 저장 뒤 요청을 다시 열어도 선택한 처리 방식과 후보가 유지된다.
6. 준비 중 전환 직전에 후보의 BOM이 바뀌었을 때 재검증이 실패하고 자동 대체하지 않는다.
