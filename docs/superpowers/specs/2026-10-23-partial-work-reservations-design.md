# 부족 자재가 있는 작업의 부분 예약

사용자가 승인한 동작: 자재가 부족해도 작업을 저장하고, 현재 확보할 수 있는 수량만 예약한다. 부족한 수량을 표시하고 전체 자재가 확보되기 전에는 제출할 수 없다.

- 저장은 품목·출발 위치별 필요 수량과 기존 본인 예약을 계산하고, 다른 예약을 제외한 가용량까지만 확보한다. 실물 재고는 변경하지 않는다.
- 기존 `reservation_status`와 DB 구조를 유지한다. 필요 자재가 있으면 `reserved`, 필요 자재가 없으면 `not_required`를 사용한다. 부분 확보 또는 전량 부족은 `reservation_issue.code=stock_shortage`와 위치별 부족 수량으로 구분한다.
- `effective_plan`은 전체 작업의 필요량을 유지하고 `IoDraftReservation`에는 실제 확보량만 저장한다. 0 수량 원장은 만들지 않는다.
- 작성기에서 본인 예약을 재사용할 때는 실제 확보분만 가산한다. 부족한 필요량을 확보한 것으로 계산하면 안 된다.
- 부족 자재와 수량은 작성기와 작업 목록의 펼친 상세에 표시한다. 작업 목록의 요약 행은 기존 부족 품목 수 표시만 사용하고, 별도의 부분 예약 배지와 긴 부족 안내는 표시하지 않는다. 작성기의 일반 예약 안내 박스는 모든 단계에서 숨기며 실사·반려·최신 작업 충돌·원작업 복귀 안내는 유지한다.
- 추가 입고 후 사용자가 다시 저장하면 부족분을 추가 확보한다. 저장하지 않은 신규 가용 재고는 확보된 예약으로 간주하지 않는다.
- 기존 작업 제출은 전체 필요량과 실제 예약 원장을 확인한 뒤 실행한다. 부족하면 버전·예약·재고를 바꾸기 전에 차단한다. 신규 직접 제출도 부족 시 실패하고 임시 작업을 남기지 않는다.
- 취소는 실제 확보된 예약만 해제한다. 실사 중 예약 해제·재개, 승인 예약 인계, 동시성 잠금과 버전 검사는 유지한다.

검증: 저장·재저장·조회·제출·취소의 API 회귀 테스트, 다른 작업의 예약 보호, 데스크톱·모바일 복원 및 저장/제출 제어 테스트, 해당 브라우저 흐름.
