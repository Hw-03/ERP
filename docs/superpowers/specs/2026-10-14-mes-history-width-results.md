# DEXCOWIN MES 입출고 내역 품목명 폭 수정

## 변경 동작

기준은 작업 브랜치 `codex/mes-expectation-closure`의 `9bf71b9b`다. 1440px에서 펼침 고정 사이드바와 상세 패널을 함께 열면 내역 표의 대상 열이 0px가 되어 대표·하위 품목명이 사라졌다. 고정된 나머지 열의 합계가 796px이고 대상 열만 남은 폭을 사용한 것이 원인이다.

`HistoryTable.tsx`의 표 표면 최소 폭을 1000px로 지정했다. 대상 열에 204px를 남기며, 공간이 부족할 때 기존 목록 스크롤 영역 안에서 가로로 이동해 오른쪽 수량·담당자 열을 확인한다. 상세를 닫거나 창을 넓히면 사용 가능한 폭에 맞춰 표시한다. 로딩 표에도 같은 최소 폭을 적용했다.

표의 데이터·재고 계산·API·DB·상세 패널 폭·모바일 화면은 변경하지 않았다. 긴 품목명의 기존 말줄임과 툴팁은 유지한다. 모든 열이 좁은 화면에 동시에 들어온다는 의미는 아니다.

## 과거 완료와 현재 국소 검증 구분

제품 파일이 바뀌면 기존 `reviewed-reuse`는 현재 전체 PASS를 허용하지 않는다. 사용자의 추가 승인에 따라 **`BASELINE_PASS`**를 도입했다. 이는 기준 커밋에서 검증한 조건의 완료를 보존하며, 현재 코드의 전체 실행 완료를 뜻하지 않는다. 현재 전체 PASS 집계에서는 제외하고 `baselineCases`로 분리한다. `--require-complete`는 이 상태를 현재 전체 완료로 인정하지 않는다.

기존 전체 완료 1,058조건은 새 NOT_RUN으로 되돌리지 않는다. 원래 실행·재사용 기록·선택자·조건·원문은 그대로 보존하고, 기준 완료 wrapper에서 다시 검증한다. 이번 화면 3건의 최종 원문·현재 프론트 입력 해시·변경된 모든 입력의 이전 소스·도구 호환성 근거를 별도로 연결한다. 기존 6건 통과 중 변경하지 않은 업무 단언의 결과도 위 실행 기록에 남긴다.

새 경로도 변경 누락, 현재 입력 변경, 원문/이전 소스/국소 결과 변조, 결과 없는 완료 주장, 기준 완료의 현재 PASS 승격을 거부한다. 기존 V3 재사용 경로의 제품·공유 fixture·설정 변경 금지는 그대로 유지한다. 도구 회귀 검사 74건이 통과했고, 별도 읽기 전용 리뷰에서 완료 승격·소비자 호환 결함은 발견되지 않았다.

정제된 근거는 [현재 변경 검토 기록](2026-10-07-mes-expectations.sources/verification/history-width-20261014/review.json)에 연결한다. 기준 완료 원장 연결 검사 `normalize-mes-expectations.mjs --check`는 native exit 0으로 통과했다. [완료 영수증](2026-10-07-mes-expectations.sources/verification/history-width-20261014/completion.json)에 검증 원문·보존 대조·화면의 해시를 기록했다. 기존 정상 복구 묶음과 그 과거 결과는 이번 화면 수정의 신규 빌드·복구 근거로 승격하지 않는다.

## 적용 범위

정리 기록, 화면 수정, 기준 완료 연결을 작업 브랜치에 나누어 저장한다. main 반영과 직원 배포는 하지 않는다. 새 HEAD의 CI는 시작 상태만 확인하며 전체 종료는 기다리지 않는다. 합의된 제외 기능과 기존 성능 기준 미충족 기록은 이번 화면 수정으로 바뀌지 않는다.
