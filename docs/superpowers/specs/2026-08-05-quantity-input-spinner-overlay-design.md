# 공통 수량 입력 스피너 오버레이 설계

## 목표

DEXCOWIN MES의 모든 업무 수량 입력에서 브라우저 기본 위·아래 증감 버튼을 다시 표시한다. 증감 버튼은 입력 오른쪽에 겹쳐 표시하고, 숫자의 현재 수평 중앙 위치와 입력 자체의 크기·배치는 변경하지 않는다.

## 확정 범위

- 공통 `QuantityInput`을 사용하는 전체 업무 수량 입력에 동일 적용한다.
- 현재 `QuantityStepper`의 `-10/-1/+1/+10` 버튼은 그대로 유지한다.
- 각 사용처가 전달하는 `min`, `max`, `step`, `disabled`, `readOnly` 계약을 그대로 따른다.
- PIN, 검색, 창고 치수, 페이지 크기처럼 업무 수량이 아닌 입력은 변경하지 않는다.
- 백엔드 API, DB, 저장 형식은 변경하지 않는다.

## 선택한 접근

브라우저 네이티브 number spinner를 사용한다. `QuantityInput`은 기존처럼 단일 `<input type="number">`를 반환하고 별도 래퍼나 커스텀 버튼을 추가하지 않는다.

공통 CSS에서 spinner를 다시 표시하되 일반 레이아웃 흐름에서 분리하여 입력 오른쪽 최상위 레이어에 배치한다. 이에 따라 spinner가 생겨도 텍스트 정렬 영역을 차지하지 않으며 숫자는 현재와 같은 중앙 좌표를 유지한다.

이 접근은 다음 대안보다 변경 위험이 작다.

- 커스텀 증감 버튼: 모든 소비 화면의 래퍼·grid·ref 계약을 바꿔야 한다.
- 좌우 padding 보정: 브라우저별 spinner 폭 차이 때문에 숫자 위치가 달라질 수 있다.

## 시각·상호작용 계약

- 숫자는 계속 `text-align: center`와 tabular numeral을 사용한다.
- spinner는 입력 오른쪽에 표시되며 숫자 위를 불필요하게 가리지 않는다.
- spinner 레이어는 클릭 가능하고 입력의 `step` 단위로 값을 변경한다.
- 최소·최대값과 비활성 상태는 네이티브 number input 동작을 따른다.
- 기존 44px 입력 높이, radius, 색상 토큰, focus-visible 표시를 유지한다.
- 라이트·다크 테마 모두 같은 구조를 사용한다.

## 검증

- 공통 입력 테스트를 먼저 변경해 spinner 숨김 계약이 제거되지 않은 현재 구현에서 RED를 확인한다.
- GREEN 후 `QuantityInput`과 `QuantityStepper` 관련 테스트를 실행한다.
- 인앱 Chromium 브라우저의 입출고 `기준 수량`에서 다음을 확인한다.
  - spinner가 보이고 위·아래 클릭으로 값이 변경된다.
  - 변경 전후 숫자의 수평 중앙 위치가 같다.
  - `-10/-1/+1/+10` 버튼과 입력 폭이 그대로다.
  - 라이트·다크 테마에서 겹침이나 잘림이 없다.
- 변경 파일 strict ESLint와 프런트 영향 영역 검증을 실행한다.

## 비범위

- 별도 대형 증감 버튼 추가
- 기존 stepper 버튼의 크기·순서·색상 변경
- 수량 검증 규칙이나 반올림 방식 변경
- 모바일 하단 탭바와 주간보고 등 동결 영역 수정
