# CP2 디자인 시안 — 사용자 승인 완료

2026-10-20. [단일 HTML 시안](2026-10-20-work-reservations.html) / [CP1 계약](../plans/2026-10-20-work-reservations-contract.md) / [실행 계획](../plans/2026-10-20-work-reservations.md).

## 화면 방향

- 관리자: 기존 시스템 메뉴에 작업 예약 관리. 작은 건수 요약, 검색·필터가 있는 좌측 목록, 우측 선택 상세. 담당자 부서와 자재 위치를 구분한다.
- 상세: 작업 목적과 생산/입고 예정 → 담당자 → 예약 자재 → 완료 시 증감 → 처리 기록. 하단 취소 동작은 고정하고 본문만 스크롤한다.
- 취소창: 대상·담당자·해제할 자재, 필수 사유. 공백은 차단하고 처리 중 중복 제출을 막는다. 충돌/실패 시 입력 사유를 유지한다.
- 대시보드: 실재고 분포 안에 예약 부분을 사선으로 표시하고 부서 배지에 예약량을 함께 표시한다. 상세는 가용·작업·승인·출하 예약·입고/생산 예정·위치 이동을 구분한다. 관련 작업에는 담당자·목적·해당 품목 예약량이 연결된다.

현재 디자인은 기존 blue/slate 토큰, Pretendard, 둥근 카드와 얇은 구분선을 따른다. 모든 데이터는 메모리 안의 가상 직원/가상품목 예시다. HTML은 기존 로컬 폰트를 포함하므로 외부 폰트나 앱 API 연결이 필요 없다.

## 확인한 상태

- 1914×883, 1366×768: 가로 넘침 없음, 메뉴 글자 축소 없음, 목록/상세 내부 스크롤 및 하단 취소 유지.
- 긴 품목명·많은 자재, 예약 필요, 비활성 담당자, 투입 없는 입고, 취소 기록, 0건, 조회 실패, 밝은/어두운 테마.
- 빈 취소 사유 차단, 처리 중 버튼 잠금, 충돌 시 사유 보존, 시안 내 취소 후 해당 자재 예약 해제와 가용량 갱신.
- 물리 재고 0인 결과품의 생산 예정 표시, 이동의 전체 증가 0, 미래 입고의 가용량 미가산, 품목별/담당자별 관련 예약 연결.
- 활성 버튼/입력/선택 조작 높이 44px 이상, 본문 14px·보조 정보 12px, 키보드 포커스·Escape 닫기·취소창 포커스 순환.
- 브라우저 콘솔 오류 없음, HTML 내부 JavaScript 구문 검사와 UTF-8/중복 ID/공백 검사 통과.

하위 검토자는 `GPT-6.1 Sol / High`로 정보 계약과 실제 스크린샷을 검토했다. 관련 작업 수량, 취소 후 예시 수치, 화면 전환의 빈/오류 상태, 취소된 이동 예정, 창고 입고 위치 지적을 반영하고 브라우저에서 재확인했다.

화면 증거와 로컬 검사 요약은 워크트리 `_attic/runtime/work-reservations/cp2-*`에 보관한다. 이 단계는 실제 React 화면·DB 예약 동작의 검증이 아니다.

## 사용자 확인 후 구현할 때

2026-10-20 사용자의 ‘다음 ㄱㄱ’를 시안 승인 및 CP3 진행 지시로 반영했다. 이후 CP5 요청에서도 승인한 시안대로 구현하도록 확인했다. CP5/CP6의 화면 구현은 이 시안을 기준으로 한다. 실제 구현에서는 `AdminPageHeader`, `AdminKpiBar`, `AdminListPanel`, `AdminDetailCard`, `ConfirmModal`을 재사용한다. 시안의 인라인 색/스타일을 복사하지 않고 `LEGACY_COLORS`/CSS 토큰과 기존 컴포넌트로 옮긴다. 시안의 메모리 예시 처리 코드는 제품 코드에 옮기지 않는다.

주간보고·모바일 하단 탭·출하 최종 카드 동결 영역은 건드리지 않았다. 새 모바일 관리자 진입도 이 시안 범위에 포함하지 않는다. 다음 CP는 사용자 지시를 기다린다.
