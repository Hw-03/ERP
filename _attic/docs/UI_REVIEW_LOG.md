# DEXCOWIN MES UI 검토 대화 기록

UI를 보며 나눈 질문·관찰·결정의 맥락을 보존하는 기록이다. 구현 항목을 관리하는 TODO나 작업 인수인계가 아니며, 사용자와 대화에서 명시적으로 합의한 내용만 결정으로 기록한다. 기록만으로 코드 변경을 요청하지는 않는다.

## 2026-08-19 — 대시보드 `자재 목록` 제목의 필요성

- 화면: 데스크톱 대시보드 (`/mes?tab=dashboard`)
- 관찰 대상: 재고 표 검색창 왼쪽의 `자재 목록` 텍스트
- 사용자 질문: “이 텍스트가 굳이 있어야할까”
- 검토 맥락: 같은 화면의 좌측 내비게이션과 상단 화면명, 재고 현황 카드 및 바로 아래 표가 이미 목록의 성격을 충분히 설명하는지 확인이 필요하다.
- 확정: `자재 목록` 텍스트는 제거하고 고정 영역에는 검색창만 남긴다. 대체 제목이나 품목 수는 표시하지 않는다.

### 확정 근거

- 검색 안내와 이어지는 표 열 제목만으로 목록의 성격을 충분히 알 수 있다.
- 품목 수는 상단 현황 카드와 중복되고, 다른 제목도 같은 정보를 반복한다.
- 구현할 때는 화면에 보이지 않는 접근성 이름(예: 목록 섹션의 `aria-label`)을 남겨, 시각적 제목 제거와 표의 의미 구분을 분리한다.

### 적용·검토 기록

- 고정 검색 영역에서 보이는 `자재 목록` 제목과 그 전용 wrapper를 제거하고, 검색창이 전체 폭을 사용하게 적용했다.
- 목록 section은 스크린 리더에서 계속 `자재 목록` region으로 식별되도록 접근성 이름을 유지했다.

## 2026-08-19 — 생산 가능수량의 병목 표현 방식

- 화면: 데스크톱 대시보드 > `생산 가능수량` 보기
- 비교 기준: `BOM 구성 보기` 읽기 전용 화면의 구성품 행. 품목명·품목 코드·소요량·현재 재고를 같은 행에서 확인하며, 재고가 없는 구성품은 행 전체가 강조되어 원인을 바로 파악할 수 있다.
- 사용자 관찰: BOM 구성 보기의 표현은 생각보다 잘 만들어졌고 직관적이다.
- 현재 불편: 생산 가능수량에서는 모델을 펼친 뒤 `빠른 생산 병목: <품목명>`처럼 문장으로 표시되어, 어떤 구성품이 얼마나 부족한지와 생산 가능수량의 관계를 즉시 읽기 어렵다.
- 검토 의도: 병목을 요약 문장으로만 보이게 하기보다 BOM 구성 보기처럼 병목 구성품 자체를 구조화된 행으로 보여 주는 방식을 적용할 수 있는지 검토한다.
- 범위 인식: 이 변화는 현재 모델 그룹·출하품·생산 가능수량을 읽는 흐름에 영향을 주므로, 부분 문구 수정이 아니라 대대적인 UI 재구성이 필요할 수 있다.
- 초기 상태: 방향 검토 중이었다. 이후 대화에서 합의한 최종 데스크톱 구조는 이 기록의 `확정된 데스크톱 화면 구조`를 따른다.
- 실행 요청: 없음. 코드 변경하지 않음.

### 논의에서 출발한 우선순위

- 첫 화면의 핵심 수치는 `출하 대기`·`빠른 생산`·`총생산`으로 유지한다.
- BOM을 한눈에 확인하는 기능은 세 수치와 병목의 근거를 이해하기 위한 중요한 보조 정보로 둔다.
- 공용 자재가 모델 사이에 미치는 영향은 유용하지만, 이번 UI 재설계의 우선순위는 아니다.

### 병목 용어 재검토

- 현재 `빠른 생산 병목`은 실제 모든 제한 구성품이 아니라, 계산에서 대표로 선택된 한 항목을 뜻한다. 여러 구성품이 같은 생산 한계를 만들 수 있으므로 단일 병목이라고 단정하기 어렵다.
- 생산 가능수량에서 필요한 설명은 단순한 품목명보다 “현재 한도 다음 단위를 생산하려 할 때 어떤 구성품이 각각 얼마나 부족해지는가”이다.
- 검토했던 대안: 단수 `병목` 대신 복수의 `생산 한계 구성품` 또는 `다음 생산 시 부족 구성품`으로 표시한다. 이후 단순화 방향에서 이 별도 요약은 사용하지 않기로 했다.

### 단순화 방향

- 별도의 병목·한계 구성품 요약은 표시하지 않는다. 단일 대표 항목이나 파생 부족 목록으로 BOM을 다시 설명하지 않는다.
- 생산 가능수량(`출하 대기`·`빠른 생산`·`총생산`)은 유지하고, 근거 확인은 전체 BOM 트리 자체로 한다.
- BOM은 기존처럼 품목명·품목 코드·소요량·현재 재고를 보이는 읽기 전용 구조를 사용한다.
- BOM의 기준 루트는 출하 완제품(PF)이다. 포장 자재까지 포함한 PF BOM 전체를 기본으로 펼쳐 보인다.
- 처음 열 때는 모델 순서상 첫 번째 자동 기준 PF를 선택해 수량과 BOM을 바로 표시한다. 자동 기준 PF가 없는 모델은 건너뛰며, 선택 가능한 PF가 없을 때만 빈 상태를 표시한다.
- BOM의 표시 문법은 대시보드의 기존 `BOM 구성 보기`를 기준으로 한다. 구성품명·품목 코드·소요량·현재 재고 열, 계층 들여쓰기, 재고 0 행의 강조를 유지한다.

### 선택·전환 규칙

- 여러 PF 중 선택한 하나의 PF BOM만 표시한다. 다른 PF는 목록에서 선택해 전환한다.
- 왼쪽 목록은 모델 그룹을 접고 펼친다. 처음에는 선택된 PF가 속한 모델만 펼치고 나머지 모델은 접어 둔다.
- 모델 헤더는 펼침·접기만 처리하며, PF 행을 선택할 때 오른쪽의 세 수량과 BOM이 함께 갱신된다.

### 확정된 데스크톱 화면 구조

- 왼쪽: 모델 그룹과 그 하위 PF 목록. 선택된 PF를 분명히 표시한다.
- 오른쪽 상단: 선택 PF의 이름·품목 코드와 `출하 대기`·`빠른 생산`·`총생산` 수량을 고정해 표시한다.
- 오른쪽 본문: 선택 PF를 루트로 하는 전체 BOM을 기존 `BOM 구성 보기` 문법으로 렌더한다. 이 영역만 세로로 스크롤한다.
- 전환: PF를 선택하면 오른쪽의 고정 수량과 BOM 트리를 동시에 바꾼다.
- 제외: `병목`, `생산 한계 구성품`, 파생 부족 목록처럼 BOM을 다시 요약하는 별도 UI는 두지 않는다.
- 범위: 이번 대화에서 확정한 화면은 데스크톱 대시보드 기준이다. 모바일 배열과 실제 구현 범위는 별도로 검토한다.

## 2026-08-19 — 입출고 4단계 BOM 하위 행 제어 영역 정렬

- 화면: 데스크톱 입출고 > 요청 작성 > 수량 조정(4단계)
- 사용자 관찰: 묶음 상위 행의 우측 `차감 위치`·수량 제어 영역에 비해, BOM으로 자동 전개된 하위 자재 행의 같은 제어 묶음이 왼쪽에 있어 세로 기준선이 맞지 않는다.
- 사용자 요청: 하위 행의 `차감 위치`, 수량 증감, `가능 재고`, `실행 후` 영역을 오른쪽으로 옮겨 상위 행의 우측 제어 영역과 정렬한다.

### 확정한 처리 방식

- 데스크톱에서만, BOM 하위 행이 카드 내부에서 다시 갖고 있던 18px의 오른쪽 여백을 없앤다. 카드를 벗어난 일반 행의 18px 기준선은 유지한다.
- 따라서 하위 행의 제어 묶음은 카드 헤더와 같은 시작선에 놓이고, 카드 테두리·내부 여백 때문에 생기던 이중 들여쓰기는 제거된다.
- 수량 계산, 차감 위치 선택, 재고 부족 표시, 자동 전개와 행 선택의 동작은 바꾸지 않는다.
- 모바일의 줄바꿈·여백 규칙은 그대로 둔다.

### 적용·검토 기록

- 하위 BOM 행에만 위 정렬 규칙을 적용했고, 회귀 테스트로 하위 행에는 `lg:pr-0`, 일반 행에는 기존 `lg:pr-[18px]` 기준이 유지됨을 확인했다.
- 사용자가 실제 4단계 화면에서 정렬 결과를 검토했다.
- 대화 기록과 해당 정렬 변경은 커밋 `1510cb56`으로 `main`에 푸시했다.

## 2026-08-19 — 대시보드 재고 상세 패널 상단 간격

- 화면: 데스크톱 대시보드 > 재고 상세 보기 우측 패널
- 사용자 관찰: `상세 정보`·`최근 내역` 탭 박스와 그 아래 품목명·품목 코드·상태 정보 블록이 너무 가깝게 이어져, 패널 상단의 정보 단위가 분리되어 보이지 않는다.
- 기준: 품목 정보 블록 하단 구분선과 `수량 현황` 카드 사이에 이미 쓰인 여백 정도를 탭 박스와 품목 정보 사이에도 적용한다.

### 확정한 처리 방식

- 재고 상세 패널에서만 탭 박스·닫기 버튼 묶음의 아래에 `mb-4`(16px) 여백을 둔다.
- 탭의 전환·키보드 조작·닫기 동작, 제목 정보의 구성, 아래 카드의 여백은 바꾸지 않는다.
- 공용 우측 패널 전체가 아니라 재고 상세 패널에만 적용해 다른 상세 패널의 상단 배열에는 영향을 주지 않는다.

### 적용·검토 기록

- 재고 상세 패널의 탭·닫기 버튼 묶음에 `mb-4`를 실제 적용했고, 기존 회귀 테스트와 데스크톱 브라우저 확인으로 간격 및 탭·닫기 동작을 확인했다.

## 2026-08-19 — 생산 가능수량 요약 우선 전환

- 화면: 데스크톱 대시보드 > `생산 가능수량` 모달
- 이전의 좌측 PF 목록·우측 BOM 동시 표시 구조는 모델별 수량 비교 정보를 숨겨, 전체 생산 여력을 먼저 판단하기 어렵다는 피드백이 있었다.
- 앞선 `확정된 데스크톱 화면 구조` 중 동시 표시·자동 BOM 선택 관련 결정은 이 항목으로 대체한다.

### 확정한 처리 방식

- 처음 열 때는 모델별 `모델 수`·`자동 기준 출하품`·`출하 대기`·`빠른 생산`·`총생산`을 한 표에서 비교한다.
- 모델을 펼치면 AF별 수량과 상태를, AF를 펼치면 PF별 수량과 기존 병목 정보를 확인한다.
- PF의 `BOM 보기`를 눌렀을 때만 동일 모달 안의 전용 BOM 보기로 전환한다. 전용 보기에는 선택 PF의 이름·코드·세 수량과 전체 BOM을 표시하며, 뒤로가기로 요약표로 돌아온다.
- 최초 진입에는 BOM을 요청하지 않는다. 계산 API·대시보드 상단 요약·모바일 배열은 변경하지 않는다.
