# 사용자 가이드

> **현재 기준**: DEXCOWIN MES는 브라우저의 `/mes`에서 시작한다. 이 문서는
> 데스크톱 화면의 현재 탐색 구조를 설명한다. 모바일은 화면 폭에 따라 별도 셸을 사용하므로
> 같은 URL에서도 메뉴 구성이 다를 수 있다.

> **2026-10-08 변경의 적용 상태:** 아래 설명은 현재 작업본 구현 기준이다. 정식 성능·전체 백엔드·정식 기대값·코드와 DB 공동복구·CI 검증은 아직 완료 전이며 직원 환경 배포를 실행하지 않았다. 적용 여부는 [최종 검증 결과](../../docs/superpowers/specs/2026-10-08-mes-safe-closure-results.md)와 운영자의 배포 안내로 확인한다.

## 시작하기

1. 브라우저에서 `/mes`를 연다.
2. 로그인 카드가 보이면 현재 작업자로 로그인한다. 저장된 작업자 정보가 없거나, 서버 재시작·비활성 직원 상태가 확인되면 다시 로그인 화면으로 돌아간다.
3. 데스크톱 폭에서는 좌측 사이드바와 상단 바가 있는 작업 화면이 열린다. 처음 진입하는 기본 화면은 **대시보드**다.

작업 중인 사용자의 표시 탭은 직원별 설정에 따라 달라질 수 있다. 보이지 않는 메뉴는 임의로 URL을 바꾸기보다 관리자에게 권한 설정을 확인한다.

## 데스크톱 공통 조작

- 좌측 사이드바를 클릭해 화면을 전환한다. 설정에 따라 사이드바는 마우스를 올릴 때만 펼치거나, 접힘/펼침으로 고정될 수 있다.
- 상단 바의 상태 표시에는 현재 안내·오류가 나타난다. 새로고침 버튼은 현재 탭을 다시 열어 최신 화면 데이터를 불러오도록 한다.
- 상단의 사용자 메뉴에서 PIN 변경 또는 로그아웃을 할 수 있다. 읽지 않은 알림은 알림 버튼에서 확인하고 관련 화면으로 이동할 수 있다.
- 저장·승인처럼 상태를 바꾸는 작업에서는 화면의 확인·오류 안내를 먼저 읽고, 처리 중인 버튼을 반복해서 누르지 않는다.

## 사이드바 메뉴

| 메뉴 | 사용하는 때 |
|---|---|
| **대시보드** | 재고 현황을 보고 필요한 품목을 확인하거나 입출고 작업으로 이어갈 때 |
| **입출고** | 입고·출고·이동 등 재고 작업을 작성·제출하고, 결재 또는 내 요청 흐름을 확인할 때 |
| **입출고 내역** | 완료되었거나 진행 중인 거래 이력을 검색·필터하고 상세를 확인할 때 |
| **출하** | 출하 요청을 작성하고, 준비 체크·준비 완료·픽업과 출하 이력을 관리할 때 |
| **불량** | 불량 격리·바로 처리, B급·구형 보관, 폐기·반품 등 불량 관리 흐름을 수행할 때 |
| **창고 지도** | 랙·박스와 특별 보관 영역의 위치별 품목 배치를 확인·관리할 때 |
| **주간보고** | 선택한 주의 생산·재고 흐름을 확인할 때 |
| **일일 작업 일보** | 본인의 일일 작업 내용을 기록·확인할 때 |

사이드바 아래의 **설정**에서는 테마, 사이드바 표시 방식, 개인 PIN과 로그인 알림 팝업을 관리한다. 관리자 탭이 허용된 사용자에게만 설정 화면의 **관리** 진입이 보이며, 여기서 기준 정보·BOM·보안 설정을 관리한다.

테마와 사이드바는 함께 저장한다. 저장에 성공하면 같은 직원으로 열린 같은 브라우저의 다른 탭도 자동 반영한다. 다른 직원의 설정은 바뀌지 않으며, 설정 화면에서 아직 저장하지 않은 값과 입력 중인 PIN은 유지한다.

## 주요 업무 흐름

### 대시보드에서 입출고로

대시보드에서 재고를 확인한 뒤 필요한 품목의 작업 동선을 선택하면 **입출고**로 이동한다. 이동 후에는 작업 유형, 대상 품목, 수량과 필요한 사유를 확인한 다음 화면의 제출 안내를 따른다.

화면을 새로고침하면 같은 직원의 검색어와 선택 품목을 복원한다. 열려 있던 상세는 서버에서 다시 조회해 열고, 닫혀 있던 상세는 닫힌 상태로 둔다. 삭제가 확인된 품목의 상세와 이력은 계속 볼 수 있지만 새 입출고 작업은 할 수 없다. 조회 실패는 삭제 안내와 구분하며 다시 시도할 수 있다.

### 입출고와 이력

입출고 화면은 새 작업 작성과 요청/결재 관련 화면을 제공한다. 재고에 영향을 주는 요청은 상태와 승인 요구사항을 확인한 뒤 진행한다. 결과 확인이나 과거 거래 검색이 필요하면 **입출고 내역**으로 이동해 기간·검색·필터와 상세 화면을 사용한다.

직원 등급은 사용하지 않는다. 창고 정·부, 부서 정·부, AS·연구 담당 역할에 따라 결재하며 관리자 PIN 기능과는 별개다. 역할을 회수해도 대기 요청과 예약은 유지하고, 해당 역할을 가진 결재자가 이어서 처리한다. 원자재 입고는 공정코드가 R로 끝나는 유효한 원자재만 선택할 수 있으며 삭제되었거나 분류가 바뀐 이전 초안도 제출할 수 없다.

AS·연구 사용출고의 최종 확인에는 전용 결재와 일반 부서 결재의 경로별 건수가 표시된다. 활성 전용 승인자가 없으면 해당 요청은 부서 결재로 안내한다. 원자재 입고는 창고 즉시 반영과 완료 상태를 확인하고, 일반 직원의 승인 대기 요청은 승인 완료 뒤 실제 재고에 반영되는지 확인한다.

입출고 내역의 건수는 거래 행 수가 아니라 작업 수다. 한 작업의 여러 품목은 한 건으로 세고, 취소는 원작업과 같은 업무 분류의 별도 한 건으로 센다. 원작업과 취소가 다른 달이면 각각 그 달에 표시한다. 재고가 원복되어 순변화가 없어도 처리 이력은 두 건이다.

품목 이름이나 코드가 바뀌어도 새 거래 이력에는 거래 당시 품목 정보가 남으며 현재 품목 정보와 구분해 확인할 수 있다. 당시 정보가 보존되지 않은 과거 이력은 현재 품목 정보를 사용한다는 안내가 표시된다. 상세의 재고 변화는 필요하면 위치별 항목을 펼쳐 작업 전·후 수량을 확인한다.

### 출하

출하에서는 요청을 작성한 뒤 구성품·체크리스트를 확인해 준비를 진행한다. **준비 중** 요청의 상세에서도 인보이스 번호 등 필요한 정보를 확인한 뒤 **준비 완료** 처리를 할 수 있다. 준비 완료 후의 픽업 처리와 취소 가능 여부는 요청의 현재 상태와 화면 안내를 따른다.

준비할 재고는 최종 PF 완제품과 동반 출하품이다. 다른 요청의 예약량을 뺀 가용량이 부족하면 준비 완료할 수 없다. 이미 생산된 PF는 BOM 구성품 재고가 없다는 이유만으로 차단하지 않는다. 준비 취소는 해당 요청의 예약을 풀고, 픽업 취소는 실제 출하한 품목과 위치의 수량을 복원한다.

### 불량과 창고 지도

불량 화면은 **불량 처리**, **격리 목록**, **B급·구형 자재**, **불량 통계** 네 카드에서 시작한다. 격리 등록의 각 품목은 불량 격리·B급·구형 중 관리 분류를 고른다. 세 분류 모두 양품 재고에서는 제외되며, 발생 통계에는 최초 등록 분류로 포함된다.

**불량 통계**는 이번 달 누계를 기본으로 발생 수량·건수, 이전 기간 대비 증감, 등록 사유와 품목의 집중도를 보여준다. 최초 분류별 표에서 불량·B급·구형의 현 기간과 이전 기간 수량·건수를 확인한다. 분류 필터를 펼치거나 사유·부서·품목을 선택하여 조회 범위를 좁히고, 선택 조건을 해제하거나 전체 초기화할 수 있다. 최근 기간 추세와 선택 기간의 상세 추이를 전환하고, 품목 비교표에서 이전 기간에만 발생한 품목도 확인한다. 집계 시각은 KST로 표시하며 통계 새로고침으로 다시 조회한다.

진행 중인 기간은 직전 기간의 같은 경과 구간과 비교하고, 완료된 기간은 직전 전체 기간과 비교한다. 이전 수량이 없거나 짧은 달·윤일 때문에 비교 범위가 보정되면 증감률은 표시하지 않는다. 비중은 선택 범위의 전체 발생 수량 기준이며 생산량 대비 불량률이나 손실금액을 뜻하지 않는다. 발생 시각·원래 수량·최초 분류로 집계하므로 이후 분류 변경·부분 또는 전량 복귀·폐기·반품은 과거 발생량을 바꾸지 않는다. 출처가 복원되지 않은 레거시 기록과 최초 분류 이력이 없거나 손상된 기록은 임의 추정하지 않고 각각 제외 건수와 안내로 구분한다.

불량 격리와 바로 폐기는 **부서 재고** 또는 **창고 재고**만 선택한다. 부서 재고의 실제 차감 부서는 품목코드로 자동 결정되며, 품목 목록의 부서 필터는 조회용이다. 바로 재작업은 출처 선택 없이 품목 목록으로 진입하고, 부모와 BOM 하위 품목도 각각의 품목코드에 해당하는 부서에서 차감·입고된다.

불량 처리 입력 중 뒤로 가기·새로고침·메뉴 이동을 시도하면 이탈 확인을 따른다. **계속 머무르기**를 선택하면 품목·수량·사유·메모를 유지하고, **나가기**를 선택하면 처리하지 않고 입력을 버린다. 재작업 이력에서는 상위 차감과 하위의 정상 회수·불량 격리·폐기 수량을 구분한다. 거래 자료에서 창고 전후 수량이 모두 같다고 확인된 경우에만 **창고 재고 변동 없음**을 표시한다.

B급·구형 자재는 필요한 수량만 정상 복귀할 수 있다. 폐기·반품·재작업이 필요하면 먼저 분류를 **불량 격리**로 변경한다. 분류 변경과 메모 수정은 직원 PIN으로 확인하며 기록별 이력에서 확인할 수 있다. 물리적인 보관 위치를 찾거나 배치를 조정할 때는 **창고 지도**를 사용한다. 지도에서 보이는 랙/박스와 특별 영역의 수량은 품목 마스터가 아니라 위치 배치 정보이므로, 재고 변동 작업과 혼동하지 않는다.

**여러 건 선택**은 같은 품목·부서·관리 분류에 속한 각 기록의 남은 수량 전체를 처리한다. 일부 수량만 처리하려면 개별 처리를 선택한다. 반품은 창고 또는 튜브의 불량 격리 기록과 활성 공급업체를 확인한 뒤 진행한다. 튜브에 격리된 TR 원건은 튜브 전용 업체를 사용하고, 그 밖의 허용된 반품과 원건 없는 과거 자료는 창고 업체를 유지한다. 업체 범위가 다른 기록은 나누어 반품한다. 처리 응답을 받지 못했다면 화면을 닫거나 새 요청을 만들기 전에 처리 여부를 확인하고, 현재 화면에서 같은 입력으로 다시 시도한다. 이 재시도는 중복 거래를 만들지 않는다.

### 보고와 관리

**주간보고**는 상단의 주 선택으로 기간을 바꾸어 본다. **일일 작업 일보**는 현재 작업자를 기준으로 일자별 작업 내용을 기록·확인한다. 기준 정보나 보안 설정 변경은 권한이 있는 사용자가 **설정 → 관리**에서만 수행한다.

주간 기간은 한국 시간 월요일 00시부터 다음 월요일 00시 직전까지다. 공정 생산과 PF 픽업 출하는 구분되며, 생산이 없어도 PF 실적이 있으면 모델별 표에 표시된다. **전체 정상재고**는 보고 대상 품목의 합계다. **집계·검산 기준**을 펼쳐 대상과 분류를 확인한다. 기존 방식 자료는 **전체 재고**와 검산 전 안내로 구분한다. 재작업으로 생긴 불량·폐기 자식은 입고와 불량 두 열에 함께 표시되어 정상재고 순변화가 0이 된다.

새 직원은 관리자 메뉴가 기본 숨김이다. 필요하면 직원 관리의 **메뉴 표시**에서 관리자 항목을 켠다. 메뉴 표시와 창고·부서·AS·연구 결재 역할은 각각 설정한다. 기존 직원의 메뉴나 결재 역할은 새 직원 기본값 때문에 바뀌지 않는다.

일일 작업 일보의 처리 활동은 같은 거래의 입출고 내역과 연결된다. 부서 입고는 실제 작업 유형과 해당 부서 수량을 표시하고, 요청자·승인자·각 처리 시각 및 입력한 메모를 구분해 확인할 수 있다. 원작업을 열면 해당 거래의 상세 수량과 비교한다.

일보의 취소 건수는 취소한 작업 단위로 표시한다. 여러 품목을 한 번에 취소하거나 같은 날 원작업과 취소가 모두 있어도 취소는 한 건이다. 날짜를 넘겨 취소하면 원작업 날짜에는 기존 취소 상태가 남고 취소 날짜에서도 취소 상세와 원작업 링크를 확인할 수 있다. 완료 수량에는 취소된 작업을 더하지 않는다.

관리자의 품목 생성·수정 화면에서는 모델과 공정 분류를 선택한 뒤 표시되는 품목 코드를 확인한다. 다른 사용자의 저장으로 코드가 바뀌면 입력 내용을 유지한 채 새 미리보기를 확인하고 다시 저장한다.

**BOM 관리**의 구성품 추가·수량 수정·삭제는 **구성 저장**을 눌러 함께 반영한다. 저장 실패나 다른 탭의 변경으로 충돌하면 초안과 오류 안내를 확인한다. **변경 취소**는 서버의 최신 구성을 다시 읽는다. 검토 완료한 BOM은 먼저 완료를 해제한 뒤 수정·저장하고 다시 완료 처리한다.

## 자주 묻는 상황

| 상황 | 확인 방법 |
|---|---|
| 원하는 메뉴가 보이지 않는다 | 직원별 표시 탭 설정에 따라 숨겨졌을 수 있다. 관리자에게 확인한다. |
| 작업을 저장·제출할 수 없다 | 화면의 필수값·재고·결재 또는 상태 안내를 확인한다. |
| 처리 결과를 다시 확인하고 싶다 | 입출고는 **입출고 내역**, 출하는 **출하**의 요청·이력 화면에서 확인한다. |
| 현재 화면이 오래된 것 같다 | 상단 새로고침을 사용한 뒤 상태 안내와 목록을 다시 확인한다. |
| 로그인 화면으로 돌아왔다 | 서버 재시작, 저장된 작업자 정보 부재 또는 비활성 상태일 수 있다. 현재 작업자로 다시 로그인하고 반복되면 운영자에게 알린다. |

## 운영 기준

배포·복구를 위해 작업 중지 안내를 받으면 입출고 제출·승인·취소·일보 저장 등 값을 바꾸는 작업을 멈춘다. 이미 처리 중인 요청은 완료 여부를 확인해 운영자에게 알리고, 화면이 다시 열렸다는 이유만으로 작업을 재개하지 않는다. 운영자가 확인을 마친 뒤 업무 재개를 안내하면 새로고침하고 필요한 경우 다시 로그인한다.

- 현재 운영 절차와 장애 대응은 [OPERATIONS.md](OPERATIONS.md)를 따른다.
- 데이터 구조는 [ERD.md](ERD.md)와 `backend/app/models/`를 기준으로 확인한다.
- 품목·모델·기타 변동 수치를 이 문서에서 고정값으로 판단하지 않는다. 필요하면 `python _attic/backend-scripts/facts.py` 또는 관련 화면/API로 확인한다.
