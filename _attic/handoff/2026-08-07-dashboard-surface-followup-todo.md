### 2. 입출고 내역 외곽 표면이 요약·필터 카드보다 먼저 보이지 않게 정리

- 화면/영역: 데스크톱 입출고 내역 > 상단 `이번달 58건` 요약 카드의 위쪽·주변 여백, 요약 카드와 검색·필터 카드 사이 영역.
- 증상:
  - 입출고 내역의 외곽 스크롤 컨테이너가 자체 테두리와 배경을 가지므로, 최상단 요약 카드보다 한 줄 먼저 외곽선이 나타난다.
  - 요약·필터·목록 카드 사이에서 외곽 컨테이너의 배경이 별도 패널처럼 보여 카드 표면이 자연스럽게 이어지지 않는다.
- 사용자 불편: 상단 카드가 콘텐츠 영역 안으로 살짝 밀려 들어간 것처럼 보이고, 카드 사이 배경이 제품의 밝은 표면과 어울리지 않아 완성도가 떨어진다.
- 확정 정책:
  - 상단 요약 카드보다 외곽선이 먼저 보이거나 상단으로 삐져나와 보이지 않게 한다.
  - 외곽 스크롤 컨테이너는 레이아웃·스크롤만 맡고, 내부 카드와 경쟁하는 독립적인 테두리·배경 표면으로 보이지 않게 한다.
  - 스크롤바의 색상·가시성·동작은 수정 범위에서 제외한다.
- 구현 방향:
  - `DesktopHistoryView`의 외곽 스크롤 컨테이너와 내부 `HistoryStatsBar`·`HistoryFilterBar`·`HistoryTable` 카드의 표면 책임을 분리한다.
  - 대시보드의 동일한 외곽 컨테이너 패턴과 함께 비교해, 공통 레이아웃 규칙으로 해결할 수 있는지 검토하되 각 화면의 내부 카드 여백·동작은 보존한다.
- 수용 기준:
  - 입출고 내역 진입 직후 `이번달 58건` 요약 카드 위로 외곽 테두리나 배경선이 먼저 보이지 않는다.
  - 요약·검색/필터·목록 카드 사이의 배경이 같은 표면에서 자연스럽게 이어져 별도 패널 경계처럼 보이지 않는다.
  - 검색, 기간 필터, 상세 패널, 목록 스크롤 등 기존 입출고 내역 동작이 변하지 않는다.
- 브라우저 확인 시나리오:

## 설정

### 3. 관리 진입 항목의 보조 문구를 관리자 탭의 역할로 교체

- 화면/영역: 데스크톱 설정 > 관리 > `관리자` 진입 항목의 보조 문구.
- 증상: 현재 `PIN을 입력해 시작합니다.`는 인증 절차만 설명해, 클릭 후 열리는 관리자 탭에서 무엇을 관리하는지 알 수 없다.
- 사용자 불편: 설정에서 관리 항목을 처음 보는 사용자가 진입 목적과 제공 기능을 파악하기 어렵다.
- 확정 정책: 보조 문구는 PIN 입력 자체가 아니라 관리자 탭의 업무 범위(기준 정보·BOM·보안 관리)를 설명한다. PIN 입력은 진입 뒤 인증 화면에서 안내한다.
- 구현 방향: `AppearanceSettingsModal`의 관리 진입 항목 보조 문구를 관리자 탭의 실제 섹션과 일치하는 짧은 설명으로 교체한다. 예: `기준 정보, BOM, 보안 설정을 관리합니다.`
- 수용 기준:
  - 설정의 관리 항목만 보아도 관리자 탭에서 수행할 수 있는 업무를 이해할 수 있다.
  - PIN 인증 요구는 숨기거나 완화하지 않으며, 진입 후 인증 화면의 안내는 기존대로 유지한다.
  - 문구가 실제 관리자 탭의 모델·품목·직원·부서·BOM·내보내기·보안 기능과 모순되지 않는다.
- 브라우저 확인 시나리오:
  - 데스크톱에서 `/mes?tab=settings`를 열어 관리 항목의 보조 문구를 확인한다.
  - 관리 항목을 클릭해 PIN 인증 화면으로 이동한 뒤, 관리자 탭을 열어 문구가 설명한 범위와 실제 메뉴 구성이 일치하는지 확인한다.
- 우선순위: 낮음

- 확정 정책:
  - 기존에 표시하는 요청 내용·상태·PIN 기반 수정/취소 흐름은 유지한다.
  - 카드의 첫 시선은 요청 유형·상태·요청 흐름·일시가 되게 하고, 품목 상세는 그 아래의 읽기 쉬운 목록으로 배치한다.
  - DEXCOWIN MES의 밝은 카드 표면, 토큰 기반 색상, 절제된 톤 차이를 사용하며 새 색 체계나 과도한 장식은 추가하지 않는다.
- 구현 방향:
  - `MyRequestRow`을 요청 헤더, 흐름/건수 요약, 품목 목록, 비고·행동 영역으로 시각적 책임을 나눈다.
  - 유형·상태는 시선이 모이는 헤더에서 명확한 대비로, 일시는 보조 정보로 정리한다.
  - 품목 행은 코드·명칭·수량의 정렬과 간격을 정돈하고, 현재의 5건 접기/더 보기 동작과 비고·수정·취소 동작을 보존한다.
- 수용 기준:
  - 첫 화면에서 각 요청의 유형, 상태, 창고·부서 흐름, 작성 시각을 빠르게 식별할 수 있다.
  - 다수 품목 요청과 한 품목 요청 모두에서 카드 높이·구분선·여백이 균형 있게 보인다.
  - 완료·대기·반려 등 상태가 색상에만 의존하지 않고 텍스트와 구조로도 구분된다.
  - 더 보기, 비고 펼치기, 수정, 요청 취소와 PIN 확인 흐름이 기존과 동일하게 동작한다.
- 브라우저 확인 시나리오:
  - 데스크톱에서 `/mes?tab=warehouse&section=mine`를 열어 한 건·다수 품목·비고 포함·취소 가능 상태의 요청을 각각 확인한다.
  - 카드의 정보 위계와 품목 행 정렬을 비교하고, 더 보기·비고 펼치기·수정·취소 진입을 수행한다.
- 우선순위: 중간

### 5. 입출고 주 섹션 탭을 콘텐츠 스크롤 중에도 상단에 고정

- 화면/영역: 데스크톱 입출고 > `요청 작성`·`작성 중`·`내 요청` 등 주 섹션 탭.
- 증상: 주 섹션 탭이 입출고 콘텐츠와 같은 세로 스크롤 컨테이너 안에 정적으로 배치되어, 목록을 아래로 스크롤하면 탭이 화면 밖으로 사라진다.
- 사용자 불편: 다른 섹션으로 전환하거나 현재 위치를 확인하려면 목록을 다시 위로 올려야 한다.
- 확정 정책: 주 섹션 탭은 데스크톱 입출고의 모든 섹션에서 콘텐츠 스크롤 중에도 상단 바 아래의 현재 위치에 계속 표시한다. 요청 작성의 품목 전환 집중 모드에서 탭을 숨기는 기존 동작은 유지한다.
- 구현 방향:
  - `DesktopWarehouseView`의 세로 스크롤 경계 안에서 주 섹션 탭을 sticky 레이어로 구성하거나, 스크롤 영역 밖의 고정 헤더로 분리한다.
  - 고정 상태에서 목록 콘텐츠가 탭 아래로 비쳐 읽기 어렵지 않도록 현재 배경 토큰과 적절한 z-index·여백을 적용한다.
  - 탭 개수·권한별 탭 노출·배지·URL 섹션 동기화는 변경하지 않는다.
- 수용 기준:
  - `내 요청` 등 긴 목록을 스크롤해도 주 섹션 탭이 상단 바 아래에서 계속 보인다.
  - 탭 클릭, 활성 탭 강조, 미처리 건수 배지, 권한별 탭 노출, URL의 `section` 동기화가 기존과 동일하다.
  - 요청 작성의 품목 전환 집중 모드에서는 기존처럼 탭이 숨겨지고, 집중 모드를 벗어나면 다시 정상 고정된다.
  - 고정 탭이 요청 카드·모달·드롭다운을 가리거나 스크롤 위치 점프를 만들지 않는다.
- 브라우저 확인 시나리오:
  - 데스크톱에서 `/mes?tab=warehouse&section=mine`를 열어 목록을 충분히 아래로 스크롤한다.
  - 상단에 고정된 탭으로 요청 작성·작성 중·내 요청을 전환하고 브라우저 뒤로 가기·앞으로 가기 시 URL과 활성 탭을 확인한다.
  - 권한별 탭과 요청 작성의 품목 전환 집중 모드에서 탭의 고정·숨김 상태를 확인한다.
- 우선순위: 중간

### 6. 작성 중 빈 상태를 요청 작성으로 이어지는 행동 중심 안내로 개선

- 화면/영역: 데스크톱 입출고 > `작성 중` > 임시저장 요청이 없는 상태.
- 증상: 넓은 콘텐츠 영역에 텍스트 두 줄만 작게 배치되어, 작성 중 탭의 목적과 다음에 할 일을 명확히 전달하지 못하고 화면이 밋밋하게 비어 보인다.
- 사용자 불편: 임시저장 요청이 없을 때 다음 행동인 요청 작성을 다시 찾아야 하며, 빈 상태가 완성된 화면이 아니라 미구성 상태처럼 느껴진다.
- 확정 정책:
  - 빈 상태는 오류나 경고가 아닌 정상적인 시작 상태로 표현한다.
  - 내 요청 카드 개선과 같은 밝은 표면·절제된 청록 강조·명확한 위계를 사용한다.
  - 아이콘, 짧은 제목·설명, `요청 작성`으로 이동하는 단일 주 행동을 제공한다.
- 구현 방향:
  - 공용 `EmptyState`의 icon·action 조합을 활용하되, 작성 중 탭에만 필요한 업무 맥락과 이동 동작을 상위 섹션 탭 전환으로 연결한다.
  - 아이콘·제목·설명·행동의 간격과 카드 높이를 넓은 데스크톱 영역에 맞추고, 불필요한 장식이나 별도 색 체계는 추가하지 않는다.
  - 동일 공용 빈 상태를 사용하는 다른 화면의 외형·동작은 변경하지 않는다.
- 수용 기준:
  - 빈 상태만 보아도 작성 중 탭이 임시저장 요청을 보관하는 곳임을 이해할 수 있다.
  - `요청 작성` 행동을 누르면 요청 작성 섹션으로 이동하며, 기존 URL·탭 동기화가 유지된다.
  - 아이콘, 제목, 설명, 행동이 카드 표면 안에서 균형 있게 보이고 44px 이상의 클릭 영역을 제공한다.
  - 임시저장 요청이 생기면 기존 초안 목록과 이어쓰기·삭제 동작이 그대로 표시된다.
- 브라우저 확인 시나리오:
  - 데스크톱에서 `/mes?tab=warehouse&section=cart`를 열어 초안이 없는 상태를 확인한다.
  - `요청 작성` 행동으로 이동한 뒤 브라우저 뒤로 가기·앞으로 가기에서 탭과 URL 동기화를 확인한다.
  - 임시저장 초안이 있는 계정 또는 데이터에서 기존 초안 카드·이어쓰기·삭제 흐름이 유지되는지 확인한다.
- 우선순위: 중간

## 상단 바

### 7. 사용자 메뉴와 알림 패널을 불투명 팝업 표면으로 통일

- 화면/영역: 데스크톱 상단 바 > 사용자 메뉴, 알림 패널.
- 증상: 두 팝업이 반투명 `s1` 표면을 사용해 뒤의 KPI·목록·텍스트가 비쳐 보이며, 내용의 경계와 가독성이 약하다.
- 사용자 불편: 팝업 자체에 집중하기 어렵고 상단 바의 메뉴·알림이 임시 오버레이처럼 느껴진다.
- 확정 정책: 사용자 메뉴와 알림 패널은 배경이 비치지 않는 불투명 팝업 표면을 사용한다. 라이트·다크 모드 모두에서 동일한 불투명 원칙을 유지한다.
- 구현 방향:
  - 팝업 전용 `--c-popup-bg` 토큰을 두 패널에 적용하고, 테두리·그림자는 기존 팝업 위계를 유지한다.
  - 카드·일반 화면에 쓰는 반투명 `s1` 표면은 변경하지 않는다.
- 수용 기준:
  - 대시보드 KPI·목록 위에서 사용자 메뉴와 알림 패널을 열어도 뒤 배경·텍스트·색상이 패널 안으로 비쳐 보이지 않는다.
  - 메뉴의 PIN 변경·로그아웃, 알림의 읽음·삭제·로그인 팝업 토글·항목 이동이 기존대로 동작한다.
  - 라이트·다크 모드 모두에서 메뉴와 알림 내용의 텍스트 대비가 유지된다.
- 브라우저 확인 시나리오:
  - 대시보드에서 사용자 메뉴와 알림 패널을 각각 연다.
  - 밝은 KPI·표 위에서 패널의 불투명도와 테두리·그림자를 확인하고, 다크 테마에서도 같은 동작과 가독성을 확인한다.
- 우선순위: 중간

### 8. 알림 패널 크기와 본문을 업무 판단 정보에 맞게 개선

- 화면/영역: 데스크톱 상단 바 > 알림 패널 > 결재 요청·승인·반려 알림 행.
- 증상:
  - 알림 본문이 `김현우 · 창고 → 부서 · SR-...`처럼 시스템 요청 코드를 포함해, 담당자가 무엇을 처리해야 하는지 바로 알기 어렵다.
  - 알림 일시는 `8/3 14:16` 축약 형식이라 내 요청 화면의 `2026년 08월 03일 14시 16분` 형식과 다르다.
- 알림 패널의 현재 320px 폭과 360px 목록 높이는 업무 정보가 늘어나면 줄바꿈·스크롤이 과도해질 수 있다.
- 사용자 불편: 알림만 보고 요청 대상·규모를 판단할 수 없어 항목을 열어야 하며, 동일 업무의 날짜 표기가 화면마다 달라 혼란스럽다. 좁은 패널에서는 추가 정보가 읽기 어려워진다.
- 확정 정책:
  - 결재 알림은 시스템 요청 코드 대신 요청자, 요청 흐름/유형, 대표 품목명, 품목 건수 또는 수량처럼 담당자가 판단할 수 있는 정보를 우선 표시한다.
  - 요청 코드는 알림의 기본 본문에서 제외하고, 필요한 경우 상세 화면에서 확인한다.
  - 알림 일시는 내 요청과 같은 KST 전체 날짜 형식으로 통일한다.
  - 데스크톱 알림 패널은 420px 폭을 기본으로 하고, 좁은 뷰포트에서는 화면 여백 안에서 축소한다. 목록 최대 높이도 정보량에 맞춰 440px로 확장한다.
- 구현 방향:
  - 결재 알림을 생성하는 백엔드 요약 형식과 프런트엔드 표시를 함께 검토해, 알림 API의 기존 이동 대상·읽음·삭제 호환성을 유지한 채 업무용 요약을 제공한다.
  - 프런트엔드는 공용 `formatKstDateTime`을 사용해 알림 패널의 날짜 형식을 통일한다.
  - 알림 패널의 폭·최대 목록 높이를 확장하고, 긴 본문은 대표 정보가 잘리지 않도록 행의 줄바꿈·간격을 조정한다.
  - 인수인계 등 결재 요청과 데이터 구조가 다른 알림은 현재 제공 가능한 업무 정보 범위에서 별도 요약 규칙을 둔다.
- 수용 기준:
  - 결재 알림 한 행만 보아도 누가 어떤 흐름의 어떤 품목 요청을 올렸거나, 그 요청이 승인·반려됐는지 알 수 있다.
  - 기본 알림 본문에 `SR-...` 같은 시스템 요청 코드가 표시되지 않는다.
  - 알림의 날짜가 KST 기준 `YYYY년 MM월 DD일 HH시 mm분` 형식으로 내 요청과 일치한다.
  - 데스크톱에서 알림 패널은 420px 폭으로 표시되고, 최대 440px 높이 안에서 여러 알림을 읽을 수 있다. 좁은 창에서도 화면 밖으로 넘치지 않는다.
  - 알림 클릭 이동, 읽음 처리, 개별 삭제, 읽은 알림 삭제, 기존 과거 알림의 표시가 깨지지 않는다.
- 브라우저 확인 시나리오:
  - 결재 요청·승인·반려 알림이 있는 계정으로 넓은 데스크톱과 좁은 창에서 알림 패널을 연다.
  - 각 행에서 요청자·흐름·대표 품목·건수/수량·전체 날짜를 확인하고, 클릭 이동·읽음·삭제를 수행한다.
  - 기존에 저장된 알림과 인수인계 알림도 빈 본문이나 깨진 형식 없이 표시되는지 확인한다.
- 우선순위: 중간

## 일일 작업 일보

### 9. 화면 내부 일보 헤더를 제거하고 상단 바에 작성 맥락·제어를 통합

- 화면/영역: 데스크톱 일일 작업 일보 > 화면 내부 헤더 카드, 공통 상단 바의 제목 오른쪽 빈 영역.
- 증상: 공통 상단 바와 화면 내부 헤더 카드가 모두 `일일 작업 일보` 제목을 표시해 제목이 겹쳐 보인다. 작성일·부서·작성자·내/전체 일보 전환·내보내기 제어가 콘텐츠 시작 영역을 차지해 작업 기록에 사용할 세로 공간도 줄인다.
- 사용자 불편: 일보에 들어온 직후 필요한 맥락과 조작이 두 곳에 나뉘고, 실제 작업 기록보다 헤더가 먼저 크게 보인다.
- 확정 정책:
  - 화면 내부의 일일 작업 일보 헤더 카드는 제거한다.
  - 공통 상단 바는 기존 아이콘·`일일 작업 일보` 제목을 한 번만 표시하고, 제목 오른쪽의 넓은 영역에 작성일, 부서, 작성자, 내/전체 일보 전환, 내보내기 제어를 표시한다.
  - 상단 바에 올린 제어의 순서·동작·권한은 현재 화면 내부 헤더와 동일하게 유지한다.
- 구현 방향:
  - 일일 작업 일보의 작성일·선택 작성자·내/전체 일보 탭 상태와 변경 핸들러를 상단 바 조합 경계까지 안전하게 전달해, 제어 UI가 이동해도 데이터 조회·더티 가드·저장 흐름을 보존한다.
  - `DesktopTopbar`의 `titleAddon` 또는 동등한 탭 전용 슬롯을 일일 작업 일보에도 사용하고, 상태 pill·사용자 메뉴와 겹치지 않는 반응형 정렬을 구성한다.
  - 내부 헤더 카드만 제거하며, MES 작업 기록·작업 내역·저장 제어와 전체 일보의 작성자 선택 카드는 유지한다.
- 수용 기준:
  - 일일 작업 일보 진입 시 제목은 공통 상단 바에 한 번만 보이고, 화면 내부에 중복 제목 카드가 없다.
  - 상단 바의 탭 전용 영역에서 작성일 변경, 부서·작성자 확인, 내/전체 일보 전환, 내보내기가 가능하다.
  - 작성일 변경·전체 일보에서 작성자 전환·저장하지 않은 내용이 있는 상태의 이탈 확인·저장 버튼이 기존과 동일하게 동작한다.
  - 일보 콘텐츠가 제거된 헤더 카드만큼 위로 올라가며, 상단 바의 상태 pill·사용자 메뉴·알림과 겹치지 않는다.
  - 데스크톱의 좁은 너비에서도 제어가 화면 밖으로 넘치지 않고, 우선순위가 낮은 보조 정보는 기존 맥락을 잃지 않는 방식으로 축소 또는 줄바꿈된다.
- 브라우저 확인 시나리오:
  - 데스크톱에서 `/mes?tab=dailyReport`를 열어 상단 바와 콘텐츠 시작 영역을 확인한다.
  - 작성일을 바꾸고 내/전체 일보를 전환한 뒤 작성자를 선택하여, 작업 기록·작업 내역·저장 상태가 올바르게 갱신되는지 확인한다.
  - 작성 후 저장하지 않은 상태에서 날짜·탭·다른 화면으로 이동해 더티 가드가 유지되는지 확인하고, 여러 데스크톱 너비에서 상단 제어의 겹침 여부를 확인한다.
- 우선순위: 중간

## 공통 작업 허브

### 10. 입출고·출하·불량의 업무 진입 카드를 하나의 시각 문법으로 통일

- 화면/영역: 데스크톱 입출고의 작업 유형 선택 카드, 출하의 `출하 관리`·`출하 이력` 카드, 불량의 `불량 격리`·`바로 처리`·`격리 목록` 카드.
- 증상:
  - 세 화면 모두 업무를 선택해 다음 단계로 들어가는 큰 카드인데, 아이콘 크기·제목 크기·내부 패딩·하단 설명의 정렬 기준이 각각 다르다.
  - 입출고·불량은 `창고↔부서`, `정상 재고에서 품목을 골라 격리 등록`처럼 구문형 안내를 쓰는 반면, 출하는 완결된 서술문과 별도 건수 배지를 사용해 같은 계열의 시작 화면으로 인식되지 않는다.
- 사용자 불편: 탭을 오갈 때 같은 역할의 카드를 매번 다른 방식으로 읽어야 하며, 미세한 배치·문장 톤 차이가 화면 전체의 통일감을 떨어뜨린다.
- 확정 정책:
  - 세 화면의 카드 모두 `상단 아이콘·업무명 / 선택적 우측 보조 정보 / 하단 업무 안내`라는 공통 정보 위계를 사용한다.
  - 하단 안내는 짧고 완결된 업무 설명으로 통일한다. 예를 들어 `창고와 부서 간 재고를 이동합니다.`처럼 업무 대상과 행동을 바로 이해할 수 있게 한다.
  - 출하의 미처리 건수처럼 실제 운영량을 나타내는 배지는 계속 표시하되, 의미 없는 수치를 입출고·불량 카드에 새로 만들지 않는다.
  - 입출고의 현재 선택 강조, 출하·불량의 즉시 진입 동작, 역할별 카드 노출은 기존 의미와 동작을 유지한다.
- 구현 방향:
  - 세 진입 화면의 카드 레이아웃을 공통 카드 골격(제목 행의 아이콘·제목 정렬, 선택적 우측 배지의 고정 위치, 하단 설명 기준선, 동일한 카드 여백·타이포 스케일)으로 맞춘다.
  - 새 색 체계 대신 `LEGACY_COLORS`와 기존 밝은 카드 표면·22px 안팎 라운드·절제된 강조색을 사용하고, 출하 전용 건수 배지와 입출고 전용 선택 상태는 슬롯으로 보존한다.
  - 카드 설명 문구를 각 업무의 실제 결과와 맞는 완결형 문장으로 정리하고, 권한에 따라 숨겨지는 카드·품목 전환 카드·불량의 바로 처리/격리 목록의 역할이 달라지지 않는지 함께 점검한다.
  - 공통 표현 컴포넌트 추출은 세 화면의 상태·데이터 의존성을 늘리지 않는 범위에서만 검토하며, 공유가 오히려 흐름별 동작을 숨기면 동일한 스타일 규칙을 각 화면에 적용한다.
- 수용 기준:
  - 입출고·출하·불량의 진입 카드에서 아이콘·제목 시작선, 제목 행의 높이, 하단 안내문 시작선, 카드 여백과 타이포 위계가 같은 문법으로 보인다.
  - 안내문은 모든 카드에서 업무 목적을 설명하는 짧은 완결형 문장이고, 제목을 반복하거나 시스템 용어만 나열하지 않는다.
  - 출하 카드의 건수는 우측 상단 보조 정보로 안정적으로 정렬되고, 건수가 없는 입출고·불량 카드의 제목 정렬은 흐트러지지 않는다.
  - 입출고의 선택 상태·출하/불량의 카드 클릭 이동·권한별 카드 노출·품목 전환 카드의 표시 조건이 기존과 동일하게 동작한다.
  - 라이트·다크 모드에서 카드 표면·텍스트·강조색의 대비가 유지되고, 카드의 클릭 영역은 44px 이상이다.
- 브라우저 확인 시나리오:
  - 데스크톱에서 `/mes?tab=warehouse`, `/mes?tab=shipping`, `/mes?tab=defect`를 차례로 열어 첫 진입 카드의 제목 행·하단 안내문·카드 간격을 비교한다.
  - 입출고에서 작업 유형을 바꿔 선택 강조를 확인하고, 출하에서 건수가 있는 카드와 없는 상태를 확인하며, 불량의 세 카드로 각각 진입·뒤로 이동한다.
  - 조립·출하·AS 등 역할이 다른 계정에서 권한별 입출고 카드 및 품목 전환 카드가 기존 조건대로 나타나는지 확인하고, 라이트·다크 모드와 좁은 데스크톱 너비에서 정렬·줄바꿈을 확인한다.
- 우선순위: 중간

## 창고 지도

### 11. 전체화면 제어를 지도 헤더에 통합하고 평면도를 작업 영역에 최대 확장

- 화면/영역: 데스크톱 창고 지도 > 일반 보기의 `전체화면` 버튼, 검색 헤더, 평면도 작업 영역과 앵글·특수 구역 배치 캔버스.
- 증상:
  - `전체화면` 버튼이 지도 카드 위의 독립 행에 있어, 지도 검색·탐색 제어와 분리되어 보이고 세로 공간도 별도로 차지한다.
  - 지도 카드 안의 평면도는 고정 880×300 좌표 캔버스를 맞춰 그리지만, 카드·작업 영역이 넓어져도 캔버스와 앵글 블록이 남는 공간을 충분히 활용하지 못하는 것처럼 보인다.
- 사용자 불편: 전체화면 전환 위치를 찾기 위해 시선이 지도 밖으로 이동하고, 큰 데스크톱에서 실제 창고 배치와 앵글 블록이 작아 보여 지도 화면의 활용감과 가독성이 떨어진다.
- 확정 정책:
  - `전체화면`은 일반 보기의 지도 카드 상단 헤더 오른쪽, 검색 영역과 같은 제어 줄 안에 둔다.
  - 전체화면 전환의 현재 의미(사이드바·상단 바·일반 지도 헤더를 숨기고 Escape로 복귀)는 그대로 유지한다.
  - 일반 보기의 지도 카드와 평면도 스테이지는 상단 바 아래의 사용 가능한 가로·세로 공간을 최대한 사용한다.
  - 앵글·통로·PL 위치를 나타내는 좌표와 비율은 찌그러뜨리거나 잘라내지 않는다. 캔버스는 작업 영역 안에서 비율을 유지한 최대 크기로 확대하고, 그에 맞춰 앵글·특수 구역·입구 표지도 함께 확대한다.
- 구현 방향:
  - `DesktopWarehouseMapTab` 밖의 독립 `전체화면` 버튼을 제거하고, `DesktopWarehouseMapView`의 일반 보기 헤더 우측 행동 영역에 같은 상태 전환 핸들러를 연결한다.
  - 검색창의 중앙 정렬과 드릴다운 뒤로가기·경로 표시는 유지하며, 전체화면 버튼이 검색 결과 드롭다운이나 좁은 데스크톱에서 검색 입력을 가리지 않도록 헤더의 좌·중앙·우측 레이아웃을 조정한다.
  - 지도 카드·스테이지·`FloorStage`의 가용 높이 전달 경로를 정리해, 바깥 작업 영역을 채우고 880×300 논리 좌표계를 컨테이너에 비율 유지 최대 맞춤한다.
  - 지도 데이터의 `pos_x`·`pos_y`·폭·높이, 검색 강조·드릴다운·상세 패널·관리자 편집 모드의 박스 이동 흐름은 변경하지 않는다.
- 수용 기준:
  - 일반 창고 지도에서 `전체화면` 버튼은 검색 헤더의 우측 제어 영역에 표시되고, 지도 카드 밖에 별도 버튼 행이 남지 않는다.
  - 버튼을 누르면 기존처럼 창고 지도 전용 전체화면으로 전환되고 Escape와 탭 이동 시 정상 보기로 복귀한다.
  - 일반 보기의 지도 카드와 평면도 스테이지가 상단 바 아래의 남은 영역을 사용하며, 앵글·PL·입구 표지를 포함한 평면도가 현재보다 크게 읽힌다.
  - 확대된 평면도에서도 앵글의 상대 위치·가로세로 비율·통로와 PL의 크기 관계가 보존되고, 캔버스가 잘리거나 불필요한 스크롤바가 생기지 않는다.
  - 품목 검색, 다중 후보 드롭다운, 검색 결과 강조·위치 칩, 앵글/칸 드릴다운, 상세 패널과 관리자 편집 기능이 기존처럼 동작한다.
- 브라우저 확인 시나리오:
  - 데스크톱에서 `/mes?tab=warehouseMap`을 열어 검색 헤더 오른쪽의 `전체화면` 버튼 위치와 지도 카드의 남는 공간을 확인한다.
  - 버튼을 눌러 전체화면으로 전환하고 Escape로 복귀한 뒤, 상단 바·사이드바·검색 헤더의 표시 상태가 기존 규칙과 같은지 확인한다.
  - 넓은 데스크톱과 좁은 데스크톱에서 평면도·앵글·PL·입구가 작업 영역을 최대 활용하면서도 찌그러지거나 잘리지 않는지 확인한다.
  - 품목을 검색해 위치 칩을 선택하고 앵글·칸을 차례로 열어 뒤로가기·상세 패널을 확인한다. 창고 관리자 계정에서는 편집 모드의 박스 이동·추가·제거도 확인한다.
- 우선순위: 중간
