## 조립 체크리스트 관리

### 1. 박스 이름 변경

- 화면/영역: 모바일 > 체크리스트 > 관리 > 제품 상세의 각 박스 제목. 예: `기본 항목`, `전원 OFF`, `전원 ON`.
- 증상: 박스를 추가할 때만 이름을 입력할 수 있고, 기존 박스 제목은 표시만 되어 수정할 수 없다.
- 사용자 불편: 기본값 또는 오탈자가 있는 박스 이름을 바로잡으려면 박스를 새로 만들고 항목을 다시 구성해야 한다.
- 확정 정책: 모든 기존 박스의 이름을 모바일 관리 화면에서 변경할 수 있다. PC 화면은 변경하지 않는다.
- 구현 방향: 박스 제목 옆에 편집 진입점을 두고, 빈 문자열·공백 제목은 막는 박스명 변경 API를 추가한다. 저장 성공 시 최신 전체 체크리스트 응답으로 화면을 갱신한다.
- 수용 기준:
  - `기본 항목`을 포함한 모든 박스 제목을 수정·저장할 수 있다.
  - 빈 제목은 저장되지 않고 기존 제목이 유지된다.
  - 저장 직후 관리·일반 열람 화면에 새 이름이 반영된다.
  - 다른 박스의 항목·순서, PC 화면, 하단 탭 바는 변경되지 않는다.
- 브라우저 확인 시나리오: 관리 화면에서 `기본 항목`의 이름을 변경하고 저장한다. 목록을 나갔다 다시 들어가 일반 열람 화면에도 새 제목이 유지되는지 확인한다.
- 우선순위: 높음

### 2. 항목 삭제 실동작 재검증과 실패 상태 처리

- 화면/영역: 모바일 > 체크리스트 > 관리 > 제품 상세의 각 항목 삭제 버튼.
- 증상: 사용자가 삭제가 잘 되지 않는다고 보고했다. 현재 브라우저에서는 확인 창 표시는 재현했지만, 브라우저 기본 창 때문에 삭제 확정 뒤 목록 갱신까지 확인하지 못했다.
- 사용자 불편: 불필요하거나 잘못 입력한 항목을 제거했는지 확신할 수 없고, 실패해도 이유를 바로 알기 어렵다.
- 확정 정책: 삭제 확정 후 해당 항목은 즉시 목록에서 사라지고, 같은 박스의 번호는 연속으로 다시 매겨진다. 실패 시 현재 화면에 오류를 표시한다.
- 구현 방향: 삭제 요청의 최신 전체 체크리스트 응답을 단일 화면 상태로 반영하고, 삭제 중에는 중복 요청을 막는다. 자동화 테스트와 브라우저 재검증으로 요청·응답·목록 갱신을 분리해 확인한다.
- 수용 기준:
  - 취소하면 삭제 API 호출과 목록 변경이 없다.
  - 삭제를 확정하면 대상 항목만 사라지고 남은 항목의 번호가 연속된다.
  - 네트워크·서버 실패 시 대상 항목은 남고 오류 문구가 보인다.
  - 같은 항목을 빠르게 여러 번 눌러도 중복 삭제 요청이 발생하지 않는다.
- 브라우저 확인 시나리오: 사용자 지정 삭제 가능 항목에서 취소와 확정을 각각 확인한다. 확정 뒤 목록에서 항목이 사라지고, 새로고침 후에도 삭제 상태와 번호가 유지되는지 확인한다.
- 우선순위: 높음

### 3. 항목을 다른 박스로 직접 이동

- 화면/영역: 모바일 > 체크리스트 > 관리 > 제품 상세의 항목 순서 변경 핸들과 박스 목록.
- 증상: 현재 드래그는 같은 박스 안의 순서만 바꿀 수 있어, 항목을 다른 박스로 옮기려면 삭제 후 다시 입력해야 한다.
- 사용자 불편: 전원 OFF/전원 ON 등 박스를 잘못 선택한 항목을 고칠 때 내용·순서를 다시 입력해야 한다.
- 확정 정책: 항목의 드래그 핸들을 잡아 다른 박스의 원하는 위치에 놓으면 바로 이동한다.
- 구현 방향: 현재 포인터 기반 드래그 흐름을 확장해 출발·도착 박스와 도착 순서를 한 번에 저장하는 API를 추가한다. 성공 응답은 최신 전체 체크리스트이며, 출발·도착 박스의 항목 번호를 모두 연속으로 다시 매긴다.
- 수용 기준:
  - 한 항목을 다른 박스로 옮길 수 있고 항목 내용은 바뀌지 않는다.
  - 도착 박스에서 의도한 위치에 들어가며, 출발·도착 박스의 번호가 모두 연속된다.
  - 같은 박스 내 기존 순서 변경은 계속 동작한다.
  - 존재하지 않는 대상 박스 또는 잘못된 항목 조합은 저장되지 않는다.
- 브라우저 확인 시나리오: 전원 OFF의 항목 하나를 전원 ON의 중간 위치로 이동한다. 두 박스의 순서·번호를 확인하고, 새로고침 뒤에도 유지되는지 확인한다.
- 우선순위: 중간

### 4. 삭제 확인을 앱 공통 시스템 팝업으로 교체

- 화면/영역: 모바일 > 체크리스트 > 관리 > 제품 상세의 항목 삭제 확인.
- 증상: 항목 삭제 시 브라우저 기본 알림이 떠서 앱 화면과 분리되고 자동화·모바일 조작 흐름을 막는다.
- 사용자 불편: 확인 창의 모양과 동작이 DEXCOWIN MES 화면과 다르고, 브라우저별 경험 차이도 생긴다.
- 확정 정책: 브라우저 기본 알림 대신 앱 안의 공통 시스템 확인 팝업을 사용한다.
- 구현 방향: `window.confirm`을 제거하고 기존 `ConfirmModal`을 위험 동작 톤으로 연결한다. 취소·배경 닫기·ESC는 삭제하지 않고, 삭제 중에는 확인 버튼을 잠근다.
- 수용 기준:
  - 삭제 버튼을 눌러도 브라우저 기본 알림이 뜨지 않는다.
  - 앱 시스템 팝업에 삭제 대상과 취소·삭제 선택지가 보인다.
  - 취소·ESC·배경 닫기는 항목을 유지하고, 삭제는 한 번만 요청된다.
  - 모바일 다른 화면과 PC 화면에는 영향을 주지 않는다.
- 브라우저 확인 시나리오: 항목 삭제 버튼을 눌러 앱 내부 팝업만 표시되는지 확인한다. 취소·배경 닫기·삭제 중 상태를 각각 확인하고, 확정은 사용자 지정 삭제 가능 항목에서 2번 TODO와 함께 검증한다.
- 우선순위: 높음
