## 공통

### 1. 브라우저 뒤로가기 탐색 상태를 필요한 화면 흐름에 맞게 보존

- 화면/영역: 관리자 > BOM 관리의 부모 품목 선택·사용처·편집 전환, 그리고 내부 화면 전환이 있는 다른 탭.
- 증상: 사용처에서 품목을 눌러 BOM 편집으로 이동하거나 편집 중 다른 BOM을 선택해도 브라우저 히스토리에 상태가 쌓이지 않아 뒤로가기로 직전 컨텍스트를 복원할 수 없다.
- 사용자 불편: 사용처에서 보던 품목과 BOM 선택 맥락을 잃고, 다시 목록·사용처를 찾아야 한다.
- 확정 정책: 사용처 → 특정 품목 편집, 편집 중 BOM 선택 변경은 각각 브라우저 뒤로가기로 한 단계씩 되돌아가야 한다. 뒤로가기는 탭 이동·저장·삭제 같은 데이터 변경을 되돌리지 않고 화면 선택 상태만 복원한다.
- 구현 방향: BOM 워크벤치의 `mode`, `parentId`, 필요 시 부서·필터를 명시적인 history state로 push/restore하고 popstate 처리 중 재적재를 막는다. 이어서 내부 상태 전환을 가진 탭을 전수 점검해, 사용자가 명시적으로 한 화면 전환인데도 뒤로가기로 복원되지 않는 흐름만 같은 원칙으로 보완한다. 이미 동작하는 부적합품 히스토리는 회귀 기준으로 사용한다.
- 수용 기준:
  - 사용처에서 품목 A를 열어 편집으로 간 뒤 뒤로가기를 하면 품목 A의 사용처 화면으로 복원된다.
  - 편집에서 A → B를 선택한 뒤 뒤로가기를 하면 A 편집 상태로 복원되고, 다시 뒤로가기를 하면 직전 사용처 또는 목록 상태로 복원된다.
  - 앞으로가기, 탭 전환 후 복귀, 새로고침에서도 잘못된 루프·중복 push·선택 불일치가 없다.
  - 전수 점검 결과는 적용/미적용 화면, 근거 파일·줄, 의도적으로 미적용한 사유를 남긴다.
- 브라우저 확인 시나리오: 관리자 PIN 해제 후 BOM 편집과 사용처를 왕복하고, 브라우저 뒤로/앞으로 버튼과 새로고침을 각각 실행한다. 부적합품의 허브·목록·처리 화면도 기존 뒤로가기 동작이 유지되는지 확인한다.
- 우선순위: 높음.

## 설정

### 2. PIN 재설정과 알림 설정을 설정 탭 팝업으로 통합하고 설정 동선을 재구성

- 화면/영역: 데스크톱 상단바, 설정 탭의 설정 팝업.
- 증상: PIN 변경은 상단바에서 별도 모달로 열리고 알림은 상단 벨 중심으로 접근되어, 개인 설정이 한곳에 모여 있지 않다.
- 사용자 불편: 설정을 바꾸려면 상단바의 서로 다른 진입점을 기억해야 하며, 설정 화면의 역할이 불분명하다.
- 확정 정책: PIN 재설정과 알림 설정의 진입·편집 UI를 설정 탭 팝업으로 옮긴다. 알림 벨은 수신함/읽음 처리 기능을 유지하되 개인 알림 설정의 편집 진입점으로 쓰지 않는다.
- 구현 방향: 현재 설정 탭과 `AppearanceSettingsModal`의 실제 렌더 경로를 확인해 팝업 내 섹션을 재구성하고, PIN 변경 API·검증·성공 피드백 및 로그인 알림 팝업 설정을 이관한다. 상단바에서 중복된 설정 진입 UI와 상태를 제거하되 수신 알림 패널 동작은 보존한다.
- 수용 기준:
  - 설정 탭 팝업에서 현재 PIN, 새 PIN, 확인 PIN을 검증해 PIN을 변경할 수 있다.
  - 설정 탭 팝업에서 개인 알림 표시 설정을 확인·변경할 수 있고 다음 로그인/수신 흐름에 반영된다.
  - 상단바에는 알림 수신함 기능만 남고 PIN 변경·알림 설정의 중복 진입점이 없다.
  - 팝업 닫기, 저장 중 중복 실행 방지, 성공·오류 피드백과 키보드 접근성이 기존 수준으로 유지된다.
- 브라우저 확인 시나리오: 설정 탭을 열어 PIN 불일치·정상 변경을 각각 확인하고, 알림 설정을 바꾼 뒤 새로고침·재로그인 후 반영 여부와 알림 벨의 읽음/이동 동작을 확인한다.
- 우선순위: 중간.

## 부적합품

### 3. 부적합품 데이터를 관리자 내보내기 체계에 적용

- 화면/영역: 부적합품 탭, 관리자 > 내보내기.
- 증상: 부적합품 관련 데이터가 현재 관리자 내보내기 대상·형식에 어떻게 포함되는지 일관된 확인 경로가 없다.
- 사용자 불편: 현장 부적합품 처리 이력을 별도 수작업 없이 필요한 형식으로 반출하기 어렵다.
- 정책 확인 필요: 부적합품을 기존 전체 Excel·선택 CSV에 포함할지, 부적합품 전용 CSV/XLSX를 추가할지, 그리고 포함할 기간·부서·상태·개인정보 열을 확정한다.
- 구현 방향: 기존 F705/F704 내보내기 구조, 부적합품 API 데이터 모델, 권한·감사 로그를 대조해 선택된 정책에 맞는 최소 범위의 내보내기 경로와 열 정의를 추가한다. 화면의 필터·정렬과 파일 데이터의 기준이 어긋나지 않게 한다.
- 수용 기준:
  - 확정된 형식에서 부적합품 식별, 품목, 수량, 발생 위치/부서, 상태, 시각, 필요한 처리 정보를 누락 없이 내보낸다.
  - 화면 필터 조건과 파일 행 범위가 일치하며, 데이터 없음·권한 없음·생성 실패 상태가 명확하다.
  - 기존 일반 내보내기, 감사 CSV/XLSX, 다운로드 이력에 회귀가 없다.
- 브라우저 확인 시나리오: 서로 다른 부서·상태의 부적합품을 준비해 관리자 내보내기를 실행하고 다운로드 파일의 열·행·필터 결과를 확인한다. 권한 없는 상태와 데이터 없는 조건도 확인한다.
- 우선순위: 높음.

- 구현 방향: 모델 슬롯 생성·정렬·삭제·이동 규칙, DB 제약, API·프런트엔드·출력물에서 코드가 쓰이는 위치를 실제 검색·이력으로 추적한다. 코드가 안정 식별자인지 표시용 번호인지와 재사용·변경 정책을 근거와 함께 정리하고, 확정된 공개 위치에만 짧게 설명을 제공한다.
- 수용 기준:
  - 코드의 생성 규칙, 예시, 변경/재사용 가능 여부, 업무상 의미를 근거 파일·줄과 함께 설명할 수 있다.

  - 설명을 화면에 노출하기로 했다면 모델 관리에서 과도한 정보 없이 확인 가능하고, 현행 코드/데이터 동작은 바뀌지 않는다.

### 5. BOM 수량 표기를 `X1EA`가 아닌 `1EA`로 바꾸고 가운데 정렬 복원

- 화면/영역: BOM 구성 행·카드에서 수량을 표시하는 모든 데스크톱/모바일 문맥.
- 증상: 수량 앞에 불필요한 `X`가 붙어 `X1EA`로 보이며, 수정 후 가운데 정렬이 무너질 수 있다.
- 사용자 불편: 수량 표기가 읽기 어색하고 목록 정렬이 흔들려 스캔 속도가 떨어진다.
- 확정 정책: 단위가 있는 BOM 수량은 `1EA` 형식으로 표시하고 해당 수량 셀/배지는 기존 의도대로 가운데 정렬한다. 곱셈 의미가 실제로 필요한 별도 문맥은 변경하지 않는다.
- 구현 방향: BOM 표시 전용 formatter와 렌더 지점을 검색해 `X` 접두어가 단순 수량 장식인 경우에만 제거하고, 수량 컨테이너의 정렬 규칙을 통일한다. 동일 formatter를 쓰는 비-BOM 화면은 시각·업무 의미를 확인한 뒤 영향 범위를 결정한다.
- 수용 기준:
  - BOM의 정수·소수 수량이 각각 `1EA`, `1.5EA`처럼 표시되고 `X`가 붙지 않는다.
  - 수량 열/배지는 품목명 길이·수량 자리수와 관계없이 시각적으로 가운데 정렬된다.
  - 단위 없음, 0, 큰 수량, 모바일 BOM 보기에서 회귀가 없다.
- 브라우저 확인 시나리오: 관리자 BOM 편집, 재고 상세 BOM 보기, 출하 BOM 구성에서 1·복수·소수 수량을 비교하고 데스크톱/모바일 폭에서 정렬을 확인한다.
- 우선순위: 낮음.

## 입출고

### 6. 기준 수량 number input을 증감 화살표까지 고려해 시각적 중앙에 맞춤

- 화면/영역: 입출고 > 기준 수량 입력(`QuantityStepper`).
- 증상: number input의 브라우저 기본 증감 화살표가 우측 공간을 차지해 `text-center`만 적용하면 숫자가 화면상 왼쪽으로 치우쳐 보인다.
- 사용자 불편: 기준 수량이 버튼·입력창 가운데에 놓이지 않아 빠르게 수치를 확인하기 어렵다.
- 확정 정책: 브라우저 number spin button을 유지하는 환경에서도 숫자가 입력 상자 시각 중심에 가깝게 보이도록 보정한다. 화살표의 조작 가능성과 키보드 입력은 유지한다.
- 구현 방향: 실제 대상 브라우저에서 spin button의 점유 폭을 확인한 뒤 input의 text alignment·padding·appearance 규칙을 최소 조정한다. 공용 `QuantityStepper` 변경이 다른 수량 입력에 미치는 영향을 확인하고 필요한 경우 기준 수량 문맥에만 제한한다.
- 수용 기준:
  - 기준 수량 숫자가 증감 화살표를 포함한 입력 상자에서 시각적으로 중앙에 놓인다.
  - 마우스 화살표, 키보드 증감, 직접 입력, 최소값 보정, 모바일 44px 터치 영역이 유지된다.
  - 공용 수량 입력을 공유하는 다른 화면에서 의도하지 않은 정렬 변화가 없다.
- 브라우저 확인 시나리오: Chrome/프로젝트 지원 브라우저에서 1·10·1000·소수 입력과 위/아래 화살표를 확인하고, 입고·출고·공정 흐름 및 모바일 폭에서 동작을 비교한다.
- 우선순위: 중간.

## 대시보드

### 7. 우측 카드의 BOM 구성 보기 화면을 용도 중심으로 최적화·재구성

- 화면/영역: 대시보드 우측 재고 상세 카드에서 여는 BOM 구성 보기.
- 증상: BOM 구성 보기의 정보 밀도·스크롤·선택 흐름이 우측 카드에서 빠르게 구성품을 확인하려는 목적에 비해 비효율적이다.
- 사용자 불편: 품목 구성과 수량을 한눈에 파악하기 어렵고 상세 확인을 위해 불필요한 스크롤·시선 이동이 생긴다.
- 정책 확인 필요: 재구성의 우선 목적을 빠른 요약(직계 구성품)으로 둘지, 전체 계층 탐색까지 포함할지와 우측 카드에서 유지할 필수 열·행 수를 확정한다.
- 구현 방향: `BomDetailModal`의 실제 데이터 구조와 열·계층·스크롤을 측정하고, 우측 카드 폭에서 가장 빈번한 확인 작업을 우선 배치한다. 제목·부모 품목·구성품 수·수량·단위·하위 진입의 위계를 재정리하되 데이터 의미, 접근성, 기존 닫기/선택 동작은 보존한다.
- 수용 기준:
  - 우측 카드에서 현재 품목과 직계 BOM 구성품·수량을 첫 화면에서 빠르게 비교할 수 있다.
  - 긴 이름·다수 구성품·빈 BOM·하위 BOM에서 줄바꿈, 스크롤, 빈 상태가 안정적이다.
  - 구성품 선택/하위 진입, 닫기, 키보드 포커스와 화면 갱신이 기존 데이터 의미를 유지한다.
- 브라우저 확인 시나리오: 대시보드 우측 카드에서 구성품 0개·소수·다수·하위 BOM이 있는 품목을 각각 열어 데스크톱 폭과 좁은 폭에서 첫 화면 정보, 스크롤, 하위 진입·복귀를 확인한다.
- 우선순위: 높음.
