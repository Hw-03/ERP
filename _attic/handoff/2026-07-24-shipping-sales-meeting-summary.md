# 출하 기능 개선 반영 내용

> 영업부 미팅 후 개발 반영본 · 2026-07-24
> 실제 배포 전, 업무 흐름과 문구를 함께 확인하기 위한 문서입니다.

## 한눈에 보기

| 항목 | 반영 내용 | 상태 |
|---|---|---|
| 인보이스 번호 | PF를 고르기 전에 입력하며, 번호가 없으면 비워 두고 시작 가능 | 개발 반영 완료 |
| 준비 완료 조건 | 요청·사전 준비는 가능하지만 `준비 완료` 전에는 인보이스 필수 | 개발 반영 완료 |
| 요청 수정 이력 | 누가, 언제, 무엇을 어떻게 바꿨는지 기록 | 개발 반영 완료 |
| 모바일 변경 안내 | 준비 목록이 바뀌면 `수정됨`과 변경 내용을 계속 표시 | 개발 반영 완료 |
| 중요 품목 강조 | 품목에서 설정하고 출하 작성 화면에서 `영업 확인`으로 강조 | 개발 반영 완료 |
| 출하 이력 찾기 | 완료·취소 이력을 연도·월별로 보고 인보이스·PF 품명으로 검색 | 개발 반영 완료 |

## 앞으로의 출하 요청 흐름

1. 출하 요청을 시작합니다.
2. 인보이스 번호를 입력합니다.
   - 아직 번호가 나오지 않았다면 비워 두어도 됩니다.
3. PF를 선택하고 BOM, 동반품, 수량을 확인합니다.
4. 요청을 저장하고 출하 준비를 시작합니다.
5. 준비 중 요청이 수정되면 모바일 카드에 `수정됨`이 표시됩니다.
6. 인보이스 번호가 입력된 뒤에만 `준비 완료` 처리할 수 있습니다.

## 1. 인보이스 번호

- 새 요청의 첫 화면에서 PF보다 먼저 보입니다.
- 번호 없이 요청을 만들고 준비 중까지 진행할 수 있습니다.
- 요청 상세에서 나중에 번호를 입력하거나 오타를 정정할 수 있습니다.
- 입력값은 앞뒤 공백을 없애고 영문을 대문자로 저장합니다.
- 같은 번호는 취소된 요청을 포함해 다른 출하 요청에서 다시 사용할 수 없습니다.
- 한 번이라도 준비 완료된 요청은 번호를 다른 값으로 고칠 수는 있지만, 다시 빈칸으로 만들 수는 없습니다.
- 인보이스가 없는 준비 중 요청은 `준비 완료` 버튼과 안내 문구에서 입력 필요 여부를 바로 알 수 있습니다.

## 2. 요청 수정 이력과 모바일 안내

### PC에서 확인하는 내용

- 수정한 사람
- 수정 날짜와 시각
- 변경된 항목
- 변경 전 내용과 변경 후 내용

수량, 품명, 메모, BOM 구성, 동반 출하품, 인보이스 번호 등의 실제 값이 달라졌을 때만 한 건의 수정 이력을 남깁니다.

### 모바일 작업자에게 보이는 내용

- 준비 중 카드의 `수정됨` 표시
- 마지막 수정자와 수정 시각
- `출하 수량 · BOM 구성 수정`처럼 읽기 쉬운 한 줄 요약
- 펼쳐서 보는 품목 추가·삭제·수량·포함/제외 변경 내용

모바일은 출하 화면을 열 때와 앱으로 돌아올 때 즉시 최신 목록을 확인하고, 화면을 보고 있는 동안에는 30초마다 갱신합니다. 인보이스나 요청자만 바뀐 경우에는 준비 작업 변경으로 표시하지 않습니다.

### 체크리스트는 그대로 사용합니다

- 요청이 수정됐다는 이유로 체크리스트 전체를 자동 초기화하지 않습니다.
- 기존처럼 품목별로 체크하거나 해제할 수 있습니다.
- 필요하면 `전체 해제`를 사용합니다.

핵심은 체크 방식을 바꾸는 것이 아니라, **원래 보던 준비 목록이 바뀌었다는 사실을 바로 알리는 것**입니다.

## 3. 영업부 확인이 필요한 중요 품목

설정 위치는 아래로 확정했습니다.

> **PC 관리 > 품목 관리 > 기본 정보 > 영업 확인 필요**

- 한 번 설정하면 새 출하 요청에서 같은 기준으로 표시됩니다.
- 출하 작성 2단계와 5단계에서 주황색 계열 배경·테두리로 강조합니다.
- 색상과 함께 `영업 확인` 문구를 표시합니다.
- 기존 공정 코드 색상과 최종 검토 화면의 카드 크기·스크롤 방식은 그대로 유지합니다.

## 4. 출하 이력 찾기

- `출하 완료`와 `요청 취소`를 나누어 볼 수 있습니다.
- 연도 > 월 순서의 폴더처럼 접고 펼칠 수 있습니다.
- 월마다 건수를 함께 표시합니다.
- 인보이스 번호 또는 PF 품명 일부로 검색할 수 있습니다.
- 결과가 많으면 50건씩 이어서 불러옵니다.
- 완료 건은 픽업 완료일, 취소 건은 요청 취소일을 기준으로 월을 나눕니다.

별도의 출고처 입력란은 만들지 않았습니다. 현재 업무 기준대로 **PF 품명으로 출고처를 찾습니다.**

## 확정된 운영 원칙

- 출하 요청은 영업부가 기본적으로 담당합니다.
- 시스템상 부서를 제한하지 않으므로 필요한 경우 다른 부서도 요청을 만들거나 수정할 수 있습니다.
- 수정할 때는 실제 로그인한 활성 직원의 이름으로 기록합니다.
- 취소 요청은 삭제하지 않고 취소자·취소 시각·기존 수정 이력과 함께 보존합니다.
- 모바일의 `수정됨`은 별도 확인 버튼 없이 요청이 `준비 중`인 동안 계속 보입니다.
- 실시간 알림이나 체크리스트 전건 완료 조건은 이번 범위에 추가하지 않았습니다.
