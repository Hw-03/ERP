### 7. 요청 상세 구성품 카드의 내용만큼 세로 확장

- 화면/영역: PC 출하 > 요청 상세 > `PA 구성품`·`PF 구성품`·`카톤·동반 출하품` 3개 카드
- 증상: 각 카드가 상세 화면의 남은 높이에 고정되어 있고, 항목이 많아지면 카드 내부 목록만 세로 스크롤된다.
- 사용자 불편: 구성품 전체를 보려면 카드마다 따로 스크롤해야 하며, 요청 전체를 한 번에 검토할 수 없다.
- 확정 정책: 세 카드와 요청 상세 컨테이너가 항목 수만큼 자연스럽게 늘어나도록 하며, 구성품 목록의 내부 세로 스크롤을 제거한다.
- 구현 방향: 요청 상세의 고정 높이·`min-h-0`·`flex-1` 제약과 목록의 `overflow-y-auto`를 이 화면 범위에서 해제하고, 하단 작업 버튼이 모든 구성품 다음에 흐르도록 조정한다.
- 수용 기준: PA·PF·카톤·동반 출하품 각각에 다수 항목이 있어도 모든 행이 바로 보이고, 세 카드 안에는 별도 세로 스크롤바가 없다.
- 브라우저 확인 시나리오: 구성품이 충분히 많은 준비 중 요청을 열고, 페이지를 아래로 스크롤해 모든 구성품을 확인한 뒤 `준비 완료`·`요청 취소` 버튼이 구성품 요약 다음에 표시되는지 확인한다.
- 우선순위: 높음

### 8. 요청 메모를 하단 작업 영역 왼쪽으로 이동

- 화면/영역: PC 출하 > 요청 상세 > `요청 메모`
- 증상: 요청 메모가 헤더 바로 아래에 표시되어, 하단 작업 영역의 왼쪽 빈 공간을 활용하지 못한다.
- 사용자 불편: 출하 준비자가 구성품을 검토하는 흐름에서 메모와 실제 작업 버튼의 연결이 약하고, 상단 정보 밀도가 불필요하게 높다.
- 확정 정책: 요청 메모는 PA/PF/카톤·동반 출하품 요약 다음의 하단 작업 영역 왼쪽에 표시하고, `수정`·`요청 취소`·`준비 완료` 등 작업 버튼은 같은 영역의 오른쪽에 둔다. 메모가 없으면 메모 영역은 표시하지 않는다.
- 구현 방향: 요청 상세의 상단 메모 렌더링을 제거하고, 하단 작업 컨테이너를 좌측 메모·우측 버튼 묶음 구조로 바꾼다. 기존 메모 카드 스타일과 내용은 유지한다.
- 수용 기준: 메모가 있는 요청에서는 모든 구성품 카드 다음의 하단 작업 영역에서 메모가 왼쪽, 작업 버튼이 오른쪽에 함께 보인다. 메모가 없는 요청에는 빈 메모 카드나 불필요한 여백을 만들지 않는다.
- 브라우저 확인 시나리오: 메모가 있는 요청과 없는 요청을 각각 열어, 메모가 하단 작업 영역의 왼쪽에 표시되고 버튼이 오른쪽에 유지되는지, 반응형 폭에서도 내용과 버튼이 겹치지 않는지 확인한다.
- 우선순위: 중간

### 9. 수정 이력의 BOM·동반 출하품 변경을 카드 목록으로 표시

- 화면/영역: PC 출하 > 요청 상세 > `수정 이력` > BOM 구성 또는 동반 출하품 변경 이력 펼침
- 증상: 펼친 변경값이 긴 원시 문자열로 이어져 PA·PF·동반 출하품의 품목 경계, 품명, 코드, 수량을 빠르게 구분할 수 없다.
- 사용자 불편: 사람이 검토할 수 없는 밀도의 문장이 되어 어떤 구성품이 어떻게 바뀌었는지 확인하기 어렵다.
- 확정 정책: BOM·동반 출하품 변경은 변경 전·후를 검산할 수 있도록 PA·PF·카톤·동반 출하품별로 나누고, 각 품목을 출하 작성 2단계와 같은 카드형 목록(품명, MES 코드, 수량)으로 보여 준다. 변경된 상태(추가·제외·수량 변경)는 각 행에서 식별 가능해야 한다.
- 구현 방향: 수정 이력의 BOM/동반 출하품 값 전용 렌더러를 두어 JSON/문자열 직렬화 결과를 그대로 출력하지 않고, 현재 출하 작성 화면의 구성품 카드 문법을 재사용하거나 같은 정보 구조로 표현한다.
- 수용 기준: 항목이 많은 BOM 수정 이력을 펼쳐도 줄글이 나오지 않고, 그룹·품목·코드·수량·변경 상태를 스크롤 없이 행 단위로 식별할 수 있다. 비-BOM 필드 이력의 기존 표시 방식은 유지한다.
- 브라우저 확인 시나리오: PA와 PF 구성품, 동반 출하품에 추가·제외·수량 변경이 섞인 요청을 수정한 뒤 이력을 펼쳐, 변경 전후와 각 변경 상태가 카드별로 명확히 구분되는지 확인한다.
- 우선순위: 높음

### 10. 출하 완료 이력 상단에 완제품 SN·취소 동작 통합

- 화면/영역: PC 출하 > 출하 상세 이력 > 픽업 완료 요청의 상단 정보 영역
- 증상: `완제품 SN`은 제목·인보이스·수정 이력 아래의 전체폭 안내 박스로 떨어져 있고, `픽업 완료 취소`도 별도 행에 있어 상단과 요약 카드 사이에 큰 빈 공간이 생긴다. 우측 `픽업 완료` 상태 배지는 제목 행에서 세로 가운데에 맞지 않는다.
- 사용자 불편: 이미 확정된 출하의 핵심 식별 정보와 취소 동작이 분산되어 있으며, 불필요한 세로 공간 때문에 최종 PA/PF·입출고 로그와 구성품 요약이 아래로 밀린다.
- 확정 정책: 픽업 완료 요청에서는 제목 행을 좌측 출하 품목, 중앙 완제품 SN 독립 카드, 우측 상태 배지와 `픽업 완료 취소` 버튼으로 구성한다. 상태 배지와 취소 버튼은 제목 행의 세로 가운데에 정렬한다. 기존 전체폭 완제품 SN 박스와 별도 취소 버튼 행은 제거한다. SN이 없을 때는 빈 SN 카드를 만들지 않는다.
- 구현 방향: 출하 이력 상세의 상단 행에서 완제품 SN과 픽업 완료 취소 동작을 조건부 렌더링하고, 상태·동작 묶음에 가운데 정렬을 적용한다. 기존의 SN `Notice`와 별도 액션 컨테이너는 이력 화면에서만 제거해 아래 요약·구성품 영역이 즉시 위로 올라오게 한다.
- 수용 기준: 픽업 완료 이력에서 제목, 완제품 SN, 상태·취소 버튼이 한 행에 배치되고, 그 다음에는 인보이스·수정 이력과 최종 PA/PF·입출고 로그·구성품 요약이 빈 행 없이 이어진다. SN이 없는 이력과 취소 이력에서는 비어 있는 중앙 카드나 취소 버튼을 표시하지 않는다.
- 브라우저 확인 시나리오: SN이 있는 픽업 완료 이력, SN이 없는 픽업 완료 이력, 취소 이력을 각각 열어 상단 카드의 조건부 표시, 상태·버튼의 세로 정렬, 기존 전체폭 SN/별도 취소 행 제거, 아래 요약 카드의 상향 배치를 확인한다.
- 우선순위: 중간
