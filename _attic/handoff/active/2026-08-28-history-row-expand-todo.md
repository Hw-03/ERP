### 2. [완료] BOM 팝업 헤더에 현재 재고와 추가 생산 가능 수량 나란히 표시
- 완료일: 2026-08-28
- 구현 결과: BOM 트리 루트 응답에 선택적 `additional_producible_quantity`를 추가하고, 기존 생산 가능 계산의 가용재고·다단계·공유 구성품·제외 품목 정책을 재사용해 루트 기존 재고를 제외한 순수 추가 생산분을 반환한다. 팝업 헤더는 `현재 재고 → 추가 생산 가능 → 모두 펼치기 → 모두 접기 → 닫기` 순서로 고정했으며 `0`과 계산 불가를 구분하고 품목 전환·실시간 갱신 시 이전 값을 남기지 않는다.
- 검증 근거: 백엔드 관련 테스트 32개, 프론트엔드 관련 테스트 47개, `lint:strict` 통과. 인앱 브라우저의 `COCOON TOP BODY ASS'Y (S)` BOM 팝업에서 `현재 재고 71 EA`와 `추가 생산 가능 81 EA`의 위치·순서·보라색 강조·헤더 고정 배치를 확인했다.
- 화면/영역: PC `대시보드` 탭의 품목 상세에서 여는 `BOM 구성 보기` 팝업 헤더.
- 증상: 현재 헤더 우측에는 `현재 재고 N EA` 배지 뒤로 `모두 펼치기`, `모두 접기`, 닫기 버튼이 이어지고, BOM 구성품 재고로 해당 품목을 몇 개 더 생산할 수 있는지는 표시하지 않는다.
- 사용자 불편: 현재 완제품 보유량과 구성품 기준 추가 생산 여력을 한눈에 비교할 수 없어, 사용자가 구성품별 소요량과 재고를 직접 계산해야 한다.
- 확정 정책: `현재 재고 N EA` 배지를 사용자가 표시한 왼쪽 여유 공간으로 옮기고, 원래 배지 자리에는 `추가 생산 가능 N EA`를 표시한다. 헤더 우측의 최종 순서는 `현재 재고` → `추가 생산 가능` → `모두 펼치기` → `모두 접기` → `닫기`가 되며, 두 수량 배지는 현재 팝업의 둥근 배지 스타일·숫자 정렬·단위를 유지한다.
- 정책 확인 필요: `추가 생산 가능`을 공식 생산 가능 수량과 같은 가용재고(예약 차감) 기준으로 계산할지, 팝업 표에 표시되는 현재 정상재고 기준으로 계산할지 결정해야 한다. 권장안은 대시보드 전체의 의미 정합성을 위해 가용재고 기준을 사용하는 것이다.
- 구현 방향: 헤더 배지 재배치는 `BomDetailModal`의 기존 flex 구조 안에서 최소 변경으로 처리한다. 생산 가능 수량은 프론트에서 화면에 보이는 행을 임의 합산하지 않고, 확정된 재고 기준으로 백엔드가 다단계 BOM과 공유 구성품을 한 번만 반영해 루트 품목의 **기존 완제품 재고를 제외한 추가 생산분**을 반환하도록 한다. 기존 생산 가능 계산의 순수 로직을 재사용하거나 동일 계약의 공용 계산 경계를 두고, BOM 트리 응답에는 팝업이 직접 표시할 명시적 필드를 제공한다.
- 수용 기준:
  - BOM 트리 로드가 끝나면 헤더에 `현재 재고 N <단위>`와 `추가 생산 가능 N <단위>`가 동시에 보인다.
  - `현재 재고`는 사용자 표시 위치처럼 품목 식별 정보와 우측 액션 사이의 왼쪽 여유 공간에 놓이고, `추가 생산 가능`은 기존 `현재 재고` 자리에서 펼치기 버튼 바로 앞에 놓인다.
  - 추가 생산 가능 수량은 현재 루트 품목 재고를 더하지 않은 순수 추가 생산분이며, 값이 0이어도 배지를 숨기지 않고 `0 <단위>`로 표시한다.
  - 다단계 BOM에서는 하위 단계 재고까지 반영하고, 여러 경로에서 공유하는 구성품을 중복 사용 가능한 것으로 계산하지 않는다.
  - 생산 가능 계산 제외 품목과 예약 재고의 반영 여부는 확정된 정책과 기존 생산 가능 수량 화면의 계약에 일치한다.
  - 품목을 전환하거나 실시간 재고 갱신이 발생하면 이전 품목의 수량이 잠깐 남지 않고 두 배지가 함께 최신 값으로 갱신된다.
  - BOM 트리를 불러오지 못했거나 계산 근거가 없을 때 `0`으로 꾸며 표시하지 않고 `계산 불가` 상태를 구분한다.
  - 긴 품목명·품목코드에서도 두 배지와 세 액션이 겹치거나 줄바꿈되어 헤더 높이가 흔들리지 않는다.
  - `InventoryDetailPanel`/`BomDetailModal` 테스트에 배지 문구·순서·0·계산 불가·품목 전환 상태가 포함되고, 백엔드 계산 테스트에 소요량, 다단계 BOM, 공유 구성품, 예약 재고 정책 사례가 포함된다.
- 브라우저 확인 시나리오:
  1. `http://localhost:3001/mes?tab=dashboard`에서 BOM이 등록된 품목의 상세를 열고 `하위 구성 보기`를 눌러 팝업을 연다.
  2. 헤더에서 `현재 재고`가 왼쪽으로 이동하고 `추가 생산 가능`이 펼치기 버튼 바로 앞에 표시되는지 확인한다.
  3. 구성품의 `소요량`과 재고가 서로 다른 BOM에서 확정된 계산 기준으로 추가 생산 가능 수량을 검산한다.
  4. 추가 생산 가능 수량이 0인 품목과 다단계·공유 구성품이 있는 품목에서도 값과 배치가 올바른지 확인한다.
  5. 팝업을 닫고 다른 품목으로 전환한 뒤 다시 열어 이전 품목의 수량이 남지 않는지 확인한다.
  6. 재고가 실시간으로 바뀐 뒤 팝업의 현재 재고와 추가 생산 가능 수량이 함께 갱신되는지 확인한다.
