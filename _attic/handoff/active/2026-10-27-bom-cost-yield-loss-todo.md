- Q12에 따라 가계도의 각 품목 상자에는 **개당 원가·소요수량·합계 금액을 함께 표시**한다. 소요수량과 합계는 선택한 상위 품목 한 개를 기준으로 구분한다. 공통 부품의 경로별·전체 합산 표현과 카드 배치는 별도 미정이다.
- Q13에 따라 원가 기준값의 입력·수정 담당은 **부서 정·부와 창고 정·부**다. Q14에 따라 **두 역할 모두 전체 원가 기준값을 수정**할 수 있다. 자재 단가와 표준 작업시간·표준 인건비를 역할별로 나누지 않는다. 기존 MES의 `department_role`, `warehouse_role` 정·부 역할과 대응하며 관리자라는 명칭만으로 별도 편집 대상자를 추가하지 않는다. 기존 관리자 품목 편집 경로와의 관계는 구현 전 점검한다.
- Q15에서 사용자는 **과거 손실은 당시 금액 유지, 현재 품목 원가만 새 기준 적용**을 선호하면서 복잡해질 것을 우려했다. 이 방향과 단순성 제약을 함께 반영한다. 초기 검토 범위는 손실 확정 당시의 평가 원가·수량·금액을 자동 보존하고 과거 조회에 쓰는 정도로 제한한다. 전체 과거 BOM·단가·표준시간을 복원하거나 재평가하는 시스템을 이 답변만으로 도입하지 않는다.
- Q16에 따라 **원가가 없던 기존 불량 이력은 수량·처리 결과를 유지하고 금액은 ‘정보 없음’으로 표시**한다. 현재 기준을 적용한 소급 추정은 하지 않고 원가 기준을 갖춘 이후의 새 기록부터 금액을 관리한다. 정보가 없는 금액을 0원이나 손실 없음으로 해석하지 않는다. 금액 관리 개시점과 기존 건의 후속 처리 연결 기준은 구현 전 구체화한다.
- Q17에 따라 단가·표준시간·하위 BOM 정보가 일부 빠져 있어도 **계산 가능한 부분 합계와 누락 항목을 함께 표시**한다. 카드·가계도에서 ‘부분 합계·미완성’임을 명확히 하고 누락을 0원으로 대체하지 않는다. 계산 가능한 금액 자체가 없으면 ‘계산 정보 없음’으로 구분한다. 이 표시 결정을 불완전한 금액의 확정 손실 저장 승인으로 확대하지 않는다.
- Q7에 따라 **일반 직원도 펼친 재료비·표준 인건비 상세를 확인**할 수 있게 한다. 개인별 급여를 표시한다는 뜻은 아니며, 이번 원가에서 사용하는 표준 금액 상세의 공개를 확정한 것이다. 단가·표준시간의 수정 권한까지 부여한 것은 아니다.
- 게터 소요량 0.5는 최초 운영부터 **입고를 2배 수량으로 환산**해 MES 정수 단위로 관리해 왔다. 소수 수량 지원을 별도 요구로 삼지 않는다. 다른 품목에 이 규칙을 임의 확대하지 않는다.

- 브라우저 확인 시나리오: 추후 일반 직원과 관리자 화면에서 원자재·중간품·완료품·단가 미등록 품목의 요약과 펼침 상세를 확인한다. 수정 가능 여부는 별도 합의한 권한으로 확인한다.
- 우선순위: 높음

## BOM 가계도

### 10. 구성 관계·누적 원가를 함께 보는 BOM 가계도

- 출처: 사용자 요청.
- 화면/영역: BOM 시각화·원가 탐색. 기존 HTML을 참고한다.
- 증상: 기존 관계·필요수량·가용재고 가계도를 원가 계산과 이해에도 활용하고 싶다.
- 사용자 불편: 여러 단계의 구성과 비용이 어디서 더해지는지 표만으로 파악하기 어렵다.
- 확정 정책: 시각적 BOM을 원가 이해·검산에 활용한다. Q10에 따라 대시보드에서 원가분석을 펼치며 Q11에 따라 선택 품목의 BOM 가계도와 원가 구성을 첫 화면의 중심으로 표시한다. Q12에 따라 각 품목 상자에 개당 원가·소요수량·합계 금액을 함께 표시한다. Q17에 따라 정보가 빠진 품목은 계산 가능한 부분 합계와 누락 항목을 함께 알리고 ‘미완성’ 상태를 표시한다. 기존 HTML을 그대로 제품에 넣기로 확정한 것은 아니다.
- 정책 확인 필요: 선택 품목 주변의 초기 표시 범위·깊이, 정·역전개, 공통 부품 반복과 경로별/전체 합계 표시, 접기·검색, 편집, 모바일.
- 구현 방향: 하위→중간품→완료품의 단계 추가비용과 누적 원가를 확인한다. 공통 부품의 여러 경로를 합쳐 수량을 누락하지 않는다.
- 확인한 데이터: `346789-VR-0040` 방사구와 `34678-PR-0061` 실리카겔처럼 여러 부모가 같은 자재를 공유한다. White/Black, TFT·컬리메이터 사양도 실제 코드·BOM으로 구분돼 있다. 모델별 대표 BOM 하나로 합쳐 가격을 계산하지 않고 현재 품목 코드별 구성을 활용하는 방안을 우선 검토한다.
- 수용 기준: 원가분석 첫 화면에서 선택 품목의 가계도와 원가 구성을 확인할 수 있다. 각 품목 상자에서 개당 원가·소요수량·합계 금액을 함께 확인하고 기준 수량을 구분한다. 누락이 있으면 부분 합계와 누락 항목을 함께 안내하고 상위 누적액도 완성된 금액으로 보이지 않는다. 가계도·원가 내역·카드 기준이 일치하며 반복 사용량·비용과 미완성 BOM을 설명한다.
- 브라우저 확인 시나리오: 추후 대시보드에서 품목을 선택해 원가분석을 펼쳤을 때 해당 품목의 가계도·원가 구성을 먼저 확인한다. 완제품 하위를 펼치고 공통 자재에서 상위 사용처로 이동해 사양별 기여금액을 비교한다.
- 우선순위: 중간

## 원가분석

### 13. 원가분석 상세 화면과 대시보드 연결 구성

- 출처: 사용자 추가 요청. 카드에는 기본 원가만 보여도 되는지, 별도 페이지·진입로·화면 이름은 무엇인지 질문했고 이후 대시보드 자체의 역할과 통합 구성을 재논의했다.
- 화면/영역: 원가·수율·불량 손실·시뮬레이션·BOM을 함께 살펴보는 `원가분석` 화면의 정보 구조.
- 증상: 원가분석 명칭·대시보드 진입·첫 화면의 중심은 정했으나 내부 배치와 기간별 분석 구성을 구체화해야 한다.
- 사용자 불편: 우측 카드에 분석 기능을 모두 넣는 것인지, 별도 화면에서 확인하는 것인지 전체 구상을 이해하기 어렵다.
- 확정 정책: 아직 구현하지 않는다. 카드에는 기본 원가와 기존 펼침 상세를 둔다. Q9에서 이름은 `원가분석`으로 확정했다. Q10에 따라 별도 메뉴는 보류하고 대시보드에서 원가분석을 펼치며 Q11에 따라 선택 품목의 BOM 가계도와 원가 구성을 첫 화면의 중심으로 표시한다. Q20에 따라 선택 품목의 손실 상세와 품목·공정별 손실 비교도 함께 제공한다. Q21에 따라 실제 수율 지표는 첫 통과율만 표시한다.
- 정책 확인 필요: 가계도 세부 표시·배치, 대시보드 원가·손실·수율 요약의 범위·배치, 손실 비교의 기간·정렬·공정 귀속, Q22 시뮬레이션 가정 입력 범위, 구체적인 펼침 형태, 품목·기간 필터 유지, 기존 불량·BOM 관리와의 연결, 모바일 진입. 독립 메뉴는 사용자가 재논의할 때만 다시 검토한다.
- 구현 방향: 대시보드에서 선택 품목의 가계도와 원가 구성 중심으로 원가분석을 펼친다. 불량 손실은 선택 품목 상세와 품목·공정별 비교를 함께 탐색한다. 실제 수율·시뮬레이션의 구성과 손실 비교 배치는 별도로 정한다. 대시보드 요약과 상세 펼침 형태도 별도 미정이며 단순 요약과 복잡한 조작을 한 카드에 모두 넣지 않는다. 제품 메뉴·경로·컴포넌트를 생성하지 않는다.
- 수용 기준: 별도 메뉴 추가 없이 대시보드에서 원가분석을 열 수 있고 첫 화면에서 선택 품목의 BOM 가계도·원가 구성을 확인할 수 있다. 선택 품목의 손실 상세와 품목·공정별 손실 비교를 모두 탐색하고 합의한 조회 맥락을 유지한다. 확정된 진입 방향을 내부 배치·기술 구현 전체 승인으로 확대하지 않는다.
- 브라우저 확인 시나리오: 추후 대시보드에서 원가분석을 펼쳐 BOM·원가 구성과 선택 품목의 손실 상세, 품목·공정별 손실 비교를 확인한다. 돌아올 때 합의한 품목·기간 맥락이 유지되는지 확인한다. 이번 범위에 독립 메뉴 진입을 추가하지 않는다. 기존 불량 처리 화면 연결 시에도 같은 조회 맥락을 확인한다.
- 우선순위: 중간

### 조사 기준과 한계

- 조사 시점: 2026-10-27 15:21 KST에 캡처한 `backend/mes.db`의 읽기 전용 스냅샷. 최신 거래는 2026-10-26 16:36 KST이며 원본 DB 수정 시각은 스냅샷 전후 동일했다.
