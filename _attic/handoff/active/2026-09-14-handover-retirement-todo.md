## 입출고

### 1. 인수인계 신규 기능 폐기·기존 기록 보존

- 화면/영역: 입출고 탭 `인수인계`, 프론트 API 클라이언트, `/api/handovers` 쓰기 경로, 인수인계 DB 모델과 기존 기록
- 증상: 인수인계가 별도 초안·제출·인수 흐름으로 존재하며 인수 완료 시 부서 간 재고를 실제로 이동시킨다.
- 사용자 불편: 더 이상 사용할 필요가 없는 별도 재고 이동 경로가 남아 입출고 업무와 테스트 범위를 복잡하게 만든다.
- 확정 정책: 현재 회귀 테스트 구축에서는 완전히 제외한다. 향후 별도 작업에서 탭과 신규 작성·저장·제출·인수 기능을 폐기하되 기존 DB 기록은 보존한다.
- 구현 방향: 입출고 탭의 인수인계 노출과 진입을 제거하고 신규 쓰기 API를 사용할 수 없게 한다. 기존 테이블과 행은 삭제하지 않으며, 제거 후 OpenAPI와 프론트 타입·호출부·테스트를 같은 변경에서 정리한다.
- 수용 기준: 어떤 직원에게도 인수인계 탭이 보이지 않는다. 직접 URL로 진입할 수 없다. 신규 작성·초안 저장·제출·인수 API가 실행되지 않고 재고도 변하지 않는다. 기존 `handovers`·`handover_lines` 행 수와 내용은 변경 전후 동일하다. 현재 회귀 테스트 계약에는 인수인계 정상 동작 테스트가 추가되지 않는다.
- 브라우저 확인 시나리오: 튜브·고압·진공 직원을 각각 로그인시켜 인수인계 탭이 없음을 확인하고 직접 `section=handover` 접근이 기본 입출고 화면으로 돌아오는지 확인한다. 쓰기 API 직접 호출이 거절되고 위치별 재고와 기존 인수인계 행이 무변경인지 확인한다.
