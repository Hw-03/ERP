## 대시보드

### 1. BOM 구성 보기 현재 재고에서 불량 재고 제외

- 화면/영역: 대시보드 > BOM 구성 보기 모달 > `현재 재고` 열
- 증상: 현재 재고가 정상 재고와 불량 재고를 합산해 표시되어, 실제 생산·사용 가능한 재고를 즉시 판단하기 어렵다.
- 사용자 불편: 불량 수량이 있는 품목의 가용 재고가 과대 표시된다.
- 확정 정책: BOM 구성 보기의 `현재 재고`는 불량 재고를 합산하지 않고, 가용 가능한 정상 재고만 표시한다.
- 구현 방향: BOM 트리 응답과 현재 재고 계산 경로를 확인해 불량 위치·상태의 수량을 제외한 값을 모달 열에 전달한다. 생산가능 수량 계산의 재고 기준과 다르면 그 기준을 문서화하고 일치 여부를 검증한다.
- 수용 기준: 불량 재고만 보유한 품목은 `현재 재고`에 `0 EA`로 표시되고, 정상 재고와 불량 재고를 함께 보유한 품목은 정상 재고만 표시된다.
- 브라우저 확인 시나리오: 불량 재고와 정상 재고를 함께 가진 품목 및 불량 재고만 가진 품목을 포함한 BOM을 열어 현재 재고 열을 대조한다.
- 우선순위: 높음

### 2. 펼침 가능한 BOM 행의 텍스트 선택·복사 지원

- 화면/영역: 대시보드 > BOM 구성 보기 모달 > 자식이 있는 트리 행
- 증상: 접기·펼치기 행이 버튼 전체 구조여서 품목코드와 품목명을 마우스로 드래그해 선택·복사할 수 없다.
- 사용자 불편: 일반 구성품 행에서는 가능한 품목코드 복사가 펼침 가능한 행에서만 막혀 업무 중 코드 공유·검색이 불편하다.
- 확정 정책: 단순 행 클릭과 Enter·Space는 기존처럼 접기·펼치기를 수행한다. 품목명·품목코드를 드래그해 선택하는 동작은 펼침 상태를 바꾸지 않고 복사할 수 있어야 한다.
- 구현 방향: 전체 `<button>` 구조를 선택 가능한 행 컨테이너와 접근 가능한 토글 동작으로 분리하고, 텍스트 선택 제스처를 감지해 행 토글을 억제한다. Chevron·키보드·`aria-expanded` 동작은 유지한다.
- 수용 기준: 자식이 있는 행의 품목명과 품목코드를 마우스로 드래그해 복사할 수 있고, 빈 영역 단순 클릭·Enter·Space는 기존과 동일하게 행을 접고 펼친다.
- 브라우저 확인 시나리오: 자식이 있는 행과 리프 행 각각에서 품목코드를 드래그해 복사한 뒤, 행 빈 영역 클릭과 키보드 토글을 확인한다.
- 우선순위: 중간

### 3. BOM 수량 단위 공백 표기 통일

- 화면/영역: 대시보드 > BOM 구성 보기 모달 > `소요량`, `현재 재고` 열
- 증상: 소요량은 `1EA`처럼 수량과 단위 사이에 공백이 없지만, 현재 재고는 `0 EA`처럼 공백이 있어 같은 표 안에서 표기 규칙이 다르다.
- 사용자 불편: 같은 종류의 수량 정보가 서로 다른 형식으로 보여 빠르게 훑을 때 일관성이 떨어진다.
- 확정 정책: BOM 구성 보기의 소요량과 현재 재고는 모두 `수량 + 공백 + 단위` 형식(예: `1 EA`)으로 표시한다.
- 구현 방향: 두 열의 수량 포맷 경로를 공통 표기 규칙으로 맞추고, 0 재고의 강조·취소선 스타일은 유지한다.
- 수용 기준: 일반 재고·0 재고·복수 소요량 행 모두 소요량과 현재 재고가 단위 앞 공백을 포함해 표시된다.
- 브라우저 확인 시나리오: BOM 구성 보기에서 `1EA`, `4EA`, `0 EA`, 천 단위 재고를 함께 확인해 모든 수량 단위가 공백 규칙을 지키는지 확인한다.
- 우선순위: 낮음

### 4. BOM 트리 스크롤 레일 분리

- 화면/영역: 대시보드 > BOM 구성 보기 모달 > 트리 표 오른쪽 스크롤 영역
- 증상: 열 위치 고정을 위해 항상 확보한 스크롤바 폭이 표 테두리 안의 빈 띠로 남아, 스크롤이 없을 때 마지막 열과 행 배경이 중간에 잘린 것처럼 보인다.
- 사용자 불편: 짧은 BOM을 볼 때 표가 완결되지 않은 인상을 주고, 실제 데이터가 가려졌는지 판단하기 어렵다.
- 확정 정책: 스크롤바 폭은 항상 확보해 열 위치와 모달 크기를 고정한다. 단, 표 테두리는 스크롤바 왼쪽에서 완결하고 스크롤바는 표 바깥의 별도 레일에 둔다. 가짜 스크롤바나 비활성 thumb는 표시하지 않는다.
- 구현 방향: 고정 높이의 스크롤 호스트와 표 카드 레이어를 분리한다. 스크롤 호스트는 항상 세로 스크롤바 폭을 확보하고, header·행·둥근 테두리는 그 콘텐츠 폭까지만 그린다. sticky 열 머리글과 긴 트리 스크롤은 같은 호스트에서 유지한다.
- 수용 기준: 접힌 짧은 트리에서는 마지막 `현재 재고` 열과 행 배경이 표의 오른쪽 테두리까지 자연스럽게 이어지고, 펼쳐 스크롤이 생겨도 열 x좌표·표 카드 너비·모달 너비가 변하지 않는다.
- 브라우저 확인 시나리오: 같은 BOM에서 모두 접기와 모두 펼치기를 차례로 실행해 스크롤바 유무 전환 시 마지막 열, 표 테두리, 열 위치가 안정적인지 확인한다.
- 우선순위: 중간

### 5. 생산 가능수량 상세를 BOM 구성 보기와 같은 불투명 모달 표면으로 통일

- 화면/영역: 대시보드 > `생산 가능수량` 상세 모달 전체.
- 증상: 생산 가능수량 상세는 반투명 검은 오버레이 위에 별도 모달을 띄워, 뒤 대시보드의 카드·텍스트가 비치고 BOM 구성 보기와 서로 다른 화면 계층으로 보인다.
- 사용자 불편: 대시보드의 두 상세 화면이 같은 시스템의 구성 보기로 인식되지 않고, 생산 가능수량을 확인할 때 뒤 화면 정보가 시야를 분산시킨다.
- 확정 정책: 생산 가능수량 상세의 화면 배경은 투명하지 않게 처리한다. BOM 구성 보기와 같은 불투명 전체 배경 위의 패널 구조, 표면색·테두리·그림자·닫기 제어 문법을 사용해 같은 컴포넌트를 쓰는 듯한 일관된 인상을 준다. 내용·테이블·PF 상세 진입 흐름은 생산 가능수량 전용으로 유지한다.
- 구현 방향: `CapacityDetailModal`의 반투명 오버레이와 독자 패널 셸을 `BomDetailModal`의 불투명 배경·패널 표면 패턴에 맞춘다. 공통 모달 셸을 실제로 추출할지는 두 화면의 포커스 트랩, Escape·바깥 클릭 닫기, 크기 요구사항이 모두 보존되는 경우에만 판단한다.
- 수용 기준: 생산 가능수량을 열어도 뒤 대시보드의 카드·텍스트·스크롤 위치가 보이지 않는다. 제목·패널 외곽·닫기 버튼·콘텐츠 표면이 BOM 구성 보기와 동일 계열의 불투명한 표면으로 읽히며, 기존 생산 가능수량 설명·모델 목록·PF BOM 상세 진입과 복귀·닫기는 그대로 동작한다.
- 브라우저 확인 시나리오: 데스크톱 `/mes?tab=dashboard`에서 생산 가능수량 상세와 임의 품목의 BOM 구성 보기를 각각 열어 배경 불투명도, 패널 경계, 닫기 제어를 비교한다. 생산 가능수량에서 모델 행을 열고 PF BOM 상세에 진입·복귀한 뒤, 바깥 클릭·Escape·닫기 버튼으로 닫기 동작을 확인한다.
- 우선순위: 중간

### 6. 자재 목록의 총재고 열을 사용 가능 재고로 전환

- 화면/영역: 대시보드 > 자재 목록 > `총재고` 수량 열(데스크톱 및 compact 목록).
- 증상: 현재 열 제목은 `총재고`이고 행 값도 `item.quantity`를 표시한다. 이 값은 창고·생산·불량 재고를 모두 합친 수량이어서, 불량 재고 또는 출고·승인 예약이 있는 품목의 실제 사용 가능분보다 크게 보일 수 있다. 같은 품목의 우측 상세 패널은 이미 별도의 `사용 가능 재고`를 표시한다.
- 사용자 불편: 목록을 훑어 생산·출고에 바로 쓸 수 있는 수량을 판단할 때 불량·예약 수량을 다시 빼야 하며, 목록과 상세 화면의 재고 기준이 달라 혼동된다.
- 확정 정책: 자재 목록의 해당 열 제목은 `사용 가능 재고`로 변경한다. 행 값은 API의 `available_quantity`를 사용하며, 창고·생산 실재고에서 각 출발지의 예약 수량을 차감하고 불량 재고는 제외한 수량으로 한다. 상태(정상·부족·품절)와 최소재고 비교도 이 표시 기준과 일치시킨다. 부서별 재고 칩·분포 막대는 실재고 구성 표시 역할을 유지한다.
- 구현 방향: `InventoryItemsTable`의 열 제목과 `InventoryItemRow`의 값·상태 판정 수량을 `available_quantity` 기준으로 통일한다. 기존 목록 API가 이미 제공하는 `available_quantity`를 그대로 사용해 프런트엔드에서 불량·예약을 재계산하지 않으며, 열 폭·정렬·품목 선택·우측 상세 패널 동작은 유지한다. 관련 단위 테스트의 열 제목과 행 수량 기대값도 함께 갱신한다.
- 수용 기준:
  - 대시보드 자재 목록의 해당 열 제목은 데스크톱과 compact 목록 모두 `사용 가능 재고`로 표시되고 `총재고`는 남지 않는다.
  - 불량 재고 또는 예약 수량이 있는 품목의 목록 값은 API `available_quantity` 및 우측 상세 패널의 `사용 가능 재고`와 정확히 일치한다.
  - 불량 재고만 있는 품목은 목록에서 사용 가능 재고 `0`과 품절 상태로 보이며, 예약 차감 뒤 최소재고보다 적은 품목은 부족 상태가 된다.
  - 부서별 재고 구성, 검색·필터, 행 선택, 상세 패널, 열 폭과 반응형 목록 동작은 기존처럼 유지된다.
- 브라우저 확인 시나리오: `/mes?tab=dashboard`에서 불량 재고와 정상 재고를 함께 가진 품목, 예약 수량이 있는 품목, 사용 가능 재고가 최소재고 미만인 품목을 각각 확인한다 → 목록 열 제목·값을 우측 상세 패널의 `사용 가능 재고`와 대조한다 → 불량만 있는 품목이 `0`·품절로 보이는지 확인한다 → 검색·필터·행 선택과 데스크톱·compact 폭을 확인한다.
- 우선순위: 높음
