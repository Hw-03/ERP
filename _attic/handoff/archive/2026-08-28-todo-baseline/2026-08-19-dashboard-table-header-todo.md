## 대시보드

### 1. 재고 목록 sticky 제목 행의 불투명 표면과 모서리 마스킹 보장

- 화면/영역: 데스크톱 대시보드 > `자재 목록` > 검색 바 아래의 상태·이미지·품목명 등 열 제목 행.
- 증상:
  - 제목 행의 둥근 상단 모서리 뒤로 목록을 스크롤할 때 품목 행의 선·내용이 드러난다.
  - 제목 행 배경이 살짝 투명해 아래의 품목 정보가 비친다.
- 사용자 불편: 제목 행의 경계가 표의 고정 기준점으로 읽히지 않고, 스크롤 내용과 겹쳐 화면 완성도가 떨어진다.
- 확정 정책:
  - 현재의 둥근 제목 행 모서리는 유지한다.
  - sticky 제목 행과 모서리 주변의 배경은 완전히 불투명해야 한다.
  - 스크롤된 행은 제목 행의 표면이나 둥근 모서리 뒤로 보이면 안 된다.
- 구현 방향:
  - 표 외곽 클리핑과 sticky 제목 행의 쌓임·배경 책임을 함께 정리해, 둥근 모서리 안쪽을 불투명한 제목 표면으로 마스킹한다.
  - 라이트·다크 모드 모두에서 제목 행에 알파값이 없는 적절한 표면 색을 적용하되, 기존 테두리·열 폭·스크롤 동작은 보존한다.
- 수용 기준:
  - 재고 목록을 위·아래로 스크롤해도 제목 행의 둥근 양쪽 상단 모서리 뒤로 품목 행, 구분선, 이미지 또는 텍스트가 보이지 않는다.
  - 제목 행 어디에서도 아래 품목 행의 글자·색상·선이 비치지 않는다.
  - 제목 행의 둥근 모서리, 열 제목, 검색 바, 품목 선택 및 우측 상세 패널의 기존 동작이 유지된다.
  - 라이트·다크 모드 모두에서 제목 행과 모서리 마스킹이 불투명하게 유지된다.
- 브라우저 확인 시나리오:
  - 데스크톱 너비에서 `/mes?tab=dashboard`를 연다.
  - 품목 목록을 여러 행 아래로 스크롤한 뒤, 제목 행의 좌우 상단 둥근 모서리와 각 열 제목 배경을 확인한다.
  - 다시 최상단과 중간 위치를 번갈아 확인하고, 행 선택·검색·우측 상세 패널을 조작해 표 동작이 유지되는지 확인한다.
  - 다크 모드에서도 같은 스크롤 위치를 확인한다.
- 우선순위: 중간

### 2. 우측 상세 패널의 탭과 닫기 버튼을 상단 한 줄로 재배치

- 화면/영역: 데스크톱 대시보드 > 품목 선택 후 우측 `재고 상세 보기` 패널의 상단 `상세 정보`·`최근 내역` 탭 및 패널 닫기 버튼.
- 증상:
  - 탭 박스가 두 탭의 내용 폭만 사용해 상단 왼쪽에 작게 보인다.
  - 닫기 버튼은 아래 품목명 행 오른쪽에 따로 있어, 탭 박스와 닫기 동작이 상단에서 한 덩어리로 읽히지 않는다.
- 사용자 불편: 상세 보기의 전환과 닫기 동선이 세로로 분리되어 상단 공간을 비효율적으로 쓰며, 패널의 첫 조작 영역이 정돈되어 보이지 않는다.
- 확정 정책:
  - `상세 정보`·`최근 내역` 탭 박스와 닫기 버튼은 패널 최상단의 한 줄에 둔다.
  - 탭 박스의 외곽 표면은 왼쪽 시작점부터 닫기 버튼 직전까지 남는 가로 폭을 사용한다.
  - 닫기 버튼은 기존 32px 조작 크기와 동작을 유지하되, 그 한 줄의 오른쪽 끝에 배치한다.
  - 품목명·코드·상태 정보와 탭 전환·키보드 조작·ESC 닫기 동작은 유지한다.
- 구현 방향:
  - 대시보드 재고 상세 패널에서 탭 목록과 닫기 버튼을 같은 상단 레이아웃 컨테이너로 조합한다.
  - 공용 우측 패널의 제목 영역은 다른 화면의 닫기 버튼 배치에 영향을 주지 않도록, 재고 상세 패널에만 필요한 닫기 버튼 배치 책임을 명확히 분리한다.
  - 탭 박스는 남은 폭을 차지하되, 두 탭 버튼의 선택 상태·포커스·가로 정렬은 기존 접근성 동작을 보존한다.
- 수용 기준:
  - 품목 선택 시 `상세 정보`·`최근 내역` 탭 박스와 닫기 버튼이 우측 패널 최상단의 동일한 가로 행에 보인다.
  - 탭 박스 외곽은 패널의 왼쪽 콘텐츠 시작점부터 닫기 버튼 바로 앞까지 넓게 이어지고, 닫기 버튼은 행 오른쪽 끝에 있다.
  - 탭 전환, 좌우 방향 키 전환, ESC 및 닫기 버튼으로 패널 닫기가 기존과 동일하게 동작한다.
  - 품목명·품목 코드·상태 및 아래 수량 현황은 잘리거나 겹치지 않는다.
- 브라우저 확인 시나리오:
  - 데스크톱 너비에서 `/mes?tab=dashboard`를 열고 품목 하나를 선택한다.
  - 우측 패널 최상단에서 탭 박스의 가로 폭, 닫기 버튼의 오른쪽 끝 정렬, 두 요소의 한 줄 배치를 확인한다.
  - 두 탭을 클릭하고 키보드 좌우 화살표로 전환한 뒤, 닫기 버튼과 ESC로 패널을 닫아 기존 동작을 확인한다.
  - 이름·코드가 긴 품목을 선택해 제목 정보와 상단 조작 행이 겹치지 않는지 확인한다.
- 우선순위: 중간

- 증상:
  - 목록 우측 상단과 하단의 둥근 마감이 주변 표면과 다른 곡률로 보이며, 모서리가 한 번에 매끈하게 이어지지 않고 다듬다 만 듯한 인상을 준다.
  - 외곽 스크롤 뷰포트, 내부 표 표면, 열 제목 셀이 서로 다른 곡률을 가져 경계가 겹쳐 보일 수 있다.
- 사용자 불편: 화면의 큰 목록 표면이 완성된 카드로 읽히지 않고, 특히 우측 끝에서 시각적 품질이 떨어진다.
- 확정 정책:
  - 사용자가 보는 우측 상단과 하단 모서리는 서로 같은 곡률·마감 품질로 보이게 한다.
  - 외곽 스크롤 영역과 내부 표 표면의 곡률은 계단·이중 테두리·잘린 호처럼 드러나면 안 된다.
  - 목록 데이터, 열 너비, 행 선택, 무한 스크롤과 세로 스크롤바 동작은 유지한다.
- 구현 방향:
  - 입출고 내역 외곽 뷰포트·표 표면·제목 행 가운데 노출된 모서리의 표면 책임을 하나로 정리한다.
  - 상단과 하단 모두에서 동일한 곡률이 보이도록 클리핑·테두리·배경의 적용 위치를 조정하고, 내부 표의 스크롤·가로 레이아웃은 보존한다.
- 수용 기준:
  - 입출고 내역 진입 직후와 목록을 중간까지 스크롤한 상태 모두에서 우측 상단과 하단 모서리가 매끈한 단일 곡선으로 보인다.
  - 우측 모서리에서 두 겹의 호, 끊긴 테두리, 서로 다른 곡률의 단계가 보이지 않는다.
  - 목록의 열 제목·행·스크롤바·상세 패널 및 추가 불러오기 동작이 기존과 같다.
- 브라우저 확인 시나리오:
  - 데스크톱 너비에서 `/mes?tab=history`를 연다.
  - 목록의 우측 상단과 하단을 확대해 비교하고, 위·아래로 스크롤한 뒤에도 모서리 마감이 유지되는지 확인한다.
  - 행 하나를 선택해 상세 패널을 열고 닫은 뒤, 목록 폭과 우측 모서리가 변형되지 않는지 확인한다.
- 우선순위: 중간

### 4. 달력 연·월 라벨에 연 뷰 진입을 알리는 자연스러운 테두리 적용

- 화면/영역: 데스크톱 입출고 내역 > 달력 > 월 네비게이션 중앙의 `YYYY년 M월` 연·월 라벨.
- 증상: 연·월 라벨을 누르면 연 뷰가 열리지만, 현재는 일반 텍스트처럼 보여 누를 수 있는 제어인지 즉시 알기 어렵다.
- 사용자 불편: 달력의 연 단위 탐색 기능을 발견하기 어렵고, 월 이동 화살표와 중앙 라벨의 역할 차이가 시각적으로 드러나지 않는다.
- 확정 정책:
  - 연·월 라벨은 연 뷰를 여는 버튼임을 명확히 보여 준다.
  - 과도하게 분리된 버튼처럼 보이지 않으면서도, 달력 상단 바와 어울리는 자연스러운 둥근 테두리·표면·hover·키보드 포커스 상태를 갖는다.
  - 연 뷰에서 연도 라벨을 눌러 월 뷰로 돌아가는 대응 제어도 같은 문법을 사용한다.
- 구현 방향:
  - 달력 월·연 뷰의 중앙 라벨 버튼에 공통된 시각 상태를 적용하고, 기존 레이블·화살표 배치·연 뷰 전환 동작은 보존한다.
  - 라이트·다크 모드에서 테두리와 포커스가 충분히 보이는지 확인한다.
- 수용 기준:
  - 월 뷰의 `YYYY년 M월` 라벨이 자연스러운 테두리·표면을 가진 클릭 가능한 제어로 보인다.
  - hover 및 키보드 포커스에서 상호작용 가능 상태를 식별할 수 있다.
  - 라벨 클릭 시 연 뷰가 열리고, 연 뷰의 연도 라벨 클릭 시 월 뷰로 돌아가는 기존 동작이 유지된다.
- 브라우저 확인 시나리오:
  - 데스크톱 `/mes?tab=history`에서 달력을 연다.
  - 중앙의 연·월 라벨 외형과 hover·키보드 포커스를 확인한 뒤 클릭해 연 뷰를 연다.
  - 연 뷰의 연도 라벨을 눌러 월 뷰로 돌아오고, 화살표 월 이동과의 배치 균형을 확인한다.
  - 다크 모드에서도 테두리·포커스·텍스트 대비를 확인한다.
- 우선순위: 중간

### 5. 달력 월 이동을 거래 목록의 해당 월 기간 필터로 연결

- 화면/영역: 데스크톱 입출고 내역 > 달력 월 네비게이션 및 연 뷰의 월 카드 > 아래 거래 목록·상단 요약·기간 표기.
- 증상: 달력에서 이전·다음 월로 이동하거나 연 뷰에서 특정 월을 골라도 달력만 바뀌고, 아래 거래 목록은 기존 날짜 조건을 계속 표시한다.
- 사용자 불편: 달력에서 보고 있는 월과 거래 목록의 기간이 달라, 사용자가 해당 달의 내역을 따로 찾거나 필터를 다시 지정해야 한다.
- 확정 정책:
  - 이전·다음 월 이동과 연 뷰의 월 선택은 선택한 연·월 전체를 거래 목록의 날짜 범위로 적용한다.
  - 월 필터는 하루 선택과 동시에 유지하지 않으며, 월을 바꾸면 기존 하루 선택은 해제한다.
  - 검색·거래 유형·부서·모델 필터는 유지한 채 날짜 범위만 선택 월로 바꾼다.
  - 상단 요약과 기간 표기는 목록과 같은 선택 월을 정직하게 표시하고, 기존 `전체`·`오늘`·`이번주`·`이번달` 기간 칩을 선택하면 월 필터는 해제한다.
- 구현 방향:
  - 달력 표시용 연·월 상태와 목록 조회용 월 범위 상태를 연결해, 월 이동·연 뷰 월 선택에서 시작일·마지막 날 조건을 갱신한다.
  - 기존 하루 선택과 상단 기간 칩의 날짜 조건을 하나의 배타적인 흐름으로 정리하고, 목록·요약·거래 기준 수량 조회가 같은 월 범위를 사용하게 한다.
- 수용 기준:
  - 달력에서 2026년 8월에서 2026년 7월로 이동하면 거래 목록에는 2026년 7월 거래만 보인다.
  - 연 뷰에서 다른 월을 선택해 월 뷰로 돌아와도 목록·요약·기간 표기가 같은 연·월을 가리킨다.
  - 하루를 선택하면 그 하루만 필터되고, 이후 월을 바꾸면 하루 선택은 해제되어 해당 월 전체가 보인다.
  - 검색·거래 유형·부서·모델 조건은 월 이동 뒤에도 유지되며, 상단 기간 칩을 고르면 월 필터가 해제된다.
- 브라우저 확인 시나리오:
  - `/mes?tab=history`에서 달력을 열고 현재 월의 목록 행 날짜를 확인한다.
  - 이전·다음 화살표로 월을 바꾸어 달력·목록·요약·기간 표기가 같은 연·월로 갱신되는지 확인한다.
  - 연 뷰에서 임의의 월을 선택한 뒤 같은 검증을 반복한다.
  - 특정 날짜 선택, 검색 또는 부서 필터, 상단 기간 칩 선택을 차례로 조합해 날짜 조건의 배타성과 다른 필터의 유지 여부를 확인한다.
- 우선순위: 중간
