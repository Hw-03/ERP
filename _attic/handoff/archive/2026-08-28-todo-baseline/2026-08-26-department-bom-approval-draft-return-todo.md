## 확정 결정 요약
- 부서 생산·분해 BOM의 하위 품목은 수량을 `+/-`로 조정한다. 포함된 항목의 체크를 누르면 수량 0으로 제외하고, 제외된 항목은 수량을 늘려 다시 포함한다.
- 현재 BOM 기준 수량과 하나라도 다르면 부서 정·부 결재를 거친다.
- 하위를 하나라도 커스텀한 출고 BOM 묶음은 `BOM 참고 선택 출고`로 전환한다. 상위는 참고용으로만 남기고, 승인 후 포함된 하위 품목 전체를 각 소속 부서 재고에서 차감한다. 아무것도 건드리지 않은 출고 BOM은 기존 분해처럼 상위를 차감하고 하위를 회수 입고한다. 커스텀 입고·생산 BOM은 기존 동작을 유지한다.
- 여러 BOM이 한 요청에 섞이면 위 판정을 묶음별로 적용한다.
- 제출·임시저장·미리보기의 요청자 ID는 화면에 현재 표시된 작업자 ID와 항상 같아야 한다.
- 반려된 부서 낱개 입출고는 원 요청의 모든 품목을 하나의 작성 중 초안으로 되돌리되, 반려 요청과 사유는 감사 이력으로 남긴다.
- BOM 커스텀 결재의 반려 초안 복귀는 이번 범위에 포함하지 않는다.

## 부서 입출고

### 1. [완료] 부서 BOM 하위 품목 수량 커스텀과 부서 결재
- 화면/영역: 부서 입출고 > 생산·분해 BOM > 품목 확인·제출
- 증상: BOM 하위 품목 수량이 잠겨 있어 생산·분해 작업의 실제 투입·산출 수량을 반영할 수 없다.
- 사용자 불편: 실제 수량이 BOM과 다르면 별도 작업으로 처리해야 하고, 변경을 승인받을 통제가 없다.
- 확정 정책: 하위 품목은 `+/-`로 수량을 변경할 수 있다. 포함된 자동 BOM 항목의 체크를 누르면 수량 0으로 제외하며, 제외 상태에서는 수량을 늘려 다시 포함한다. BOM 기준 수량과 다른 하위 품목이 하나라도 있으면 부서 정·부 PIN 결재가 필요하다. 커스텀 출고 BOM은 상위 재고를 바꾸지 않고 포함된 하위 전체를 선택 출고하며, 손대지 않은 출고 BOM은 기존 분해 동작을 유지한다. 커스텀 입고·생산은 기존 동작을 유지하고 재고 미반영 BOM 항목은 계속 수정할 수 없다.
- 구현 방향: 재고 미반영 항목은 계속 잠근다. 포함된 자동 BOM 항목의 체크 해제는 수량 0·제외로 동기화하고, 상위 수량이 바뀌면 미수정 하위 품목만 비례 재계산한다. 상위 수량이 0이면 하위 항목을 모두 제외한다. 프런트는 원본 BOM 토큰 라인을 보존하면서 커스텀 출고 하위를 `production(기존 to_department) → none` 효과로 파생해 표시·부족 검증한다. 서버는 원본 토큰과 현재 DB BOM을 검증한 뒤 같은 출고 방향으로 실제 `IoLine`을 정규화하여 예약·결재·승인 실행에 사용한다. 품목 확인·최종 확인·이력 화면도 `BOM 참고 출고`, `상위 미반영`, 하위 음수 변동을 표시한다.
- 수용 기준: 기본 출고 BOM은 상위 감소·하위 증가를 기존 방식대로 즉시 반영한다. 커스텀 출고는 승인 전 재고에 반영되지 않고 하위 출고 재고만 예약하며, 승인 후 상위는 그대로 두고 포함된 하위 전체를 정확한 수량으로 차감한다. 한 요청의 다른 미수정 BOM 묶음은 기존 분해를 유지한다. 요청 본문의 `edited`나 경로를 조작해도 결재·재고 검증을 우회할 수 없다. 이력에는 실행 로그가 없는 상위 재고 변동을 표시하지 않고 하위의 실제 음수 로그와 전후 재고를 표시한다.
- 브라우저 확인 시나리오: 부서 생산·분해 BOM에서 포함된 하위 체크를 눌러 수량 0·제외되는지, `+`로 다시 포함되는지, 기본 수량 제출, 하위 수량 증가·감소·0 제출, 상위 수량 변경 후 미수정 하위 비례 변경, 재고 미반영 항목 잠김을 각각 확인한다.
- 우선순위: 높음
- 완료 확인: 커스텀 출고 BOM의 상위 미반영·포함 하위 전체 차감·부족 차단·원본 토큰 검증·승인 후 음수 로그, 표준 분해 회귀, 실행 로그 기반 이력 표시를 백엔드 서비스 및 프런트 회귀 테스트로 확인했다.

### 2. [완료] 부서 낱개 입출고 반려 시 작성 중 복귀
- 화면/영역: 부서 승인함 > 낱개 입고·출고 반려, 요청자 > 작성 중
- 증상: 반려된 낱개 부서 입출고를 요청자가 같은 구성으로 수정·재제출할 수 있는 작성 중 작업으로 되돌릴 수 없다.
- 사용자 불편: 여러 품목의 요청 내용을 다시 입력해야 하고, 반려 사유를 보며 수정할 수 없다.
- 확정 정책: 반려 요청 하나에 담긴 모든 품목·수량·메모·참조정보를 하나의 작성 중 초안으로 복귀한다. 반려된 `StockRequest`의 반려자·시각·사유는 삭제하지 않는다.
- 구현 방향: 부서 낱개 입출고 `IoBatch`만 `draft`로 되돌리고, 예약 재고를 해제한다. 최신 반려 사유는 작성 중 카드에 표시하되, 이어서 작업 화면에는 중복 표시하지 않는다. 수정 후 재제출하면 원 초안을 유지한 채 새 결재 요청을 만든다.
- 수용 기준: 반려와 동시에 예약 재고가 해제된다. 요청자는 자기 작성 중에서만 작업을 열어 수정·재제출할 수 있다. 모든 품목이 한 초안으로 복원되며, 재승인 후에만 재고가 반영된다.
- 브라우저 확인 시나리오: 여러 품목의 부서 낱개 요청을 반려하고, 요청자의 작성 중 카드에는 반려 사유가 표시되며 이어서 작업 화면에는 중복 표시되지 않는지 확인한다. 전체 품목 복원·수정·재제출·재승인까지 확인한다.
- 우선순위: 높음
- 완료 확인: 반려→같은 초안 재제출→재승인→재고 반영, 데스크톱·모바일 작성 중 카드 표시와 이어서 작업 화면 미표시 테스트를 통과했다.
