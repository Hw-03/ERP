## 자율 점검 기준

- 모델명과 상태명은 장식 기호나 말줄임 때문에 다른 값으로 오해되지 않아야 한다.
- 같은 의미의 선택 상태는 같은 강도의 그림자와 배경 문법을 사용한다.
- 나란히 놓인 제어 영역은 높이와 수직 정렬을 맞춘다.
- 같은 헤더 행의 KPI와 작업 버튼은 외곽 높이와 위·아래 기준선을 맞춘다.
- 정보 표시를 위해 넓힌 목록이 오른쪽 작업 영역을 불필요하게 압박하지 않아야 한다.
- 장식용 외곽선을 없애도 클릭 가능 여부와 상태 강조는 분명해야 한다.
- 자주 쓰는 작업을 먼저 두고 보조·일괄 다운로드는 사용자가 지정한 순서에 배치한다.
- 화면에서 제거하는 안내가 실제 다운로드 데이터나 파일 형식을 바꾸면 안 된다.
- 긴 단일 화면은 현재 위치를 잃지 않고 원하는 업무 구역으로 바로 이동할 수 있어야 한다.
- 콘텐츠가 하나뿐인 화면은 작업 카드를 가용 영역의 중심에 배치해 빈 공간을 의도적으로 사용한다.
- 나란한 BOM 패널의 제목·보조 제어·열 머리글은 대응하는 행끼리 높이를 맞춘다.
- 나란한 BOM 목록의 데이터 행은 같은 높이 문법을 사용하고, 수량 편집 상태에서도 행 높이가 뛰지 않아야 한다.
- 상세 카드의 위험 작업은 쉽게 찾을 수 있어야 하지만 내용 없는 전용 행을 차지해 핵심 정보 높이를 줄이지 않아야 한다.
- 같은 위치에서 같은 저장 역할을 하는 관리자 주 작업 버튼은 충분한 클릭 높이와 같은 크기 문법을 사용해야 한다.
- 이력의 이동 경로는 거래를 요청한 부서보다 실제 재고가 출발한 상태를 우선해 표시한다.
- 재고 변화 묶음 제목은 빠른 비교에 필요한 품목 수와 합계만 남기고 단위는 상세 행에서 확인한다.
- 데스크톱 업무 메뉴는 일간 기록과 주간 요약이 연속되도록 배치하되 하단 고정 유틸리티 영역과 섞지 않는다.
- 출하 요청 카드의 사람·시간 정보는 장식 구분점보다 명시적 필드명으로 읽히게 한다.
- 안내 문구를 제거한 헤더는 남은 제목·아이콘·제어를 다시 정렬하고 제목 위계를 보강해 빈 비율을 남기지 않는다.
- 전체 화면 인증 배경은 셸의 기본 캔버스와 이어져야 하며, 보안 강조용 색은 화면 전체 판이 아니라 인증 카드 주변에 제한한다.
- 출하 이력의 상태 색은 업무 의미를, 연월 폴더 색은 탐색 선택을 나타내도록 서로 구분한다.

## 확정 결정 요약

- 생산 가능 요약의 모델명 앞 가운데점은 모든 모델에서 제거하고 모델 순서·수량·색상은 유지한다.
- 선택 효과는 현재 관리자 상단 `품목 관리`의 약한 그림자를 기준으로 같은 유형의 선택 버튼에 통일한다.
- 부서 목록은 폭과 상태 열을 함께 조정해 `사용 중`을 말줄임 없이 표시한다.
- BOM 상단 공정 필터 영역과 버튼은 선택된 상위 품목 요약 박스 높이에 맞춰 키운다.
- `미배치 원자재` 접이식 박스의 바깥 테두리는 제거한다.
- BOM 헤더의 `BOM 내보내기`와 `편집 / 사용처` 전환 영역은 `미착수` KPI 카드 높이에 맞춘다.
- `품목·입출고 Excel` 카드는 CSV·최근 기록·시스템 원본 로그 영역보다 뒤인 내보내기 페이지 최하단으로 이동한다.
- `시스템 원본 컬럼 구성 (11)` 안내는 화면에서 제거하되 원본 로그 파일의 실제 컬럼은 변경하지 않는다.
- 내보내기 헤더에는 각 업무 구역으로 스크롤하는 바로가기 버튼을 둔다.
- 보안 화면의 PIN 변경 카드는 헤더 아래 가용 영역 중앙에 배치한다.
- BOM `상위 품목 선택`과 검색창은 같은 첫 행에 두고 단계 필터는 둘째 행으로 분리하며, `하위 품목 추가` 패널과 대응 행의 디자인을 맞춘다.
- BOM `현재 구성`의 제목 행과 열 머리글 행은 각각 `하위 품목 추가`의 제목·검색 행과 필터 행 높이에 맞춘다.
- 선택된 품목 상세의 별도 삭제 헤더 행은 제거하고, 삭제·확인 동작을 세부 탭과 같은 행의 오른쪽 작업 영역으로 옮겨 확보한 높이를 상세 본문에 돌린다.
- 모델·직원·부서 상세 헤더의 파란 `저장` 버튼은 44px 높이·16px 아이콘을 기준으로 같은 크기로 키운다.
- 격리 재고를 폐기한 거래의 이동 경로는 부서명이 아니라 `격리 → 폐기`로 표시한다.
- 이력 재고 변화의 모든 묶음 제목에서 합계 뒤 단위(`EA` 등)를 제거하되 품목 수와 부호 있는 합계는 유지한다.
- 데스크톱 사이드바의 `일일 작업 일지`는 `주간보고` 바로 아래로 이동해 주 업무 메뉴의 마지막 항목으로 둔다.
- 출하 요청 목록 헤더의 진행 건수·절차 설명 문장은 제거하고 각 상태 열의 건수만 유지한다.
- 진행 중 출하 요청 카드의 `생성`은 `요청 일시`로 바꾸고 요청자는 `요청자: 이름` 형식으로 같은 메타정보 영역에 표시한다.
- 출하 이력의 `출하 완료` 선택은 초록, `요청 취소` 선택은 빨강, 선택·검색 연월 폴더는 파랑 계열로 통일하고 강한 선택 그림자는 관리자 탭 수준으로 낮춘다.
- 출하 이력의 월 폴더는 첫 클릭에서 선택과 콘텐츠 열림이 동시에 완료되고 선택된 한 달만 열린 상태를 유지한다.
- 출하 이력 헤더의 설명 문구는 제거하고 제목 크기·수직 정렬·제어 위치를 단일 행에 맞게 재조정한다.

## 관리자 품목 관리

### 2. 선택 버튼 그림자를 관리자 상단 탭 수준으로 통일

- 원본 코멘트: 2~4번.
- 화면/영역: 데스크톱 관리자 > 상단 섹션 탭과 품목 관리 상세의 `기본 정보`·`재고 정보`·`BOM / 사용처` 탭을 포함한 관리자 선택형 버튼.
- 증상: 관리자 상단 `품목 관리`는 전용 규칙으로 약한 inset 그림자를 사용하지만, 상세 탭은 전역 `aria-selected="true"` 규칙의 더 강한 그림자를 사용한다. 같은 관리자 화면 안에서 선택 효과의 깊이가 다르다.
- 사용자 불편: 상세 탭이 상단 기준보다 과하게 눌린 것처럼 보이고, 유사한 선택 버튼마다 강조 강도가 달라 화면의 위계가 흔들린다.
- 확정 정책: 현재 관리자 상단 `품목 관리` 선택 상태의 약한 그림자를 기준으로 관리자 화면의 같은 유형 선택 버튼을 통일한다. 활성 배경·글자색·테두리·포커스 링·키보드 탭 동작은 유지한다. 프로젝트에서 동결된 모바일 하단 탭 바와 주간보고 화면은 변경 대상에서 제외한다.
- 구현 방향: `AdminDetailCard` 한 곳만 임시 덮어쓰지 말고 관리자 내부의 `aria-current`·`aria-pressed`·`aria-selected` 사용처를 점검해 동일한 선택 깊이를 적용한다. 비선택 버튼, 위험 버튼, 일반 카드의 그림자는 건드리지 않는다.
- 수용 기준:
  - `기본 정보`, `재고 정보`, `BOM / 사용처` 중 어느 탭을 선택해도 상단 `품목 관리`와 같은 수준의 약한 그림자로 보인다.
  - 관리자 내 다른 선택형 버튼에서도 기존의 강한 inset 효과가 남아 있지 않다.
  - 활성 상태 구분, Tab/방향키/Enter 조작, 포커스 표시, 라이트·다크 테마 대비는 유지된다.
  - 관리자 밖 화면과 동결된 화면의 선택 스타일에는 의도하지 않은 변화가 없다.
- 브라우저 확인 시나리오: 관리자 상단에서 모델 관리·품목 관리·직원 관리·부서 관리·BOM 관리·내보내기·보안을 차례로 선택한다 → 품목 상세의 세 탭을 마우스와 키보드로 전환한다 → 관리자 안의 다른 선택형 버튼을 비교한다 → 라이트·다크 테마에서 그림자 강도와 포커스 표시를 확인한다.
- 우선순위: 중간.

### 3. 품목 상세의 빈 삭제 헤더를 없애고 삭제를 탭 행으로 이동

- 원본 코멘트: 2026-08-03 추가 코멘트 1~4번.
- 화면/영역: 데스크톱 관리자 > 품목 관리 > 선택된 활성 품목의 오른쪽 상세 카드 상단, `기본 정보 / 재고 정보 / BOM / 사용처` 탭과 삭제 작업 영역.
- 증상: 선택된 품목은 상세 제목을 표시하지 않지만 삭제 액션만으로 별도의 `px-5 py-4` 헤더 행이 렌더링된다. 그 아래에 세부 탭 행이 다시 놓여, 내용 없는 왼쪽 공간과 삭제 버튼 하나가 카드 상단 한 행을 차지한다.
- 사용자 불편: 자주 확인하는 품목 기본 정보보다 삭제 작업이 독립된 큰 위계를 차지하고, 상세 본문의 가용 높이가 줄어 입력 필드와 BOM·사용처 정보를 보기 위해 더 일찍 스크롤해야 한다.
- 확정 정책: 선택된 활성 품목에서는 삭제 전용 헤더 행을 완전히 제거한다. 삭제 버튼은 세부 탭과 같은 시각 행의 오른쪽 끝으로 내리고, 삭제 확인 문구·취소·삭제 확인도 그 작업 영역에서 처리한다. 탭은 왼쪽, 삭제 작업은 오른쪽에 두되 삭제 버튼을 `tablist` 역할 안에 포함하지 않는다. 제거한 헤더 높이는 상세 본문에 돌려 정보 표시량을 늘린다. 새 품목 추가의 실제 제목·설명 헤더와 삭제된 품목의 하단 복구 동작은 유지한다.
- 구현 방향: `AdminDetailCard`에 탭 행과 나란히 놓는 전용 액션 슬롯을 추가하거나 동등한 제한적 조합을 사용하고, `AdminMasterItemsSection`의 삭제·확인 액션만 그 슬롯으로 옮긴다. 제목·상태가 있는 다른 상세 카드의 기존 헤더와 공용 탭 키보드 동작은 바꾸지 않는다. 탭 묶음과 위험 작업 묶음은 같은 외곽 행 안의 형제 영역으로 구성해 ARIA 탭 의미를 보존한다.
- 수용 기준:
  - 활성 품목을 선택하면 카드 상단에 삭제 버튼만 있는 빈 헤더 행이 보이지 않는다.
  - `기본 정보 / 재고 정보 / BOM / 사용처` 탭은 왼쪽, 삭제 버튼은 같은 행 오른쪽 끝에 수직 중앙 정렬된다.
  - 삭제를 누르면 확인 문구·취소·삭제 확인을 사용할 수 있고, 확인 상태 때문에 별도 상단 행이 생기거나 탭을 덮지 않는다.
  - 제거된 헤더만큼 상세 본문의 세로 가용 영역이 커지며, 본문 내부 스크롤과 고정 footer가 중복 스크롤을 만들지 않는다.
  - 기본 정보의 저장 footer, 재고·BOM 탭의 footer 없음, 삭제 완료 후 상태 갱신, 삭제된 품목 복구가 기존처럼 동작한다.
  - `새 품목 추가` 상태의 제목·설명 헤더와 추가 폼은 제거되지 않는다.
- 브라우저 확인 시나리오: 활성 품목을 선택한다 → 탭과 삭제가 한 행인지 확인한다 → 세 탭을 마우스와 방향키로 전환한다 → 삭제를 눌러 취소와 삭제 확인 상태의 배치를 확인한다 → 기본 정보에서 저장한다 → 삭제된 품목과 새 품목 추가 상태를 각각 열어 복구 footer와 실제 제목 헤더가 유지되는지 확인한다 → 동일 뷰포트에서 변경 전보다 보이는 입력·정보 행이 늘었는지 비교한다.
- 우선순위: 중간.

## 관리자 부서 관리

### 4. 부서 목록 폭과 상태 열을 조정해 상태명 전체 표시

- 원본 코멘트: 5~6번.
- 화면/영역: 데스크톱 관리자 > 부서 관리 > 좌측 `부서 목록`.
- 증상: 좌측 패널은 300px 폭에서 `부서명 / 코드·소속 직원 / 상태`를 나누고, 상태 열은 76px이며 `StatusPill`의 최대 폭은 70px이다. 알약의 점·간격·좌우 패딩까지 같은 폭에 포함되어 `사용 중`이 `사용...`처럼 잘린다.
- 사용자 불편: 활성 여부라는 핵심 상태를 목록에서 바로 읽을 수 없고, 상태를 확인하려면 행을 선택해 오른쪽 상세를 봐야 한다.
- 확정 정책: 좌측 부서 목록의 전체 폭과 내부 열 배분을 함께 조정해 `사용 중`과 `비활성`을 항상 전체 표시한다. 부서명, 코드·소속 직원 수, 상태의 3열 구조와 목록 스크롤은 유지하며 오른쪽 상세 카드가 작업하기 어려울 정도로 좁아지지 않게 한다.
- 구현 방향: 부서 목록에만 적용되는 패널 폭, 상태 열 너비, 상태 알약 최대 폭 또는 패딩을 함께 조정한다. 공용 `StatusPill` 전체를 무조건 작게 만들거나 다른 화면의 알약 크기를 바꾸지 않는다.
- 수용 기준:
  - 모든 부서 행에서 `사용 중`과 `비활성`이 말줄임표 없이 보인다.
  - 부서명과 `DPT-xx · N명` 정보가 서로 겹치지 않고 상태 열과 분리된다.
  - 표준 데스크톱과 지원하는 최소 데스크톱 폭에서 좌측 목록에 불필요한 가로 스크롤이 생기지 않는다.
  - 오른쪽 부서 상세의 입력·색상·직원 목록·비활성화 버튼을 기존처럼 사용할 수 있다.
- 브라우저 확인 시나리오: 부서 관리에서 전체·사용 중·비활성 필터를 각각 선택한다 → 짧고 긴 부서명의 행에서 상태명과 코드·직원 수를 확인한다 → 브라우저 폭을 표준·최소 데스크톱 구간으로 바꿔 좌우 패널의 가독성과 세로 스크롤을 확인한다.
- 우선순위: 중간.

### 7. BOM 헤더 작업 버튼 높이를 KPI 카드에 맞춤

- 원본 코멘트: 추가 코멘트 1~3번.

- 수용 기준:

  - `편집`과 `사용처` 버튼은 전환 캡슐 안에서 같은 높이로 중앙 정렬되고 클릭 영역도 높이에 맞게 유지된다.

- 증상: 현재 소스는 상위 패널도 제목+검색 첫 행과 필터 둘째 행으로 이미 분리했지만, 사용자가 실행 화면에서 가운데 `하위 품목 추가` 패널을 기준으로 좌측 제어부의 전체 디자인을 다시 같게 맞춰 달라고 지정했다. 구조만 같고 행 경계·표면·높이·패딩·검색창 비율 중 일부가 다르면 두 패널이 여전히 별도 문법처럼 보일 수 있다.
- 사용자 불편: 같은 작업대의 상위·하위 패널에서 대응하는 제어 행의 시각 문법이 다르면 좌우를 오갈 때 시선 흐름이 끊기고, 세 열의 본문 시작선도 어긋나 보인다.
- 확정 정책: 상위 패널은 `하위 품목 추가` 패널을 기준으로 첫 행의 높이·패딩·제목 위계·검색창 높이와 둘째 행의 높이·패딩·경계·필터 칩 문법을 동일하게 사용한다. 첫 행에는 `상위 품목 선택`과 검색을, 둘째 행에는 상위 품목 단계 필터를 둔다. 각 패널에 필요한 필터 종류와 검색·선택 동작은 유지하고, 없는 건수 표시는 새로 만들지 않는다.
- 구현 방향: `BomParentList`와 `BomChildAddBox`의 대응 행 계산 스타일을 먼저 비교하고, 차이가 있는 행 래퍼·경계·검색 입력 규칙만 맞춘다. 같은 규칙이 반복되면 두 컴포넌트가 공유할 수 있는 기존 primitive 또는 제한적인 공용 클래스 조합을 사용하되, 공정 필터가 추가된 하위 패널의 고유 내용까지 억지로 추상화하지 않는다.
- 수용 기준:
  - `상위 품목 선택`과 검색창이 같은 첫 행에서 수직 중앙 정렬된다.
  - 상위·하위 패널의 첫 행과 둘째 행은 각각 위·아래 경계, 높이, 좌우 패딩, 검색창 높이가 일치한다.
  - 전체·원자재(사용처 모드)·중간공정·공정완료 필터는 별도 둘째 행에 배치되고, 하위 패널의 단계·공정 필터 순서는 유지된다.
  - 첫 행과 필터 행, 필터 행과 표 머리글의 경계가 두 패널에서 같은 방식으로 보인다.
  - 검색어와 단계·상태·공정 조건의 교집합과 선택 행은 기존과 같다.
  - 표준·좁은 데스크톱 폭에서 검색창이 제목을 밀어내거나 필터가 잘리지 않는다.
- 브라우저 확인 시나리오: BOM 편집 모드에서 상위·하위 패널의 첫 두 행 경계·높이·패딩·검색 입력 높이를 나란히 비교한다 → 상위 검색어와 단계 필터를 함께 적용해 결과를 확인한다 → 하위 단계·공정 필터의 교집합을 확인한다 → 사용처 모드로 전환해 원자재를 포함한 필터가 한 행에 유지되는지 확인한다 → 표준·좁은 데스크톱 폭을 확인한다.
- 우선순위: 중간.

  - 상위 품목·하위 후보의 표 머리글 높이에는 의도하지 않은 변화가 없다.
- 브라우저 확인 시나리오: BOM 편집에서 구성품이 있는 상위 품목을 선택한다 → 가운데와 우측 패널의 첫째·둘째 행 경계를 각각 비교한다 → 수량을 수정해 Enter 저장·Escape 취소를 확인한다 → 삭제 요청과 빈 구성 상태도 확인한다.

### 10. BOM 세 목록의 데이터 행 높이를 하나로 통일

- 원본 코멘트: 2026-08-03 추가 코멘트 7~9번.
- 화면/영역: 데스크톱 관리자 > BOM 관리 편집 모드 > 좌측 `상위 품목 선택`, 가운데 `하위 품목 추가`, 우측 `현재 구성`의 반복 데이터 행. 직접 비교 대상은 가운데의 `AR D-910 크래들 BOTTOM 사출` 후보 행과 우측의 `AR ADX4000W 히팅 싱크 신형` 구성 행이다.

- 수용 기준:
  - 좌·가운데·우측 반복 데이터 행의 위·아래 경계와 텍스트 기준선이 같은 리듬으로 맞는다.
  - 우측 수량 표시를 클릭해 input으로 바꾸거나 취소·저장해도 해당 행과 아래 행의 위치가 뛰지 않는다.

  - 수량 Enter 저장·Escape 취소·blur 저장, 삭제 확인, 후보 추가와 각 목록의 세로 스크롤은 기존처럼 동작한다.

- 브라우저 확인 시나리오: 같은 부서에서 세 패널에 여러 행이 보이는 상위 품목을 선택한다 → 첫 행부터 아래로 세 열의 행 경계를 비교한다 → 현재 구성 수량을 편집·취소·저장한다 → 후보 행을 펼쳐 수량 입력을 연다 → 이미 등록됨·삭제된 품목·긴 이름 상태를 확인한다 → 각 패널을 끝까지 스크롤하고 표준·좁은 데스크톱 폭에서 겹침과 표시 행 수를 확인한다.

### 11. 품목·입출고 Excel 카드를 내보내기 화면 최하단으로 이동

- 원본 코멘트: 내보내기 추가 코멘트 1~5번.
- 화면/영역: 데스크톱 관리자 > 내보내기 전체 스크롤 화면. 이동 대상은 `품목·입출고 Excel`, 선행 기준은 `선택 데이터 내보내기 (CSV)`·`최근 내보내기`·`시스템 원본 로그 관리`·`시스템 원본 로그 (월별)`이다.
- 증상: 현재 `품목·입출고 Excel`은 `주요 내보내기`의 왼쪽 열에서 F705-02 바로 아래에 있어, 사용자가 지정한 CSV·최근 기록·시스템 원본 로그 영역보다 먼저 보인다.
- 사용자 불편: 화면을 위에서 아래로 훑을 때 우선 확인하려는 선택형 내보내기와 최근 결과·원본 로그보다 일괄 Excel 다운로드가 앞서 업무 순서와 맞지 않는다.
- 확정 정책: `품목·입출고 Excel` 카드 전체를 내보내기 스크롤 영역의 가장 마지막으로 이동한다. 최종 문서 순서는 최소한 `선택 데이터 내보내기 (CSV)` → `최근 내보내기` → `시스템 원본 로그 관리` → `시스템 원본 로그 (월별)` → `품목·입출고 Excel`을 만족해야 한다. F705-02는 기존 상단 위치를 유지한다.
- 구현 방향: `AdminExportSection`에서 Excel `ExportSurface`를 현재 주요 내보내기 좌측 열에서 분리해 `외부 제출·원본 로그` 섹션이 끝난 뒤에 렌더링한다. 외부 로그 섹션 안에 잘못 중첩하지 말고 독립 카드로 유지한다. 카드 내용·너비 감각·버튼 배치 외에는 순서만 최소 변경한다.
- 수용 기준:
  - `품목·입출고 Excel`이 내보내기 페이지에서 마지막 콘텐츠 카드로 보인다.
  - CSV, 최근 내보내기, 시스템 원본 로그 관리, 월별 파일 목록은 모두 Excel 카드보다 먼저 보인다.
  - F705-02 카드와 선택 CSV 카드의 기능·내용·상단 배치는 유지된다.
  - `Excel 2개 다운로드`는 기존처럼 품목 전체와 최근 30일 입출고 파일을 내려받고 최근 내보내기 기록에도 반영된다.
  - 표준·좁은 데스크톱 폭에서 이동한 카드가 잘리거나 다른 섹션 안에 중첩되어 보이지 않는다.
- 브라우저 확인 시나리오: 관리자 > 내보내기를 맨 위에서 연다 → F705-02와 선택 CSV를 확인한다 → 최근 내보내기와 외부 제출·원본 로그를 차례로 지난다 → 월별 원본 로그 아래의 마지막 카드가 `품목·입출고 Excel`인지 확인한다 → Excel 다운로드 후 최근 내보내기 기록이 갱신되는지 확인한다.
- 우선순위: 중간.

### 12. 시스템 원본 컬럼 구성 안내 제거

- 원본 코멘트: 내보내기 추가 코멘트 6번.

- 사용자 불편: 파일 목록과 다운로드가 핵심인 영역에서 정적인 컬럼 안내가 하단 공간을 차지하고, 화면을 불필요하게 길게 만든다.
- 확정 정책: `시스템 원본 컬럼 구성 (11)` 접이식 안내 박스와 내부 컬럼명 문구를 화면에서 완전히 제거한다. CSV/XLSX 원본 로그의 실제 11개 컬럼, 생성·백필·다운로드 동작은 그대로 유지한다.
- 구현 방향: `AdminAuditCsvSection` 하단의 `<details>`를 감싼 안내 블록만 제거한다. 내보내기 스키마, 백엔드 데이터, 월별 파일 목록과 행 다운로드 버튼은 변경하지 않는다.
- 수용 기준:
  - 월별 시스템 원본 로그 목록 아래에 `시스템 원본 컬럼 구성 (11)` 행과 컬럼명 문구가 보이지 않는다.
  - 월별 파일 건수·행 수·용량, 새로고침, Excel·CSV 다운로드는 기존대로 표시되고 동작한다.
  - 백필 재실행과 F704-02 대장 다운로드는 영향을 받지 않는다.
  - 내려받은 원본 로그 파일의 컬럼 구성과 데이터는 변경 전과 같다.
- 브라우저 확인 시나리오: 관리자 > 내보내기 > 외부 제출·원본 로그로 이동한다 → 월별 파일 목록 아래에 컬럼 구성 안내가 없는지 확인한다 → 새로고침과 월별 Excel·CSV 다운로드를 실행한다 → 시스템 원본 로그 백필과 F704-02 다운로드가 기존처럼 동작하는지 확인한다.
- 우선순위: 낮음.

### 13. 내보내기 헤더에 섹션 스크롤 바로가기 추가

- 원본 코멘트: 이번 추가 코멘트 1~2번.
- 화면/영역: 데스크톱 관리자 > 내보내기 상단 `내보내기` 제목과 설명이 있는 헤더, 그 아래 내부 스크롤 콘텐츠.
- 증상: 내보내기 헤더의 요약 영역에는 설명 문구만 있고, 화면은 주요 내보내기·최근 기록·외부 제출·원본 로그·최하단 Excel까지 길게 이어진다.
- 사용자 불편: 원하는 구역으로 가려면 긴 화면을 직접 스크롤해야 하며, 다른 관리자 화면의 KPI가 차지하는 헤더 영역에 탐색 기능이 없어 시각적으로도 밋밋하다.
- 확정 정책: KPI 수치 대신 헤더 요약 영역에 `주요 내보내기`, `최근 내보내기`, `원본 로그`, `품목·입출고 Excel` 바로가기 버튼을 둔다. 버튼을 누르면 페이지 전체가 아니라 내보내기 내부 스크롤 영역에서 해당 섹션 시작점으로 부드럽게 이동한다. 기존 설명 문구는 유지한다.
- 구현 방향: 내보내기 스크롤 컨테이너와 네 대상 섹션에 안정적인 ref 또는 ID를 두고, 헤더 버튼이 대상의 내부 스크롤 위치로 이동하게 한다. URL·데이터·필터 상태는 변경하지 않으며 현재 섹션 추적 같은 추가 기능은 만들지 않는다.
- 수용 기준:
  - 헤더에 네 개의 구분 가능한 바로가기 버튼이 보이고 마우스·키보드로 실행할 수 있다.
  - 각 버튼은 주요 내보내기, 최근 내보내기, 외부 제출·원본 로그, 최하단 품목·입출고 Excel의 제목 시작점으로 이동한다.
  - 내부 스크롤만 이동하며 관리자 상단 탭, 내보내기 상태, 최근 기록과 입력값은 유지된다.
  - 표준 데스크톱에서는 헤더 한 줄의 균형을 유지하고 좁은 폭에서는 버튼이 잘리지 않도록 안전하게 줄바꿈하거나 가로 스크롤한다.
  - 브라우저의 `prefers-reduced-motion` 설정에서는 과도한 스크롤 애니메이션을 강제하지 않는다.
- 브라우저 확인 시나리오: 내보내기 상단에서 네 바로가기를 차례로 클릭한다 → 각 대상 제목이 내부 스크롤 영역의 시작점에 오는지 확인한다 → CSV 옵션을 바꾼 뒤 다른 섹션으로 이동하고 돌아와 값이 유지되는지 확인한다 → Tab/Enter와 좁은 데스크톱 폭을 확인한다.
- 우선순위: 중간.

  - 낮은 높이와 좁은 데스크톱에서는 카드 상단·하단이나 오류 문구가 잘리지 않고 스크롤로 접근 가능하다.

- 브라우저 확인 시나리오: 보안 화면을 표준 데스크톱에서 열어 카드 중심 위치를 확인한다 → 잘못된 PIN과 불일치 PIN으로 오류 문구를 표시한다 → 브라우저 높이를 줄여 모든 입력·오류·버튼에 스크롤 접근 가능한지 확인한다 → 유효한 PIN에서 버튼 활성화를 확인한다.
- 우선순위: 낮음.

## 이력

### 15. 격리 재고 폐기 경로를 `격리 → 폐기`로 표시

- 원본 코멘트: 이력 추가 코멘트 1번.
- 화면/영역: 데스크톱 이력 > 격리 재고 폐기 거래의 오른쪽 상세 > `위치 / 이동 경로`.
- 증상: 배치 정보가 없는 `DEFECT_SCRAP` 거래는 실제로 불량 격리 재고를 차감하지만, 현재 표시 로직이 거래의 `department`를 출발지로 사용해 `조립 → 폐기`처럼 보여 준다.
- 사용자 불편: 폐기 직전 재고가 격리 상태였다는 핵심 흐름이 가려지고, 정상 조립 재고를 곧바로 폐기한 것으로 오해할 수 있다.
- 확정 정책: `DEFECT_SCRAP`으로 격리 재고를 폐기한 거래는 `격리 → 폐기`로 표시한다. 작업명 `폐기`, 요청 부서, 재고 변화의 `불량 재고` 표시는 유지한다. 다른 거래의 실제 창고·부서 이동 경로에는 이 문구를 일괄 적용하지 않는다.
- 구현 방향: `getFlowPresentation`의 배치 없는 `DEFECT_SCRAP` 예외가 부서명을 출발점으로 만들지 않도록 격리 출발 의미를 반환한다. 배치가 있는 거래는 기존 배치 끝점 해석을 유지하고, 공통 표시 모델을 사용하는 데스크톱 상세·요약에서 같은 경로가 나오도록 테스트한다.
- 수용 기준:
  - 배치 없는 격리 폐기 거래의 상세 경로가 `격리 → 폐기`로 보인다.
  - 같은 거래의 작업명은 `폐기`, 요청 부서는 실제 부서명, 재고 변화는 `불량 재고 -N`으로 유지된다.
  - 일반 출고·입고·부서 이동·격리·격리 해제와 배치 기반 재작업의 경로 표기는 바뀌지 않는다.
  - 선택한 거래를 닫았다 다시 열거나 다른 폐기 거래로 이동해도 부서명 경로로 되돌아가지 않는다.
- 브라우저 확인 시나리오: 이력에서 격리 후 폐기한 `DEFECT_SCRAP` 거래를 선택한다 → 오른쪽 상세의 경로가 `격리 → 폐기`인지 확인한다 → 작업명·요청자·요청 부서·불량 재고 차감은 기존 값인지 확인한다 → 일반 이동과 배치 기반 재작업 거래를 차례로 열어 기존 경로가 유지되는지 확인한다.
- 우선순위: 중간.

### 16. 재고 변화 묶음 제목에서 단위 제거

- 원본 코멘트: 이력 추가 코멘트 2번.
- 화면/영역: 데스크톱 이력 > 오른쪽 상세 > `재고 변화`의 위치별 접이식 묶음 제목. 예: `출하 재고 · 12품목 · -18 EA`.
- 증상: 여러 위치나 많은 상세 행을 접었을 때 묶음 제목이 `위치 · N품목 · 부호 있는 합계 단위` 형식으로 표시되어, 이미 품목 수가 있는 짧은 요약 끝에 `EA` 같은 단위까지 반복된다.
- 사용자 불편: 좁은 상세 패널에서 요약이 길어지고, 여러 재고 묶음의 품목 수와 합계를 빠르게 비교하기 어렵다.
- 확정 정책: 출하 재고뿐 아니라 같은 공통 묶음 제목을 사용하는 창고·박스·불량·부서·기타 위치 재고에서 합계 뒤 단위(`EA` 등)를 제거한다. `위치명 · N품목 · 부호 있는 합계`는 유지하며, 개별 품목 상세 행의 단위는 유지한다.
- 구현 방향: `getImpactGroupAmount`가 단일 단위 묶음에 대해 기존과 같은 합계를 계산하되 반환 문자열에는 단위를 붙이지 않게 한다. 여러 단위가 섞였거나 합계가 0일 때 합계를 생략하는 기존 규칙은 유지한다.
- 수용 기준:
  - 예시 묶음 제목이 `출하 재고 · 12품목 · -18`로 보이고 뒤에 `EA`가 없다.
  - 양수 합계는 `+N`, 음수 합계는 `-N`으로 부호가 유지된다.
  - 창고·박스·불량·부서·기타 위치 재고의 모든 같은 형식 제목에 단위가 붙지 않는다.
  - 펼친 개별 품목 행에는 기존 단위가 남고, 품목 수·합계 계산과 접기·펼치기 동작은 바뀌지 않는다.
  - 여러 단위가 섞인 묶음과 합계가 0인 묶음은 기존처럼 합계 부분을 표시하지 않는다.
- 브라우저 확인 시나리오: 여러 위치에 영향을 준 이력 거래를 선택한다 → 접힌 각 재고 변화 제목에서 위치명·품목 수·합계는 보이고 단위는 없는지 확인한다 → 양수·음수 묶음을 각각 확인한다 → 묶음을 펼쳐 개별 품목 단위가 남아 있는지 확인한다 → 혼합 단위와 합계 0 사례의 기존 생략 규칙을 확인한다.
- 우선순위: 낮음.

### 17. 일일 작업 일지를 주간보고 아래의 마지막 업무 메뉴로 이동

- 수용 기준:

  - 일부 탭을 권한 설정으로 숨겨도 보이는 메뉴의 상대 순서와 하단 고정 영역은 유지된다.
  - 모바일 하단 탭·`More` 메뉴와 주간보고 화면 본문에는 변화가 없다.

## 출하 관리

### 18. 요청 목록 헤더의 진행 건수·절차 설명 제거

- 원본 코멘트: 출하 추가 코멘트 1번.
- 화면/영역: 데스크톱 출하 > 출하 관리 > 요청 목록 상단의 뒤로가기 버튼과 `출하 관리` 제목 아래 설명 행.
- 증상: 제목 아래에 `진행 중 출하 N건 · 요청 생성, 준비 체크, 픽업 완료까지 이어서 처리합니다.`가 표시되지만, 바로 아래 세 상태 열이 각각 건수를 이미 보여 주고 출하 첫 선택 화면에도 같은 절차 안내가 있다.
- 사용자 불편: 같은 건수와 절차 설명이 반복되어 목록 진입 후 헤더가 불필요하게 두 줄을 차지하고, 핵심인 상태별 요청 카드보다 먼저 시선을 끈다.
- 확정 정책: 요청 목록 화면의 해당 설명 행 전체를 제거하고 뒤로가기 버튼과 `출하 관리` 제목만 유지한다. 설명을 지운 자리를 그대로 비워 두지 않고 제목을 `text-xl` 주 제목 위계로 유지해 뒤로가기 버튼과 수직 중앙 정렬한다. `출하 요청 / 준비 중 / 준비 완료` 각 열의 건수와 출하 첫 선택 화면 카드의 안내 문구는 유지한다.
- 구현 방향: `RequestListEntry`에서 전체 `total` 계산과 제목 아래 설명 요소를 제거하고, 남은 단일 제목 행의 높이·정렬·여백을 다시 맞춘다. 제목이 작아지거나 기존 두 줄 높이가 남지 않게 하되 상태 열·목록 높이 구조는 바꾸지 않는다.
- 수용 기준:
  - 요청 목록 상단에 `진행 중 출하 N건`과 뒤따르는 절차 설명이 보이지 않는다.
  - 뒤로가기 버튼과 `출하 관리` 제목은 기존 위치와 기능을 유지한다.
  - 단일 제목은 뒤로가기 버튼과 세로 중앙에 놓이고 주 제목 크기로 보여 삭제된 설명 자리의 빈 비율이 남지 않는다.
  - 세 상태 열의 개별 `N건`, 새 요청 만들기, 빈 상태와 스크롤 목록은 기존처럼 표시된다.
  - 출하 첫 선택 화면의 `요청 생성부터 준비 체크, 픽업 완료까지 이어서 처리합니다.` 안내는 유지된다.
- 브라우저 확인 시나리오: 출하 첫 선택 화면에서 `출하 관리`를 연다 → 목록 헤더에 제목만 있고 진행 건수·절차 설명이 없는지 확인한다 → 제목의 크기와 뒤로가기 버튼의 수직 중심, 아래 상태 열과의 간격을 확인한다 → 세 상태 열의 건수 합계로 진행 요청 수를 확인할 수 있는지 본다 → 뒤로가기로 첫 선택 화면에 돌아가 안내 문구가 유지되는지 확인한다.
- 우선순위: 낮음.

### 19. 요청 카드의 일시·요청자 메타정보를 명시적으로 표시

- 원본 코멘트: 출하 추가 코멘트 2~3번.
- 화면/영역: 데스크톱 출하 > 출하 관리 > `출하 요청 / 준비 중 / 준비 완료` 열의 개별 요청 카드.
- 증상: 진행 중 요청의 생성 시각은 `생성 07. 24. 오전 11:33`처럼 시스템 생성 행위로 표시되고, 요청자는 품목 코드 바로 뒤에 `· 김건호`처럼 필드명 없이 붙어 있다.
- 사용자 불편: 날짜가 실제 요청 시각인지 단순 레코드 생성 시각인지 바로 이해하기 어렵고, 코드 뒤의 이름이 요청자인지 담당자인지 추측해야 한다.
- 확정 정책: 진행 중 요청의 `created_at` 표시는 사용자 용어로 `요청 일시: 날짜·시각`이라 명명한다. 요청자는 `요청자: 이름`으로 명시하며 요청 일시와 같은 메타정보 행에 둔다. 표준 카드 폭에서는 두 정보를 한 줄에 보여 주고, 폭이 부족하면 요청자 묶음 전체가 다음 줄로 내려가게 한다. 품목 코드는 별도 코드 행에 유지한다.
- 구현 방향: `RequestRow`의 코드 행에서 점 구분 요청자 이름을 분리하고, 진행 상태의 날짜 라벨을 `요청 일시`로 변경해 요청자와 함께 `flex-wrap` 가능한 메타정보 묶음으로 렌더링한다. 요청자 값이 없으면 `요청자: 요청자 없음`으로 명시한다. 실제 필드와 API는 바꾸지 않으며 완료·취소 카드의 `출하 완료`·`요청 취소` 시각 의미는 유지한다.
- 수용 기준:
  - 출하 요청·준비 중·준비 완료 카드에 `생성` 대신 `요청 일시:`가 표시된다.
  - 모든 진행 중 요청 카드에 `요청자: 김건호`처럼 역할과 이름이 함께 보이고, 코드 뒤의 장식용 `· 이름` 표기는 없다.
  - 품목 코드, 기준 PF 정보, 인보이스 번호와 상태 알약은 기존 내용을 유지하며 서로 겹치지 않는다.
  - 표준 카드 폭에서는 요청 일시와 요청자가 한 줄에 정렬되고, 좁은 폭에서는 글자 중간이 잘리는 대신 요청자 묶음이 다음 줄로 이동한다.
  - 요청자 값이 없을 때도 역할 없는 `없음`이 아니라 `요청자: 요청자 없음`으로 보인다.
  - 완료·취소 상태를 같은 카드가 표시하는 경우 `출하 완료`·`요청 취소` 라벨과 해당 시각은 기존 의미를 유지한다.
- 브라우저 확인 시나리오: 출하 관리에서 세 진행 상태 열의 요청 카드를 확인한다 → 각 카드의 코드 행과 `요청 일시: … · 요청자: …` 메타정보를 구분해 읽는다 → 요청자 있음·없음과 기준 PF 있음·없음 카드를 비교한다 → 창 폭을 줄여 요청자 묶음이 온전히 다음 줄로 이동하는지 확인한다 → 요청을 열어 상세 데이터와 카드 정보가 일치하는지 확인한다.
- 우선순위: 낮음.

### 20. 출하 이력 선택 색상과 그림자를 의미에 맞게 조정

- 원본 코멘트: 출하 이력 추가 코멘트 1번·3번.
- 화면/영역: 데스크톱 출하 > 출하 이력 > `출하 완료 / 요청 취소` 상태 전환 버튼과 연·월 폴더의 선택·열림 상태.
- 증상: `출하 완료` 활성 버튼과 선택된 월 폴더, 검색 결과의 월 제목이 모두 보라색 계열을 사용하고, 상태 버튼은 전역 `aria-pressed` 규칙의 강한 inset 그림자까지 받아 과하게 눌린 것처럼 보인다.
- 사용자 불편: 완료 상태와 단순 탐색 선택이 같은 보라색으로 보여 의미 구분이 약하고, 강한 그림자가 작은 상태 전환 버튼보다 시선을 더 끈다.
- 확정 정책: `출하 완료` 활성 버튼은 성공 의미의 초록, `요청 취소` 활성 버튼은 위험 의미의 빨강을 사용한다. 선택·열린 월 폴더와 검색 결과 월 제목은 상태색이 아닌 중립 탐색색인 파랑을 사용한다. 상태 버튼의 선택 그림자는 관리자 상단 탭과 같은 약한 inset 수준으로 낮춘다. 비선택 배경·텍스트와 포커스 표시는 유지한다.
- 구현 방향: 출하 이력 내부에서 완료 필터에 직접 지정된 `purple`을 `green`으로, 선택·검색 월 폴더의 `purple`을 `blue`로 교체하고 기존 tint 강도 범위 안에서 배경·테두리·글자색을 함께 맞춘다. `aria-pressed`의 전역 강한 그림자는 이 상태 전환 영역에서 관리자 탭의 `inset 0 1px 4px` 수준으로 재정의하되, TODO 2의 약한 선택 규칙과 중복 구현하지 않도록 같은 공통 규칙을 재사용한다.
- 수용 기준:
  - `출하 완료` 선택은 초록, `요청 취소` 선택은 빨강으로 보이며 보라색 활성 버튼이 없다.
  - 선택·열린 월과 검색 결과의 월 제목·테두리·배경은 파랑 계열이고 보라색이 남지 않는다.
  - 상태 전환 버튼의 선택 그림자는 관리자 상단 탭과 같은 강도로 보이고 전역 강한 inset 효과가 남지 않는다.
  - 비선택 상태, 키보드 포커스, 호버·클릭 피드백과 라이트·다크 테마 대비는 유지된다.
  - 출하 이력 밖의 픽업 완료 상태 알약·출하 허브 카드 등 보라색을 사용하는 비대상 요소는 바뀌지 않는다.
- 브라우저 확인 시나리오: 출하 이력에서 출하 완료와 요청 취소를 번갈아 선택한다 → 각각 초록·빨강 활성색과 약한 그림자를 관리자 탭과 비교한다 → 기본 월 폴더와 검색 결과 월 폴더가 파랑 계열인지 확인한다 → 키보드 포커스와 라이트·다크 테마를 확인한다 → 출하 허브와 상세 상태 알약의 비대상 색이 유지되는지 확인한다.
- 우선순위: 낮음.

### 21. 월 폴더 첫 클릭에서 선택과 열림을 동시에 처리

- 원본 코멘트: 출하 이력 추가 코멘트 2번.
- 화면/영역: 데스크톱 출하 > 출하 이력 > 연도 폴더 안의 `N월 · N건` 월별 `<details>` 목록.
- 증상: 월 제목 클릭 시 React의 선택 상태 갱신과 브라우저 기본 `<details>` 토글이 서로 다른 시점에 작동해, 첫 클릭에는 선택색만 바뀌고 내용은 닫힌 채 남으며 두 번째 클릭에서야 열릴 수 있다.
- 사용자 불편: 월을 선택했는데 결과가 보이지 않아 첫 클릭이 실패한 것으로 느끼고 같은 항목을 다시 눌러야 한다.
- 확정 정책: 닫힌 월을 한 번 클릭하거나 Enter·Space로 실행하면 그 월이 선택되는 동시에 폴더가 열리고 해당 이력 로딩 결과가 표시된다. 다른 월을 선택하면 이전 월은 닫히며 선택된 한 달만 열린 상태를 유지한다. 선택된 월을 다시 눌러도 색만 남은 닫힘 상태가 되지 않는다.
- 구현 방향: 월 `<summary>`의 브라우저 기본 토글과 React 제어 상태가 경쟁하지 않도록 기본 동작을 막고 `selectedYear / selectedMonth`를 단일 열림 근거로 사용하거나, 동등한 완전 제어 방식으로 통일한다. 마우스와 키보드 접근성, `details/summary` 의미와 월 API 호출은 유지한다.
- 수용 기준:
  - 닫힌 월을 처음 클릭하면 즉시 선택색과 펼쳐진 요청 목록이 함께 보인다.
  - 다른 월을 한 번 클릭하면 이전 월은 닫히고 새 월만 열리며 해당 연·월 API가 한 번 요청된다.
  - 선택된 월을 다시 실행해도 선택색만 있고 내용이 닫힌 불일치 상태가 생기지 않는다.
  - Enter와 Space에서도 마우스와 같은 동작을 하고 포커스가 사라지지 않는다.
  - 연도 폴더 열기·닫기, 검색 결과 폴더와 더 보기 동작은 기존처럼 작동한다.
- 브라우저 확인 시나리오: 출하 완료 이력에서 기본 선택 월이 열린 것을 확인한다 → 닫힌 다른 월을 한 번 클릭해 선택·열림·데이터 교체가 동시에 되는지 확인한다 → 원래 월을 한 번 클릭해 다시 전환한다 → 선택 월을 재클릭한다 → 키보드 Enter·Space와 요청 취소 상태에서도 같은 동작을 확인한다.
- 우선순위: 중간.

### 22. 출하 이력 설명 제거 후 헤더 비율 재정렬

- 원본 코멘트: 출하 이력 추가 코멘트 4~5번.
- 화면/영역: 데스크톱 출하 > 출하 이력 상단의 뒤로가기·이력 아이콘·`출하 이력` 제목·설명과 오른쪽 상태 전환 영역.
- 증상: 제목 아래 `상태와 연월 폴더로 찾거나 전체 기간을 검색합니다.` 설명이 헤더를 두 줄로 만들고 있으며, 설명만 제거하면 현재 `text-lg` 제목과 `items-start` 정렬이 44px 아이콘·상태 버튼 사이에서 작고 위로 치우친 채 남는다.
- 사용자 불편: 불필요한 설명 때문에 헤더가 복잡하고, 문구를 단순 삭제하기만 하면 빈 높이와 작은 제목 때문에 오히려 비율이 어색해진다.
- 확정 정책: 설명 문구를 제거하고 `출하 이력` 제목을 주 제목 크기인 `text-xl`로 키운다. 뒤로가기 버튼·이력 아이콘·제목과 오른쪽 상태 전환 영역은 단일 행의 수직 중앙에 맞춘다. 좁은 폭에서 상태 전환이 다음 줄로 내려가면 각 행 내부는 중앙 정렬을 유지한다.
- 구현 방향: `HistoryListEntry`에서 `PanelTitle`의 subtitle을 제거하고, 이 헤더에만 제목 크기와 `items-center` 정렬을 적용한다. 공용 `PanelTitle`을 무조건 키워 다른 출하 패널을 바꾸지 말고 단일 행 변형이나 전용 제목 구조를 사용한다. 검색창과 아래 폴더 영역의 간격도 새 단일 행 기준으로 확인한다.
- 수용 기준:
  - 출하 이력 헤더에 설명 문구가 보이지 않고 `출하 이력` 제목만 남는다.
  - 제목은 기존보다 큰 주 제목 위계이며 44px 버튼·아이콘, 상태 전환 제어와 세로 중심이 맞는다.
  - 설명이 있던 빈 줄이나 과한 아래 여백이 남지 않고 검색 행과의 간격이 균형을 이룬다.
  - 표준 데스크톱에서는 제목 그룹과 상태 전환이 한 줄이며, 좁은 폭에서 줄바꿈돼도 겹치거나 잘리지 않는다.
  - 공용 `PanelTitle`을 쓰는 다른 출하 상세·준비 화면의 제목 크기와 정렬은 바뀌지 않는다.
- 브라우저 확인 시나리오: 출하 완료·요청 취소 이력 화면을 각각 연다 → 설명이 사라지고 제목·버튼·아이콘·상태 전환의 중심선이 맞는지 확인한다 → 검색 행과 헤더 사이 비율을 본다 → 창 폭을 줄여 상태 전환 줄바꿈을 확인한다 → 다른 출하 상세 화면의 헤더가 변하지 않았는지 비교한다.
- 우선순위: 낮음.

## 관리자 인증

### 23. PIN 인증 배경을 데스크톱 셸과 자연스럽게 연결

- 원본 코멘트: 관리자 인증 추가 코멘트 1~2번.
- 화면/영역: 데스크톱 관리자 잠금 상태 > 상단바 아래의 전체 PIN 인증 배경과 왼쪽 사이드바 사이.
- 증상: PIN 인증 컴포넌트가 본문 슬롯 전체를 채운 상태에서 화면 전역 방사형 그라데이션과 좌우의 큰 blur 도형을 별도로 올린다. 셸과 인증 컴포넌트의 기본색은 모두 같은 `--c-bg`이지만, 장식 농도가 본문 경계부터 달라져 사이드바 오른쪽에 별도 직사각형 판이 시작되는 듯한 구분감과 넓은 푸른 빈 배경이 생긴다. 브라우저 코멘트의 파란 외곽선·반투명 파란 덮개는 실제 UI가 아니라 선택 오버레이이며 이 부분은 수정 대상이 아니다.
- 사용자 불편: 인증 카드보다 넓은 배경 장식이 먼저 보여 잠금 화면이 다른 데스크톱 화면과 단절된 별도 레이어처럼 느껴지고, 사이드바 옆 경계가 필요 이상으로 도드라진다.
- 확정 정책: 인증 화면 바깥 캔버스는 데스크톱 셸의 기본 배경을 그대로 이어 받아 사이드바 옆에 색 면의 시작 경계가 생기지 않게 한다. 보안 화면의 은은한 파랑·청록 강조는 없애지 않되 인증 카드 뒤의 제한된 범위에만 낮은 농도로 둔다. 전체 본문을 감싸는 새 테두리·카드·둥근 패널은 추가하지 않으며, 인증 카드의 중앙 배치와 PIN 상호작용은 유지한다.
- 구현 방향: `DesktopPinLock`의 바깥 컨테이너는 셸 배경을 상속하게 하고, `inset-0` 전체 그라데이션과 좌우 화면 밖에서 시작하는 대형 blur 도형을 제거하거나 카드 중심의 단일한 낮은 농도 glow로 축소한다. 기존 카드의 `s1` 표면·테두리·카드 그림자를 중심 분리 수단으로 유지한다. 공용 `DesktopMesShell`, `DesktopSidebar`와 관리자 해제 후 본문 레이아웃은 변경하지 않는다.
- 수용 기준:
  - 코멘트 표시가 없는 실제 화면에서 사이드바 오른쪽부터 인증 본문까지 동일한 기본 배경이 끊김 없이 이어지고, 직선 색 경계처럼 보이는 영역이 없다.
  - 파랑·청록 장식은 인증 카드 주변에서만 은은하게 보이며 화면 좌우 끝이나 전체 빈 공간을 푸르게 덮지 않는다.
  - 인증 카드는 가용 본문 영역의 가로·세로 중앙을 유지하고, 배경과 구분되는 표면·테두리·약한 카드 그림자를 갖는다.
  - 숫자 키패드, 입력 점, 삭제, 로딩·오류 흔들림, 자동 검증과 잠금 해제·취소 동작은 기존과 같다.
  - 라이트·다크 테마에서 카드와 배경 대비가 유지되고, 관리자 인증을 마친 뒤의 상단 섹션 탭·본문 배경은 바뀌지 않는다.
  - 브라우저 코멘트 도구로 다시 선택했을 때 생기는 파란 외곽선·반투명 덮개는 제품 UI 회귀로 판정하지 않는다.
- 브라우저 확인 시나리오: 코멘트 오버레이를 닫은 1919×910 데스크톱에서 잠긴 관리자 탭을 연다 → 사이드바와 인증 본문 사이의 기본 배경이 이어지는지 확인한다 → 카드 주변 장식의 범위와 빈 공간 비율을 본다 → 라이트·다크 테마를 전환한다 → 숫자 입력·삭제·오류·성공을 확인한다 → 잠금 해제 후 관리자 본문과 다른 메인 탭의 셸 레이아웃이 그대로인지 비교한다.
- 우선순위: 낮음.

## 관리자 공통

### 24. 모델·직원·부서 상세의 저장 버튼을 공통 주 작업 크기로 확대

- 원본 코멘트: 2026-08-03 추가 코멘트 1~3번.
- 화면/영역: 데스크톱 관리자 > 모델 관리·직원 관리·부서 관리 > 선택된 항목의 상세 카드 오른쪽 상단 파란 `저장` 버튼.
- 증상: 세 화면의 저장 버튼이 모두 공용 `Button`의 `size="sm"`을 사용해 12px 글자, 14px 아이콘과 작은 세로 패딩으로 렌더링된다. 제목·상태·코드가 들어가는 넓은 상세 헤더 안에서 핵심 저장 작업이 보조 버튼처럼 작게 보인다.
- 사용자 불편: 편집을 마친 뒤 가장 중요한 완료 동작이 눈에 잘 들어오지 않고, 버튼의 클릭 영역도 상세 헤더의 여유에 비해 작다. 같은 역할의 저장 버튼을 세 화면에서 반복 사용할 때 작은 표적을 정확히 눌러야 한다.
- 확정 정책: 모델·직원·부서 상세의 저장 버튼 세 개만 같은 관리자 주 작업 규격으로 키운다. 기준은 44px 높이, 최소 88px 너비, 16px 저장 아이콘, 13px 이상 굵은 글자와 `md` 수준의 좌우 패딩·둥근 모서리다. 파란 primary 색상과 헤더 오른쪽 정렬은 유지한다. 전역 `sm` 규격, 목록의 추가 버튼, 추가 모드의 취소 버튼, 삭제·비활성화 버튼과 품목 관리 하단 저장 버튼은 변경하지 않는다.
- 구현 방향: `AdminModelsSection`, `AdminEmployeesSection`, `AdminDepartmentsSection`의 선택 상세용 저장 버튼에만 공통된 `md` 크기와 `h-11 min-w-[88px]` 수준의 헤더 액션 규격을 적용하고 아이콘을 16px로 맞춘다. 공용 `Button`의 `sm` 정의 자체를 키워 다른 화면을 연쇄 변경하지 않는다. 세 파일에 동일한 규격을 적용하되 한 번만 쓰이는 새 컴포넌트는 만들지 않는다.
- 수용 기준:
  - 모델·직원·부서 상세의 저장 버튼은 세 화면에서 같은 높이·최소 너비·글자·아이콘 크기로 보인다.
  - 버튼 높이는 최소 44px이고 제목·상태·코드 묶음과 상세 헤더 안에서 세로 중앙이 맞는다.
  - 버튼은 내용 길이에 끌려 과도하게 넓어지지 않고 표준·좁은 데스크톱에서 제목이나 상태 알약과 겹치지 않는다.
  - 모델 저장 버튼의 변경 없음 비활성 상태, 저장 중 spinner와 중복 클릭 방지, 직원·부서 저장 동작과 성공·오류 피드백은 기존처럼 작동한다.
  - 추가·취소·삭제·비활성화와 품목 관리 footer 등 범위 밖 버튼 크기는 바뀌지 않는다.
  - 라이트·다크 테마의 파란 primary 대비, hover·active·focus-visible 상태가 유지된다.
- 브라우저 확인 시나리오: 모델 관리에서 값을 바꾸기 전 비활성 버튼과 변경 후 활성 버튼의 크기를 확인하고 저장한다 → 직원 관리에서 이름·부서·권한 중 하나를 바꿔 저장한다 → 부서 관리에서 이름이나 색상을 바꿔 저장한다 → 세 헤더의 버튼 외곽 크기와 중심선을 나란히 비교한다 → 창 폭을 줄여 제목·상태와 겹치지 않는지 확인한다 → 각 화면의 추가 모드와 위험 작업 버튼 크기가 그대로인지 확인한다.
- 우선순위: 낮음.
