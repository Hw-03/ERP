# 수정 관련 브라우저 시나리오

감사 ID는 기존 기대값 연결 키다. 한 ID의 일부 검증을 전체 PASS로 확대하지 않는다. 모든 이름은 QA 접두어를 쓰고 합성 데이터만 사용한다.

| 연결 ID | 실제 UI 절차 | 기대값 / 보조 검증 |
|---|---|---|
| 8.19-02 | 관리자에서 기호 QF1 모델 생성, 해당 모델 품목과 공용 품목 생성. 모델 목록 및 BOM 연결 표시 확인 | 연결 품목 수가 API 슬롯 기준과 일치. 한 글자 기존 모델 정상. 모호한 기호 추가는 409 안내 |
| 8.19-06 | QF1 품목 편집 열기, 모델 선택 확인, 플래그만 변경 후 저장, 다시 열기 | 모델/품목 코드 유지, 변경 플래그 유지. API model_slots=[]는 빈 선택 유지 |
| 8.19-13 | 합성 직원에게 연결 품목 없는 QA 모델 배정·저장, 모델 삭제, 같은 직원 편집 재열기 | 삭제 모델 배정 제거; 다른 모델 순서 유지. 연결 품목 있는 모델 삭제는 거부 |
| 8.21-11 | 양수 초기 재고 품목 생성(창고만, 부서만, 혼합은 자동 테스트도 확인), 재고·이력·주간보고 확인 | 위치별 RECEIVE 합계=초기수량, 주간 입고에 반영, 생산량 0, 검산 통과. F704 출처 초기 재고. 0은 이력 없음 |
| PC-DELTA-PF-03 부분 | PF BOM과 재고 fixture 준비, 출하 요청→준비→픽업→픽업 취소→준비 취소→요청 취소 | 재고/예약 원복, 정상 CANCELLED 유지, 정합성 이상 없음. 진단 API/DB는 보조 근거. F705 다운로드 전체는 별도 검증 |

준비 취소 후 요청 취소의 증빙 누락·시간 역전·후속 작업, 유일 prefix 분해/모호성, 초기 재고 공통 취소와 위치 조합은 관련 pytest로 검증한다. UI에서 지원하지 않는 손상 상태를 만들기 위해 원본 DB를 수정하지 않는다.

지도 `PC-DELTA-MAP-05`, 전수 감사, 과거 자료 자동 백필은 이 스킬의 기본 실행 범위에 포함하지 않는다.

## 기대값 결정 후 회귀 시나리오

각 행의 검증 조건을 따로 기록한다. 실제 브라우저에서 일부만 확인했다면 그 부분만 PASS로 쓰고, 자동 테스트로 검증한 실패·경합 경로는 별도 결과와 선택자로 연결한다. QA-ADMIN은 합성 계정 이름이며 직원 등급을 뜻하지 않는다.

| 결정 / 연결 ID | 실제 UI 절차 | 기대값과 추가 자동 검증 |
|---|---|---|
| G01 / 8.2-07, 8.19-09 | 관리 → 직원에서 등급 입력이 없는지 확인. 창고·부서 정/부 및 AS·연구 역할을 확인하고 무역할 QA 직원을 선택해 승인함 확인 | PIN으로 여는 관리 기능과 역할은 유지. 무역할 직원은 승인 거부. 회수 후 직접 승인 API도 거부하고 대기·예약 유지, 재부여 후 한 번만 실행하는 조건은 pytest로 별도 확인 |
| G03~G05 / 8.11-01, 8.11-07 | QA 품목의 불량·B급·구형 원건을 준비하고 불량 통계의 최초 분류별 수량·건수와 합계 확인. 분류 변경·부분 및 전량 복귀 후 같은 발생 기간 다시 확인 | 원래 수량·발생 시각·최초 분류 유지. 비교 기간도 동일 세 분류. 손상된 최초 이력 제외 안내, 경계 시각·직접 처리·복원 자료 중복 방지는 pytest 증거로 구분 |
| G06 / 8.17-03 | 원자재 입고 선택에서 R 품목만 노출되는지 확인하고 유효 원자재 입고 완료 | 공정품·조립품·삭제 품목 제외. R이 아닌 코드로 바뀐 오래된 초안, 위조 혼합 요청의 미리보기·저장·제출·최종 실행 전부 거부와 DB 전체 무변경은 pytest로 확인 |
| G07 / PC-DELTA-ITEM-01 | PC와 모바일에서 검색 → 상세 열기 → 새로고침 → 닫기 → 새로고침 → 같은 선택 행 재열기 | 검색·선택·열림 상태 복원. 닫힌 상세는 계속 닫힘. 상세는 서버 재조회. 직원 전환·boot 불일치·이전 품목의 지연 응답 차단은 hook 및 Playwright 조건별 확인 |
| G08 / PC-DELTA-ITEM-02 | 열린 QA 품목을 다른 탭의 관리 화면에서 삭제한 뒤 원래 상세 새로고침 | 상세 유지, 삭제 안내, 입고·출고 실행 차단, 읽기 이력 유지. 목록 누락·404·403·503은 삭제와 구분. 조회 실패/재시도는 격리 Playwright, 삭제 후 기존 작업 취소 보존은 pytest로 각각 기록. 한글 작업명도 별도 assertion |
| G09 / 8.23-13, 8.24-16, 8.25-12 | QA 원자재 입고 또는 수량조정 후 내역 건수 확인 → 원작업 취소 → 같은 내역·필터·달력 확인 | 원작업 1 + 취소 1, 같은 업무 분류, 묶음 거래 행 중복 없음, 재고 순변화 0. KST 월 경계를 넘긴 취소는 각자의 발생 기간에 한 건씩. 주간보고 생산 실적은 변경하지 않음 |
| G10 / PC-DELTA-SETTINGS-03 | 같은 직원으로 두 탭 열기 → 한 탭에서 테마·사이드바 함께 저장 → 다른 탭 자동 반영 확인. 다른 직원 탭 추가 → 저장해도 그 직원 설정 유지 | 새로고침/수동 동기화 없이 반영. 설정 모달에서 미저장 입력·PIN 유지. 저장 실패는 알림 없음. 동시 저장·역순 GET/PUT·직원 전환·로그아웃·후속 조회 실패는 provider/Vitest·Playwright로 별도 검증 |

브라우저 결과에는 후속 원장의 개별 assertion과 실행 범위를 적는다. 기본 CONTRACT와 추가 DELTA의 연결·누락·보류 집계는 원장에서 계산하고, 연결만 된 조건을 현재 실행 PASS로 기록하지 않는다.
